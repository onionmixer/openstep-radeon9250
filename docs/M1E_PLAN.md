# M1e — 구로 음영 삼각형 (계획, 코딩 전)

기준일 2026-09-22.  선행: M1d 완료(`docs/M1D_PLAN.md` 8).
**이 문서는 코드보다 먼저 쓰였다.**

## 1. 이 칸의 한 줄

**정점마다 색이 다른 삼각형 하나가 카드로 가고, 그 그림이 R6e 가 실측한 보간 규칙과
화소 단위로 같다.**

M1d 는 평면 음영 하나만 받았다(`ShadeModel != GL_FLAT` 이면 거절).  이 칸은 그 거절
하나를 푼다.  그 외의 모든 거절(텍스처·깊이·컬링·안티앨리어싱·설정 캡)은 **그대로 둔다.**

## 2. 이미 있는 것 — 그리고 이 칸이 놀랍도록 작은 이유

| | | |
|---|---|---|
| 제출 통로 | R7b `ioctl(SUBMIT)` + 배치 창 | 실기 PASS |
| 삼각형 경로 | M1d: 훅 설치·정점 조립·폴백·씨앗·색 바이트 순서 | 실기 PASS |
| 정점 형식 | `SE_VTX_FMT_0 = 0x803`, 정점당 `x y z w 색` **다섯 워드** | 이미 정점마다 색을 싣고 있다 |
| 보간 규칙 | R6e-3 가 **규칙 B·가중치 짝수 반올림**으로 확정 | `R6E_PLAN.md:284` |
| 오라클 | `tools/r6/gouraud_oracle.py` 의 `rule_b(pts, vals, 'even')` | `gouraud_oracle.py:324` |

**M1d 는 이미 정점마다 색 워드를 보내고 있었다** — 세 개를 같은 값으로 채웠을 뿐이다.
그러니 이 칸에서 스트림이 바뀌는 곳은 **딱 두 군데**다: `SE_CNTL` 한 워드와, 같은 값을
세 번 쓰던 자리.

## 3. 무엇이 달라지는가 — 직접 읽어 확인

| E2 | 우리 서두의 `SE_CNTL` 은 `0x480055de` = diffuse **FLAT**·알파 **FLAT**·`FLAT_SHADE_VTX_LAST` | python 으로 필드 추출 |
| E3 | 구로 값은 **`0x48005ade`** 이고, R6e 오라클이 그 값을 **같은 방식으로 계산한다** | `gouraud_oracle.py:278` · `:281` |
| E4 | R6e 의 구로 스트림은 평면 스트림과 **그 한 워드만** 다르다 | `gouraud_oracle.py:312` (`state[:15] + [se_cntl_gouraud()] + state[16:]`) |

| E6 | 확정된 규칙: 정점 1/16 절삭·표본 픽셀+½·정확한 무게중심 가중치, **맨 왼쪽 정점 밖 두 가중치를 1/256 짝수 반올림**, 가중합 **내림**, 클램프 | `R6E_PLAN.md:284`, `gouraud_oracle.py:324` |
| E7 | **검증기가 구로 값을 허용한다**: `SE_CNTL` 은 클라이언트 허용 목록에 있고 `value_ok(0x1c4c, 0x48005ade)` 는 `None`(거절 사유 없음)이며, 구로로 바꾼 우리 스트림 전체가 `verify()` 를 `why=0` 으로 통과한다 | python 으로 실행 |
| E8 | `SE_VTX_FMT_0 = 0x803` = `VTX_Z0 | VTX_W0 | (VTX_PK_RGBA << VTX_COLOR_0_SHIFT)` — **정점 색(패킹 RGBA)이 이미 형식에 선언돼 있다.**  그리고 같은 워드가 **스페큘러(COLOR_1, 시프트 13)도 포그(`VTX_DISCRETE_FOG`, 비트 8)도 없음**을 말한다 | `r200_reg.h:376` · `:388` · `:392` · `:384`, python 으로 비트 분해 |
| E9 | 참조 드라이버의 `r200ShadeModel` 은 **`SE_CNTL` 하나만** 바꾸지만 필드는 **다섯**이다: diffuse·alpha·**specular·fog·disc_fog** | `r200_state.c:1447` |
| E10 | 그런데 우리 값 `0x480055de` 는 균일한 FLAT 이 아니다 — specular=FLAT·fog=FLAT 이지만 **disc_fog=0(SOLID)**.  "드라이버처럼 맞춘다" 는 잘 정의된 행동이 아니다(다섯을 다 켜면 `0x4a00aade`, 둘만 켜면 `0x48005ade`, 차이 `0x0200f000`) | python 으로 필드별 계산 |

**결정: 두 필드만 바꾼다(`0x48005ade`).**  세 가지 이유가 서로를 받친다 —
(a) **R6e 의 규칙은 바로 그 값에서 측정됐다**(E4).  다른 값으로 보내면 게이트 C 가 기대는
예측이 그 하드웨어 상태의 것이 아니게 된다.  (b) 우리 정점 형식에는 **스페큘러도 포그도
없다**(E8) — 그 세 칸에는 음영할 입력 자체가 없다.  (c) 재지 않은 것을 참조에서 베껴 오는 것이
이 프로젝트가 피하는 일이다.  다섯 필드 판은 스페큘러나 포그를 켜는 칸에서 **다시 재고**
다룬다.

**E7 이 이 칸의 크기를 정한다: 드라이버를 바꾸지 않는다 → 재부팅이 필요 없다.**
(M1d 때와 같이 CP 는 이미 켜져 있고, 러너가 `cprunning` 을 묻고 건너뛴다.)

## 4. 그런데 정말 두 군데뿐인가 — 스스로 반박해 본다

계획이 작을수록 빠뜨린 것이 있기 쉽다.  의심한 것과 그 답:

| 의심 | 확인 | 결론 |
|---|---|---|
| 정점 형식(`SE_VTX_FMT_0`)이 평면일 때와 달라야 하지 않나 | **E8 이 직접 답한다** — 그 워드가 이미 `PK_RGBA` 색을 정점마다 선언하고 있다.  R6e 도 안 건드렸다(E4) | 안 바꾼다 |
| `FLAT_SHADE_VTX_LAST`(비트 6–7)도 바꿔야 하나 | *하드웨어가 무시한다고는 여전히 말할 수 없다* — 안 재 봤다.  근거는 셋이다: `r200ShadeModel` 이 그 칸을 마스크에 **안 넣는다**(E9), **R6e 가 LAST 인 채로 구로를 측정했다**(E4), 그리고 **Mesa 자신의 초기값이 `FLAT_SHADE_VTX_LAST` 와 `DIFFUSE_SHADE_GOURAUD` 를 함께 쓴다**(E11) | 안 바꾼다 — 근거는 "무시된다" 가 아니라 "그 조합이 정상 상태다" |
| 색 바이트 교환(M1d 4d)이 정점마다 달라지나 | 교환은 **워드 하나의 순열**이라 정점과 무관 | 같은 함수를 세 번 |
| 알파도 보간되나 | E1 에 알파 음영 칸이 따로 있고 우리는 **둘 다** 구로로 둔다; E6 의 규칙은 RGB 와 알파가 같다 | 둘 다 켠다 |
| 씨앗·ZPREP 제약이 달라지나 | 제출 형태는 M1d 와 같다 | 제출 1 회당 ZPREP 1 회 그대로 |
| 분류기의 다른 거절이 풀리나 | `ShadeModel` 조건 **하나만** 없앤다 | 나머지는 그대로 |

스스로 "추론" 이라 표시한 항목이 있었던 것도 이번이 처음이다.

## 5. 설계

1. **서두에 슬롯 하나 추가** — `OSRDN_TRI_SLOT_SE_CNTL`.  생성기가 `SE_CNTL` 의 값 워드를
   슬롯으로 표시하고, 평면 값과 구로 값을 **둘 다** 표에 넣는다(둘 다 오라클에서 나온다).
   C 가 런타임에 고른다.  **표에 손으로 적는 값은 없다.**
2. **`osrdn_tri_send` 에 `smooth` 인자** — 슬롯을 어느 값으로 채울지, 그리고 정점 색을
   세 개 받는다.  현재 서명은 색을 정점 워드 안에 이미 담고 있으므로 **색 인자는 안 바뀐다**;
   훅이 정점마다 다른 색 워드를 넣기만 하면 된다.  바뀌는 것은 `smooth` 하나.
3. **훅** — `ShadeModel == GL_SMOOTH` 면 `VB->ColorPtr->data[v0/v1/v2]` 를 각각 쓰고,
   `GL_FLAT` 이면 지금처럼 `[pv]` 를 세 번.  **둘 다 같은 바이트 교환을 거친다.**
4. **분류기** — `OSRDN_WHY_SHADE_MODEL` 을 없애지 않는다.  `GL_FLAT` 과 `GL_SMOOTH` **둘만**
   받고 그 밖(있을 수 없지만)은 여전히 거절한다.  *거절 사유를 지우면 그 사유가 다시
   필요해졌을 때 이름이 없다.*
5. **판정기** — `predict()` 가 삼각형의 세 색이 모두 같으면 지금처럼 평면으로, 다르면
   `gouraud_oracle.rule_b(pts, vals, 'even')` 로 채널마다 예측한다.

## 5b. 시험 장면의 색은 고른 것이지 아무거나가 아니다 (python 으로 계산)

게이트 C 가 **실패할 수 있어야** 의미가 있다.  오라클로 후보를 재 봤다(276 화소):

| 정점 색 | R | G | B | A |
|---|---|---|---|---|
| `(255,0,0,255) (0,255,0,128) (0,0,255,64)` | 37 값 | 23 | 23 | 100 |
| **`(255,64,32,255) (16,255,128,170) (64,32,255,85)`** | **155** | **164** | **138** | **62** |

두 번째를 쓴다 — 네 채널 전부 넓게 변한다.  그리고 **평면으로 그리면 276 화소 전부가
틀린다**(평면 빨강은 전 화소 255, 구로 빨강은 27–246) — 즉 "구로를 안 켰다" 를 게이트가
놓칠 수 없다.

알파를 일부러 세 정점에서 다르게 준다.  첫 후보처럼 알파가 셋 다 255 면 **알파 평면이
상수 하나**라(위 표 첫 행의 100 은 128·64 를 넣었기 때문이다) `ALPHA_SHADE_GOURAUD` 를
켰는지 아닌지를 그림으로 알 수 없다.

**측정 한계 하나를 미리 적어 둔다**: 이 삼각형에서는 가중치 반올림 half-even 과 half-up 의
예측이 **0 화소 차이**다(python 확인).  그러니 게이트 C 가 증명하는 것은 "카드가 규칙 B 를
따른다" 이지 "반올림이 짝수다" 가 아니다 — 후자는 R6e-3 이 3310 바이트로 이미 확정했고
이 칸이 다시 재는 것이 아니다.

**그리고 이 설계는 Mesa 의 float→byte 변환에 의존하지 않는다**: 판정기는 장면이 의도한
색이 아니라 **라이브러리가 실제로 보낸 정점 색 워드**에서 예측한다(M1d 에서 세운 원칙).
변환이 어떻든 예측과 그림은 같은 색을 말한다.

## 6. 게이트

- **A** 호스트: 규칙·변이.  새 규칙 — 훅은 구로일 때 **세 정점의 색을 각각** 읽어야 하고
  (`data[v0]`·`data[v1]`·`data[v2]` 가 전부 나와야 한다), `SE_CNTL` 슬롯은 **두 값 중 하나**만
  담을 수 있어야 한다.
- **B** 호스트: 구로 스트림을 `tools/r7/verify_oracle.py` 로 판정 — **이미 통과함을 확인했다**(E7).
  생성기 자체검사에 넣어 상시화한다.
- **C** 실기, 한 승인 실행: 평면 삼각형 하나와 **구로 삼각형 하나**가 각각 제출되고,
  구로 쪽 그림이 `rule_b(..., 'even')` 예측과 **화소 단위로 같다**.
- **D** 측정: 소프트웨어 그림과의 차이를 보고한다.  **여기서는 차이가 날 것으로 예상한다** —
  Mesa 의 구로는 고정소수점 span 보간이고 카드는 무게중심 가중치라 규칙이 다르다.
  M1d 처럼 0 이 나오면 그것도 기록하되, **요구하지 않는다.**
- **E** 실기: 세 색이 같은 구로 삼각형은 평면과 **같은 그림**이어야 한다(규칙이 서로를 포함).
- **F** 실기: M1d 의 불변식 전부 유지 — 손실 0, `refused + notBound == delegated`, 매핑 1.

## 7. 구현 순서

1. 생성기에 `SE_CNTL` 슬롯 + 구로 값 + B 게이트 자체검사.
2. 삼각형 단위: `smooth` 인자.
3. 훅: 정점별 색, 분류기 조건 완화(삭제가 아니라 **두 값 허용**).
4. 판정기: 구로 예측.
5. 호스트 검사(변이 포함) → 타깃 빌드 + `nm -u` → 실기.

## 8. 이 칸이 하지 않는 것

- 텍스처·깊이·블렌드·컬링·안티앨리어싱을 켜지 않는다.
- 한 제출에 삼각형 여럿을 넣지 않는다(ZPREP 제약, `docs/M1D_PLAN.md` 4e).
- 드라이버를 바꾸지 않는다 → **재부팅이 필요 없다.**

### 게이트 D 는 계획대로 측정이었고, 그 측정이 규칙이 됐다

계획은 "카드와 소프트웨어가 다를 것으로 예상한다, 요구하지 않는다" 라고 적었는데
**판정기 코드는 M1d 의 엄격한 규칙(내부 화소 차이 = 오류)을 그대로 쓰고 있었다.**
첫 판정이 그래서 FAIL 이었다 — 계획과 코드가 어긋난 것이지 그림이 틀린 게 아니었다.

고칠 때 **약화가 아니라 분리**했다: 평면은 여전히 "내부 차이 0"(색이 하나뿐이니 덮임만
다를 수 있다), 구로는 **채널당 1 이내**라는 새 경계다.  그 경계는 지어낸 것이 아니라
이 실행에서 잰 것이다 — R 1/0.57, G 1/0.52, B 1/0.56, A 1/0.48 (최대/평균).
무게중심 가중치와 고정소수점 span 보간의 반올림 차이로 설명되는 크기이고,
보간이 틀리면 뚫고 나갈 수 있는 경계다.
