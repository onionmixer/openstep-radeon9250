# G1 까지 남은 것 — 재부팅 3 회 예산 (2026-09-26, 사용자 지시)

사용자: "앞으로 딱 3 번만 재부팅에 협조한다.  그 안에 마무리되도록 계획하라."
원칙: **부팅 하나에 진단·복구·검증을 모두 싣고, 부팅 전에 호스트에서 끝낼 수 있는 것은 전부 끝낸다.**  진단만 하는 부팅은 없다.

## 끝의 정의 (G1)
화면 해상도(1024×768)까지의 teapot 이 카드로 그려지고, 여러 바퀴 돌려도 멈추지 않거나(멈추면 참조처럼 자동 복구되고
횟수가 기록되고), `glFinish` 뒤 그림이 응용 배열에 있고, 울타리 밖 쓰기 0, `judge_teapot` PASS.  그리고 문서·릴리스 준비.
- 된 것: glFinish 동기(M3g), 큰 깊이 버퍼(M3h — 64·256·640×480 일반 CARD PASS, 울타리 0).
- 남은 막힘: (1) CP 멈춤(간헐, 4 부팅), (2) 256×256 가림 차이 4 곳.

## 부팅 1 전, 호스트에서 (재부팅 없음, 순서대로)
1. 복구 경로: 계획서(`docs/M3J_PLAN.md`) — FreeBSD `radeon_do_engine_reset`·`radeon_do_cp_reset`·`radeon_do_cp_start` 를 표로 옮겨 우리 `cpReset`·`cpStart` 와 대조 → codex 계획 검토 → 검증 → 구현 → world5 에 "멈춘 CP 가 리셋 뒤 다시 간다"·"리셋도 안 되면 걸쇠" 시험 → check-all → 빌드·게이트·설치.
2. 256×256 가림 차이: M3h 그림의 다른 4 곳 좌표·깊이를 python 으로 뽑아 깊이 배치(피치 256 타일)·정밀도 중 무엇인지 호스트에서 가른 뒤 라이브러리 수정(재부팅 불필요).
3. 실행 스크립트 하나(`build/g1/run_g1.sh`): 크기 4 종 × 일반·컬링 × 바퀴, 복구 횟수 집계, 덤프 회수, 판정 입력 정리.
4. 그 뒤 재부팅 1 요청.

G1 뒤로: 양면 조명·polygon offset 거절, 폭 8 배수 제한, `ClearPixel`/`CopyDepth`/`DepthBuffer` 훅.
