# M1b — 첫 실제 훅과 가속 `libGL` (계획, 코딩 전)

기준일 2026-09-22.  선행: M1a 완료(`docs/M1A_PLAN.md` 12).
**이 문서는 코드보다 먼저 쓰였다.**

## 1. 이 칸의 한 줄

**가속 `libGL_radeon.a` 를 만들되, 아직 아무것도 그리지 않는다.**
훅 10 개가 전부 들어가고 `UpdateState` 하나만 **진짜** 일을 한다 — 상태를 보고, 재고,
분류한다.  그리기는 M1c 다.

그림이 **stock 과 픽셀 단위로 같아야** 하고, 동시에 **계수기가 0 이 아니어야** 한다.
둘 중 하나만으로는 아무것도 증명하지 못한다: 같기만 하면 훅이 안 불렸을 수 있고,
불리기만 하면 그림이 망가졌을 수 있다.

## 2. 이미 확인한 것 (직접 읽고 센 것)

| | 사실 | 근거 |
|---|---|---|
| F1 | 훅은 OSMesa 가 **자기 선택을 끝낸 뒤** 불린다.  주석이 "그릴 수 있는 상태만 바꾸고 나머지는 **찾은 그대로 두라**" 고 적는다 | `openstep-mesa342/upstream/Mesa-3.4.2/src/OSmesa/osmesa.c` 1995–2015 |
| F2 | `rowLength`·`yUp` 는 **매번** 넘어온다 — `OSMesaPixelStore` 가 문맥이 current 가 된 뒤에도 뒤집을 수 있기 때문 | 같은 자리의 주석 |
| F3 | `choose_triangle_function` 이 non-NULL 을 주는 것은 `RasterMask` **8192 조합 중 정확히 1 개**(`DEPTH_BIT` 단독, 0.012 %)뿐이고, 가장 흔한 `RasterMask == 0` 은 **거부**된다 | `build/m1b/design1.py` PASS — 조건·비트 목록을 `osmesa.c`·`types.h` 에서 읽어 셈 |

| F5 | `gl_render_vb` 는 디스패치 표를 **루프 앞에서 래치**한다 → 중간에 바꿔 끼울 수 없고 **위임만이 방법** | 같은 트리 `src/vbrender.c` 678–706 |
| F6 | 실기에 stock `libGL.a` 가 설치돼 있다(`/LocalDeveloper/Libraries/`, 2 012 284 B) | 실기 `ls` |

## 3. 만들 것

| | |
|---|---|
| `mesa/OSRDNMesaHook.c/.h` | `UpdateState` 의 **진짜** 구현: 프로브 게이트(M1a) → `rowLength`·`yUp` 기록 → 상태 분류 → 계수.  **`ctx->Driver` 를 쓰지 않는다**(이 칸에서는) |
| `mesa/OSRDNMesaStubs.c` | 나머지 **9 개** 훅의 거절 구현.  전부 계수한다 — 안 불린 훅과 거절한 훅은 다르다 |
| `tools/build-radeon-mesa.csh` | stock 을 복사 → `osmesa.o` 를 **우리 트리 소스**에서 `-DOPENSTEP_MESA_ACCEL_HOOK` 으로 재컴파일 → 우리 오브젝트를 `ld -r` 로 **하나로** → `ar`+`ranlib` → **훅 10 개 `nm` 감사** |
| `test/osrdn-mesa-render.c` | OSMesa 로 정해진 장면을 그려 픽셀을 그대로 찍는다.  stock·가속 둘 다로 링크해 **같은 출력**이어야 |
| `tools/mesa/check_hook.py` | 소스 규칙 + 변이(기준 PASS·변이 FAIL 같은 실행) |

## 4. 상태 분류 — 이 칸에서 "받겠다" 는 뜻이 아니다

`UpdateState` 는 상태를 셋으로 나누어 **세기만** 한다:

| 분류 | 뜻 |
|---|---|
| `WOULD_TAKE` | 우리가 그릴 수 있을 상태(색 버퍼 RGBA·텍스처 없음·스무스/플랫·`RasterMask` 가 우리가 아는 비트 안) |
| `WOULD_DECLINE` | 우리가 못 그릴 상태 |
| `NO_ACCEL` | 프로브가 `HARDWARE` 가 아니라 아예 묻지 않았다 |

세 개가 **전부 0 이 아니어야** 게이트가 의미를 갖는다(장면을 그렇게 고른다).

## 5. 빌드 규칙 (선례에서 가져오되 근거를 확인했다)

- `osmesa.o` 는 **우리 트리**(`openstep-mesa342/upstream/...`)에서 컴파일한다.  스테이징 사본에서
  컴파일하면 훅 자리를 고쳐도 낡은 파일이 쓰이고 **아무도 말해주지 않는다**.
- 우리 오브젝트는 `ld -r` 로 **하나**로 묶는다.  이 `ar` 은 멤버 이름을 **15 자**에서 자르고
  우리 이름은 앞 15 자가 겹친다.
- NFS 로 복사한 archive 는 **다시 `ranlib`** 한다(복사가 TOC 를 멤버보다 오래되게 만든다).
- 빌드 끝에 **훅 10 개가 정의 심볼로 있는지** `nm` 으로 확인한다 — 빠진 라이브러리는
  **링크가 멀쩡히 되고 그냥 가속이 안 된다**.

## 6. 게이트 (교차검토 뒤 다시 씀 — 8 절)

첫 판의 게이트는 **§1 을 증명하지 못했다.**  가장 큰 구멍: *픽셀이 같다는 것은 아무것도 안
그렸다는 뜻이 아니다* — 같은 그림을 그렸거나, 그린 뒤 덮였을 수도 있다.  그리고 게이트 A 가
"규칙마다 변이" 라고만 적혀 **규칙이 무엇인지 어디에도 없었다**(그런 A 는 빠진 규칙을 못 찾는다).

### A. 부작용 허용 목록 (호스트, `check_hook`) — 규칙을 **열거한다**

| | 규칙 |
|---|---|
| **A1** | 가속 소스 어디에도 그리기 경로가 없다: `mmap` 없음, `CAPS` 아닌 `ioctl` 없음, `ctx->` 어느 필드에도 대입 없음 |
| **A2** | 나머지 9 훅은 **정해진 거절값만** 돌려주고, 포인터 인자를 통해 쓰지 않으며, 자기 계수기 말고는 어떤 전역도 안 바꾼다 |
| **A3** | `UpdateState` 가 쓰는 것은 **기록한 `rowLength`·`yUp` 와 계수기뿐**이다 |
| **A4** | 규칙마다 변이가 있고, **기준 PASS 와 각 변이 FAIL 을 같은 실행에서** 본다 |

변이에는 최소한 이것들이 든다: *훅이 수락한다* · *훅이 포인터 인자를 통해 쓴다* ·
*훅이 `mmap` 을 부른다* · *`UpdateState` 가 `ctx->Driver` 에 대입한다*.

### B. 심볼 — 종류와 자리까지 (타깃 빌드)

| | |
|---|---|
| **B1** | 훅 10 개가 **text 심볼**로 정의돼 있다(`audit_hooks.py --nm`; 그 도구는 `[Tt]` 를 요구한다 — `tools/mesa/audit_hooks.py` 175 행에서 확인) |
| **B2** | archive 멤버 중 **앞 15 자가 겹치는 쌍이 없다**(`--members`).  §5 의 `ld -r` 는 *기법*이고 이것이 그 기법이 지키려는 *불변식*이다 — 게이트는 불변식에 건다 |
| **B3** | **`nm -u` 로 본 우리 가속 오브젝트의 미정의 심볼이 적어둔 허용 목록 안이다.**  `mmap`·`ioctl`·그리기에 필요한 어떤 심볼도 그 목록에 없다 — **그린 훅은 그중 하나 없이는 링크될 수 없다.**  픽셀 비교가 못 하는 일을 이것이 한다 |

### C. 한 번의 가속 실행 (실기) — 픽셀과 계수를 **함께**

첫 판은 픽셀(C)과 계수(D)를 따로 요구했다.  그러면 구현이 실행마다 다르게 굴어도 둘 다
통과한다.  하나로 합친다:

1. 렌더 **전** 계수가 전부 0 임을 읽는다.
2. 장면을 그린다.
3. 렌더 **후** `UpdateState` > 0, `WOULD_TAKE` > 0, `WOULD_DECLINE` > 0.
4. **바로 그 실행이 낸 픽셀**이 stock 실행의 픽셀과 **전수 동일**하다.

넷이 한 실행의 산출물이어야 한다.  장면은 세 분류가 모두 0 이 아니게 고른다.

### E. 스위치 (실기)

`RDNMesaAccelOff` 를 걸면 `NO_ACCEL` 만 세어지고, 그 실행의 픽셀도 여전히 stock 과 같다.

### F. 출처 사슬 (호스트) — 첫 판은 말이 안 됐다

첫 판은 "`osmesa.o` 를 뺀 나머지 멤버가 stock 과 같다" 고 썼는데, 가속 archive 에는 stock 에
**없는 멤버**(우리 것)가 있으므로 그대로는 성립하지 않는다.  다시 쓴다:

| | |
|---|---|
| **F1** | 가속 archive 의 멤버 목록 = stock 의 멤버 목록 **+ 정확히 하나** |
| **F2** | stock 에 있는 모든 멤버가 가속 archive 에서 **바이트 동일**, 단 `osmesa.o` 는 예외 |
| **F3** | 우리 트리의 `osmesa.c` 를 **매크로 없이** 컴파일한 것이 설치본 archive 안의 `osmesa.o` 와 **정의·미정의 심볼 집합과 text 크기가 같다** → 우리가 컴파일하는 소스가 stock 이 나온 그 소스다.  (바이트 동일을 요구하지 않는 이유: 같은 기계·같은 플래그라도 오브젝트가 바이트까지 재현된다는 보장이 없고, 재현 여부 자체가 이 칸의 주장이 아니다) |
| **F4** | upstream tar 의 sha256 이 `docs/RELEASE-MANIFEST.txt` 와 일치(이미 확인, F7) |

### G. 색인 (호스트) — 절차가 아니라 성질

"NFS 복사 뒤 `ranlib` 를 돌렸다" 는 산출물로 증명할 수 없다.  증명할 수 있는 것은
**최종 NFS archive 의 색인이 유효하다**는 것이다: 그 파일을 **색인을 써서** 링크하는 시험이
성공해야 한다.

## 7. 이 칸이 하지 않는 것

- **아무것도 그리지 않는다** — `ctx->Driver.TriangleFunc` 에 손대지 않는다.
- 색·깊이·텍스처를 **켜지 않는다**(한꺼번에 켜지 말라는 선례의 규칙).
- `openstep-mesa342` 트리를 **바꾸지 않는다** — 훅 자리는 이미 거기 있다.
- 드라이버를 바꾸지 않는다 → **재부팅을 쓰지 않는다**.

## 8. codex 교차검토 판정표 (회신 `kad5k859h`, 계획 단계·코딩 전)

물은 것: **§6 게이트 A~F 가 §1 의 주장을 실제로 증명하는가.**

| codex 주장 | 내 검증 방법 | 결과 |
|---|---|---|
| 게이트를 다 통과하면서 §1 이 거짓일 수 있다 — 다른 훅이 그리되 C 의 고정 장면에서만 거절하면 된다 | §6 원문 대조.  B 는 심볼 존재만, C 는 최종 픽셀만, D 는 계수만, F 는 가속 멤버의 **행동을 안 본다**.  막는 게이트가 없다 | ✅ **채택 — 내가 틀렸다.**  A 를 부작용 허용 목록으로 열거하고, **`nm -u` 허용 목록**(B3)을 넣었다 |
| **픽셀 동일성은 "안 그렸다" 를 증명하지 않는다** — 같은 것을 그렸거나 덮였을 수 있다 | 논리 검토 + §6 C 원문.  맞다 | ✅ 채택 — 이 한 문장이 이번 검토의 핵심이다 |
| 게이트 A 는 규칙이 열거돼 있지 않아 **빠진 규칙을 못 찾는다** | §6 A 원문: "규칙마다 변이" 가 전부였다 | ✅ 채택 — A1–A4 로 열거 |
| C 와 D 가 다른 실행이면 실행마다 다르게 구는 구현이 둘 다 통과한다 | §6 D 의 "같은 실행" 은 **계수 셋끼리만** 묶고 있었다 | ✅ 채택 — 한 실행의 네 산출물로 합쳤다 |
| §5 의 앞 세 규칙(우리 트리 컴파일·`ld -r`·`ranlib`)은 어겨도 어느 게이트도 실패하지 않는다 | §6 대조.  맞다 | ✅ 채택 — F3(출처)·B2(불변식)·G(색인)로 각각 뒷받침.  다만 `ld -r` 는 **기법**이므로 그 기법이 지키려는 **불변식**(15 자 충돌 없음)에 게이트를 건다 |
| B 가 같은 이름의 **데이터 심볼**도 받아들인다 | 도구를 열었다 — `tools/mesa/audit_hooks.py` 175 행이 `[Tt]`(text)를 요구한다 | ⚖️ **부분채택 — codex 가 도구에 대해서는 틀렸다.**  틀린 것은 내 *계획서 문구*("정의 심볼")였고, 그쪽을 고쳤다 |

**codex 가 놓쳤고 내가 찾은 것**: 첫 판의 F("`osmesa.o` 를 뺀 나머지가 stock 과 같다")는 **애초에
성립하지 않는 문장**이었다 — 가속 archive 에는 stock 에 없는 멤버가 하나 더 있다.  F1–F4 로 다시 썼다.

**그리고 가장 쓸모 있는 보강은 codex 의 제안이 아니라 거기서 나온 것이다**: `nm -u` 로 우리 가속
오브젝트의 **미정의 심볼**을 허용 목록에 가두면, *그린 훅은 `mmap` 이나 제출 경로 없이 링크될 수
없으므로* 픽셀 비교가 못 하는 "안 그렸다" 를 **링커가** 증명한다.

## 10. 실기 — **M1b 완료** (빌드 `790027299`, 2026-09-22)

드라이버는 바꾸지 않았다.  `libGL_radeon.a` 는 설치된 stock 의 **완전한 대체본**이다:
82 멤버를 그대로 두고 `osmesa.o` 하나만 매크로를 켜 다시 만들었고, 우리 오브젝트 하나를 더했다.

| 게이트 | 결과 |
|---|---|
| **A** 부작용 허용 목록 | 규칙 5, 변이 **9/9** (`check_hook`) |
| **B1** 훅 10 개 **text** 심볼 | PASS |
| **B2** 멤버 15 자 충돌 | 84 멤버, 없음 |
| **B3** 미정의 심볼 | **5 개뿐**: `_open _close _ioctl _getenv dyld_stub_binding_helper` |
| **C** 픽셀 | stock = 가속 = 스위치off, **4096/4096 동일**, 비검정 1499·색 4 종 |
| **E** 스위치 | `verdict=7 DISABLED`, `noaccel=9`, 그림 동일 |
| **F1·F2·F3** | 82 멤버 유지 + 1 추가, `osmesa.o` 만 다름, 전역 심볼 8·미정의 18 동일 |
| **G** | 색인을 통해 링크 |

**한 실행의 네 산출물**(계획 6-C): 렌더 전 계수 0 → 그림 → `update=9 take=1 decline=8
noaccel=0 verdict=0` → 그 실행의 픽셀이 stock 과 전수 동일.  스위치 실행은 `update=9
noaccel=9 verdict=7` 이고 그림은 역시 같다.  **둘 다 훅이 불렸고 그림은 안 바뀌었다** —
어느 한쪽만으로는 아무것도 증명하지 못한다.

### 게이트가 잡은 것

| | |
|---|---|
| **`_memcpy` 가 미정의 심볼에 있었다** | 소스는 안 부르는데 `probeCaps = caps` 한 줄에 컴파일러가 넣었다.  `memcpy(buffer, …)` 는 **`=` 없이** 인자 버퍼에 쓰므로 규칙 A2 를 우회한다 → 대입을 필드별로 풀고, A2 에 "`=` 없이 쓰는 함수" 를 추가 |
| **F3 가 실패했는데 원인은 내 전제였다** | 우리 것엔 `_choose_triangle_function`, 설치본엔 없음.  **소문자 `t`(파일 로컬)** 이라 최적화 차이지 소스 차이가 아니었다 → F3 를 **전역 심볼**로 좁히고 로컬 차이는 정보로 출력 |
| 실기 sh 함정 셋 | `mkdir -p` 없음, `cut` 없음, `case *[!0-9]*` 가 정상값 거절 — 전부 기록돼 있던 것들 |
| `nm`·`ranlib` 의 비0 종료 | 심볼 없는 stock 멤버 때문.  **종료 코드가 아니라 출력**으로 판정하게 고침 |

### 측정된 사실 — M1c 의 입력

거절 8 건이 **전부 `RASTER`** 다.  즉 보통의 OSMesa 상태에는 우리가 모르는 raster 비트가 켜져
있고, 우리가 아는 것은 `DEPTH_BIT` 하나뿐이다.  `take=1` 은 그 중 딱 하나가 깨끗했다는 뜻이다.
**어느 비트인지는 재지 않았다** — M1c 가 먼저 할 일이 그것이고, 지금 추측하지 않는다.
