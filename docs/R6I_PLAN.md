## 0. 한 줄 요약

R6h 가 미뤄 둔 네 가지(원근·이중선형·밉·여러 단위) 중 **앞의 둘**을 한 부팅으로 잰다.
(1) 정점에 W≠1 을 주고 `RE_CNTL.PERSPECTIVE_ENABLE` 을 켜서 **어느 양을 나누는지**(아핀인가, q = W0 인가, q = 1/W0 인가)를 텍셀로 읽고,
색(구로)도 같이 보정되는지 본다.  (2) `MAG/MIN_FILTER_LINEAR` 로 2×2·8×8 텍스처를 표본해 **텍셀 공간 오프셋(−½ 인가 0 인가)·가중치 양자·마무리 반올림**을 잰다.
밉과 여러 단위는 다음 조각이다.

## 2. 설계

### 2-1. 새로 필요한 것

- **정점마다 W**: 경우 필드 `widx`(0 = 모든 정점 1.0, 아니면 1 + `cpR6W[][3]` 의 행, float32 비트).  워드 수는 그대로다(자리는 이미 있다, Y4).
- **VTE**: 경우 필드 `vte`(0 = 기본 0x300, 아니면 상태 블록의 `SE_VTE_CNTL` 값 워드를 이 값으로).  워드 수 그대로.
- **`RE_CNTL`**: 이미 있는 `recntl` 필드에 8(`PERSPECTIVE_ENABLE`)을 넣는다.
- **텍셀 무늬**: `cpR6T` 에 열 하나(`pat`)를 덧붙인다 — 0 = R6h 무늬(`0xff000000 | (u·32)<<16 | (v·32)<<8 | 0x55`),
  **1 = 모서리 구분 2×2**(A = 0xff, R = 255·[u=1], G = 255·[v=1], B = 255·[u=1 ∧ v=1]),
  **2 = 교대**(A = 0xff, R = 255·(u&1), G = 255·(v&1), B = 0x55).
  무늬 1 은 네 텍셀의 가중치를 픽셀 한 개에서 **연립으로 풀 수 있게** 한다(B = w₁₁, R−B = w₁₀, G−B = w₀₁, 나머지 = w₀₀).
  무늬 2 는 R 이 **가로 가중치만**, G 가 **세로 가중치만** 나타내게 해서 축을 분리한다.  둘 다 알파가 0xff 라 ZPREP 패턴과 겹치지 않는다(python 으로 확인).
- **`PP_TXFORMAT_X`**: `cpR6T` 에 열 하나(`fmtx`) — 지금까지 늘 0 이던 값을 경우가 정한다(Y7 을 재는 PH 경우 때문).

- **색**(PE, V8 + W=(1,1/8,1/2)): 덮인 78 픽셀 중 **76 개**에서 아핀과 원근이 레인 값으로 8 이상 다르다(최대 53.9).
- **이중선형**(a = 0 대 −½): LA 265 / LC 273 / LD 275 픽셀에서 8 LSB 이상 다르다(최대 170·170·127).
- **미세 훑기**: LD 는 가로 소수부를 21 개(간격 1/24 = 10.6 LSB), LF 는 **276 개**(가장 큰 간격 9.6 LSB, 구간 0.917)로 표본한다 → 1/32 이하의 양자는 계단으로 드러난다.
- **PZ**(z = 1/4, 3/4, 1/2 + W=(1,1/8,1/2)): 덮인 276 픽셀 **전부**가 아핀과 원근에서 24 비트 깊이로 256 LSB 이상 다르다(최대 3,904,975 = 전 구간의 23 %).
- **PL**: 253 픽셀에서 R 바이트가 8 LSB 이상 다르다(최대 121.7), 그리고 원근으로 가팔라진 뒤에도 **픽셀당 최대 0.112 텍셀**이라 모든 픽셀이 확대다(MIN 필터가 못 들어온다).
- **LN**(2×8): 폭·높이를 뒤바꾼 8×2 해석과 **267/276** 픽셀에서 다르다(pat0 의 16 텍셀 중 12 개가 덮인다).  줄 간격 32 바이트 × 8 줄 = 256 바이트(예약 1 KiB 안).

### 2-3. 판정 (`check_r6a.py --procedure r6i`)

안전은 R6h 와 같다(표지·전제·걸쇠·덮임 = R6d 규칙, 텍스처 되읽기 `pfbad = 0`, 두 버퍼와 텍스처 밖 불변).  게이트는 일곱:

- **P1 (원근 모형)**: 109–114 의 안전 픽셀에서, 규칙 공간 {아핀, q = W0, q = 1/W0} × {표본 위치 0, ½} × {나눗셈 정밀도: 정확, 역수를 2⁻¹⁶·2⁻²⁰·2⁻²⁴ 로 자름} 가운데
  **모형 축이 하나로** 정해져야 한다(정밀도 축은 텍셀 알갱이에서 안 갈릴 수 있고, 그건 기록한다).  PA·PD·PH 는 XA 와 **워드까지 같아야** 한다.
- **P2 (`W0_FMT`)**: PF 는 두 이름 중 하나여야 한다 — ① 위치는 그대로이고 q 가 1/W0 로 바뀐다(= PB 의 q 해석과 같은 그림), ② 위치까지 나뉜다(그러면 덮임 지도가 예측대로 달라진다).  어느 쪽도 아니면 FAIL(측정).
- **P3 (색의 원근)**: PE 는 R6e 규칙 B 의 가중치를 **아핀으로 쓴 것**과 **원근으로 쓴 것** 중 하나와 안전 픽셀 전부에서 맞아야 한다.
- **B1 (이중선형)**: 116·118·119·121 의 안전 픽셀(소수부가 경계에서 2⁻¹⁰ 밖)에서, 규칙 공간
  {a ∈ 0, −½} × {표본 위치 0, ½} × {소수부 양자: 정확·1/16·1/32·1/64·1/128·1/256} × {양자 반올림: 내림·반올림·짝수} × {마무리: 내림·반올림}
  가운데 **정확히 하나**가 관측 바이트를 전부 설명해야 한다.  하나도 없으면 FAIL(측정) — 경우별 최소 잔차와 잔차 지도를 적고 호스트 분석으로 넘긴다(R6e·R6f 와 같은 절차).
  117·120 은 최근접이므로 **R6h 규칙으로 워드까지** 맞아야 한다.
- **B2 (상수 채널)**: 이중선형 경우의 알파는 모든 덮인 픽셀에서 0xff, pat2 의 B 는 0x55 여야 한다(가중치 합이 1 임을 뜻한다).  아니면 기록하고 이름을 붙인다.
- **B3 (축 배정)**: LN(2×8)은 최근접이므로 R6h 규칙 + 폭 2·높이 8 로 **워드까지** 맞아야 한다(뒤바꾼 해석과 267 픽셀에서 갈린다).
- **P4 (깊이의 원근)**: PZ 의 24 비트 깊이 평면은 R6f 규칙(아핀 평면 + 내림)의 **아핀 가중치** 판과 **원근 가중치** 판 중 하나와 전 픽셀에서 맞아야 한다.
- **P5 (나눗셈 정밀도)**: PL 은 B1 이 가중치 규칙을 이름 붙인 **뒤에** 판정한다 — 그 규칙으로 계산한 원근 소수부가 관측 바이트를 설명해야 하고,
  설명 못 하면 잔차를 기록한다(정밀도 이름 짓기는 호스트 분석).  B1 이 FAIL 이면 PL 은 기록만 한다.

**분석 메모 A3(codex 가 제기한 혼동)**: LF 의 계단이 ① 보간기의 s 양자인지 ② 필터 가중치 양자인지는 한 경우로 못 가른다.
둘을 가르는 것은 **기울기 비**다 — LA 는 정규화 s 기울기 1/24·폭 2(텍셀 1/12 픽셀), LD 는 1/192·폭 8(텍셀 1/24 픽셀)이라
①이면 계단 폭이 폭(w)에 따라 4 배 달라지고 ②면 소수부 단위로 같다.  두 경우의 잔차를 함께 맞춰 가른다(추가 경우 없이).

### 2-4. 안전

- 쓰는 곳은 R6h 와 같다(색 32×32, 깊이 32×32, 텍스처는 CPU 만 쓰고 GPU 는 읽기만) — 전부 별칭 256 KiB 안.  새 레지스터는 없다(값만 바뀐다).
- W 는 어떤 경우에도 0 이 아니다(1/8 … 8) → 나눗셈 0 없음.  python 으로 표 전체를 검사한다.

## 8. R6i 실기 결과 (부팅 ff78c18a, 빌드 375a2151) — 원근·깊이·오프셋 확정, 이중선형 산술은 다음 조각

절차 전체 rc 0(ZCLEAR 19 회, PLANE 280 회, 텍스처 되읽기 `pfbad=0`), cycle `verdict=0`,
판정 `--procedure r6i` **FAIL 1**(`build/r6i/judge-ff78c18a.txt`) — 남은 하나가 **B1b(이중선형 가중치 산술)**, 규칙 공간 밖이라는 뜻이고 나머지 게이트는 전부 이름이 붙었다.
R6e 가 그랬듯 "공간 밖" 은 게이트를 무르게 하지 않고 **측정 FAIL 로 남겨** 다음 조각(R6i-2)이 이름을 붙인다.
(첫 판정은 FAIL 3 이었다 — 셋 중 둘은 판정기 잘못이었다, 아래 "규칙 공간" 참조.)

**확정된 것**

- **원근 보정은 q = W0**: 정점의 W 워드가 그대로 가중치가 된다 — `(Σλ·s·W0)/(Σλ·W0)`.  PB·PC 가 **안전 픽셀 0 불일치**로 이 모형만 맞고(아핀·1/W0 은 각각 101·223 픽셀 어긋남), PA(W=1)는 아핀 그림과 워드까지 같다.
- **`RE_CNTL.PERSPECTIVE_ENABLE` 이 결정한다**: PD(비트만 끄고 W 는 같음)는 PA 와 **276 픽셀 전부 동일** — 비트가 없으면 W 는 무시된다.
- **`SE_VTE_CNTL.VTX_W0_FMT` 는 역수를 취하라는 뜻**: PF(비트 켜고 W = 1, 8, 2)가 PB(비트 끄고 W = 1, 1/8, 1/2)와 **276 픽셀 전부 동일**.  모형이 아니라 **자료 대 자료의 항등**이라 가장 강한 증거다(Y3 가설 확인).
- **`TEXCOORD_PROJ` 는 2 성분 ST 에서 무해**: PH = PA, 276 픽셀 전부 동일(Mesa 주석대로).
- **깊이는 원근 보정되지 않는다**: PZ 와 아핀 대조 I1_24 가 **1024 픽셀 전부 동일**(원근 모형과는 최대 3,941,868 LSB 차이).  OpenGL 규약과 같다.  같은 부팅의 대조가 아핀 평면과 **최대 1 LSB** 밖에 안 다르다는 것도 확인됐다(R6f 가 남긴 설정 반올림의 크기).
- **색은 원근 보정된다**: PE 는 V8(같은 삼각형, W=1)과 78 픽셀 전부 다르고, 원근 규칙 B 로 312 바이트 중 **272 개가 정확**, 나머지 40 개가 ±1 LSB(아핀 모형은 311 바이트·최대 54 LSB 어긋남).  마지막 1 LSB 는 하드웨어의 고정소수 나눗셈 — 기록.
- **ST 표본 위치는 픽셀 중심(+½)**: PB·PC·PF 가 **½ 에서만** 0 불일치다(7/16 은 4–17 픽셀 어긋남).  → **docs/R6H_PLAN.md 8 의 "표본은 픽셀 모서리 쪽 [0, ½), 중심은 배제" 는 틀렸다**(9 참조).
- **이중선형의 텍셀 오프셋은 a = −½**(OpenGL 반 텍셀): 정확 이중선형과의 최대 차이가 a=−½ 에서 **6 LSB**, a=0 에서 **182 LSB**.
- **가중치 합은 정확히 1**: 상수 채널(알파 0xff, pat2 의 B 0x55)이 모든 이중선형 경우에서 그대로 나온다.
- **비정사각 텍스처**: 2×8 은 폭 2·높이 8 로 읽힌다(뒤바꾼 해석은 267 픽셀 어긋남).  최근접 대조 LB·LE·LN 은 R6h 규칙으로 워드까지 일치.
- **독립 재계산**(`build/r6i/indep_r6i.py`: 판정기와 다른 파서·덮임·보간·주소·텍셀 구현): 아홉 경우 **2468 픽셀 0 불일치**.

**규칙 공간이 또 좁았다(내 실수)**: 첫 판정의 FAIL 셋은 하드웨어가 아니라 판정기였다 — (1) P2 가 표본 위치를 0 으로 **고정**해 PF 를 못 맞혔고(오프셋을 훑으니 1/2 에서 0 불일치),
(2) P3 이 "정확히 일치" 만 인정해 ±1 LSB 를 FAIL 로 봤으며, (3) B1 이 텍셀 오프셋과 가중치 산술을 **한 게이트에 묶어** 둘 다 잃었다.
고친 방식은 약화가 아니라 **분리**다: P3 은 모형을 게이트하고 마지막 LSB 를 기록, B1 은 **B1a(텍셀 오프셋, 게이트)** 와 **B1b(가중치 산술, 측정)** 로 나눴다.  R6e·R6f·R6h 와 같은 실수를 네 번째로 반복했다.

**남은 것(다음 조각 R6i-2)**: 이중선형 가중치의 정확한 산술.  관측은 (i) 정확 이중선형과 **최대 5–6 LSB** 차이, (ii) R 채널이 **세로 소수부에도 의존**한다 → 네 가중치가 각각 양자화된다,
(iii) 잔차의 평면 맞춤은 기울기 오차 2·10⁻⁴ 텍셀/픽셀 수준(설정 반올림).  이름 붙은 산술(양자 1/16…1/256 × 내림·반올림·짝수 × 마무리 셋) 중 정확한 것은 없었다 — 기울기가 이진분수인 경우를 설계해 따로 재야 한다.
