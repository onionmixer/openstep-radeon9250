# M1a — 가속 게이트 (Mesa 이전, 코딩 전 계획)

기준일 2026-09-22.  선행: R7b 완료(`docs/R7_PLAN.md` 10-11).
**이 문서는 코드보다 먼저 쓰였다.**

## 1. 왜 이것이 첫 칸인가 (순서는 내가 정한 것이 아니다)

Mesa 통합의 첫 칸으로 "훅 10 개를 거절 스텁으로 구현한 가속 `libGL`" 을 만들 뻔했다.
선례가 그걸 **명시적으로 금지**한다 — 직접 열어 확인했다:

> M1-3a를 먼저 짜면 "우리 하드웨어가 있다"를 전제한 코드가 된다. 게이팅을 나중에 끼우면
> **되돌림 경로가 시험되지 않은 채 남는다** — 그리고 되돌림은 정상 경로보다 **더 자주 쓰일**
> 코드다.
> — `openstep-matrox-remade/docs/M1_3_GATING_PLAN.md` 18–23 행

> M1-3a에 **탐지와 되돌림을 먼저 넣는다. 훅을 채우기 전에.**
> — 같은 문서 285–289 행

> **Mesa 코드는 아직 건드리지 않는다.** … 배관이 증명되기 전에 Mesa를 손대면 실패했을 때
> **원인이 두 겹**이 된다.
> — `openstep-matrox-remade/docs/M1_MESA_BRIDGE_PLAN.md` 12–18 행

그래서 M1a 는 **탐지·판정·되돌림만** 한다.  훅도, 가속 `libGL` 도, 그리기도 없다.

## 2. 이미 증명된 조각 (R7b 가 만든 것)

M1a 는 새 통로를 만들지 않는다 — R7b 가 이미 만들었고 실기로 증명했다:

- `-lDriver` 없는 **순수 C** 클라이언트가 `open`·`ioctl`·`mmap` 만으로 드라이버에 닿는다.
- `ioctl(CAPS)` 가 `magic`·`version`·`window`·`bytes`·`maxWords`·`build`·`ready`·`cpRunning`·
  `winStart` 를 돌려준다.
- 모르는 명령은 **`ENOTTY`**, 장치가 없거나 걸쇠에 걸리면 **`ENXIO`**.

즉 프로브가 물어볼 것은 전부 이미 있다.  M1a 는 그것을 **재사용 가능한 판정기**로 묶는다.

## 3. 판정 (`build/m1a/design2.py`, PASS — 손으로 적지 않고 계약에서 유도)

**9 개 중 8 개가 소프트웨어를 뜻한다.**  가속하는 판정은 `HARDWARE` 하나뿐이다.

| 판정 | 언제 | 무엇을 하는가 |
|---|---|---|
| `HARDWARE` | 전부 통과 | 가속 |
| `NO_DEVICE` | 노드가 없거나 `open` 거절(`ENXIO`) | 소프트웨어 |
| `NOT_OURS` | 노드는 답하지만 이 드라이버가 아님(`ENOTTY`) | 소프트웨어 |
| `MAGIC` | `CAPS` 는 왔으나 매직이 다름 | 소프트웨어 |
| `VERSION` | 버전이 컴파일 시점과 다름 | 소프트웨어 |
| `NOT_READY` | `caps.ready == 0`(배치 페이지·창 없음) | 소프트웨어 |
| `NOT_RUNNING` | `caps.cpRunning == 0`(CP 미동작) | 소프트웨어 |
| `DISABLED` | 환경 스위치가 껐음 | 소프트웨어 |
| `REVOKED` | 앞서 문제가 있어 스스로 내려놓음 | 소프트웨어 |

## 4. 정책 (전부 시험 가능한 규칙으로)

| | 규칙 | 왜 |
|---|---|---|
| **P1** | 실패는 **오류가 아니라 판정**이다 — 프로브는 언제나 답한다 | 답하지 않는 프로브는 호출자가 폴백을 고를 수 없다 |
| **P2** | 답은 **캐시**되고 이후 호출에서 **같아야** 한다 | 프레임마다 답이 바뀌면 한 프레임이 두 층에 걸쳐 그려진다 |
| **P3** | 회수는 **단방향** — `REVOKED` 는 `HARDWARE` 로 돌아가지 않는다 | 실패한 가속을 다시 켜면 같은 실패를 반복한다 |
| **P4** | 환경 스위치는 **끄기만** 가능, 켜기는 불가 | 켤 수 있으면 하드웨어가 없는 기계에서 켜진다 |
| **P5** | 버전은 **정확히** 일치해야 한다 | 버전은 **공유 메모리 배치의 이름**이다 |
| **P6** | 정체는 **ioctl 자신**이 정한다 — 남의 드라이버는 `ENOTTY` | 이름·major 로 고르면 남의 노드를 우리 것으로 읽는다 |
| **P7** | 클라이언트는 **`-lDriver` 없이** 링크된다 | `libGL` 은 Objective-C 를 못 싣는다 — 이 사다리의 존재 이유 |

## 6. 게이트 (교차검토 뒤 다시 씀 — 9 절)

첫 판에서 게이트 A 를 "9 판정 **전부 도달**" 로 썼다.  그건 **판정을 순서대로 뱉는 가짜 구현도
통과**한다 — 내 `PLAN.md` 188 행이 금지하는 "아무것도 검증하지 않는 게이트" 를 내가 쓴 것이다.
도달이 아니라 **입력 → 기대 판정**으로 고친다.

### A. 입력과 기대 판정의 표 (호스트, `sim_probe`)

가짜 `open`/`ioctl` 에 아래 입력을 주고 **기대 판정과 일치**해야 한다.  표가 9 판정을 모두
덮는지도 같은 실행에서 센다.

| # | 가짜 입력 | 기대 |
|---|---|---|
| A1 | 노드 없음(`stat` 실패) | `NO_DEVICE` |
| A2 | `open` 이 `ENXIO` | `NO_DEVICE` |
| A3 | `CAPS` 가 `ENOTTY` — **그런데 노드 이름·major 는 그럴듯하다** | `NOT_OURS` (P6: 정체는 ioctl 이 정한다) |
| A4 | `CAPS` 는 성공, `magic` 이 다름 | `MAGIC` |
| A5 | `version` = 현재값 **− 1** | `VERSION` |
| A6 | `version` = 현재값 **+ 1** | `VERSION` |
| A7 | `version` = 현재값 (나머지 정상) | `HARDWARE` (P5: **정확히** 일치할 때만) |
| A8 | `ready == 0` | `NOT_READY` |
| A9 | `cpRunning == 0` | `NOT_RUNNING` |
| A10 | 스위치 off, 나머지 정상 | `DISABLED` |
| A11 | 정상 | `HARDWARE` |

**A-cover**: A1–A11 이 내놓은 판정의 집합이 §3 의 9 개를 **전부** 덮는다(`REVOKED` 는 A-revoke 가).
**A-noerr** (P1): A1–A11 어느 것도 오류로 끝나지 않는다 — 전부 **판정을 돌려준다**.

### A-cache (호스트, P2 를 실제로 증명)

첫 호출 뒤 **가짜 CAPS 를 바꾼다**(예: `ready` 를 0 으로).  두 번째 호출이 **그대로 `HARDWARE`** 여야
한다.  바뀌면 캐시가 아니라 매번 다시 묻는 것이다.  *상태를 안 바꾸고 두 번 부르는 것은 캐시를
증명하지 않는다.*

### A-revoke (호스트, P3 를 실제로 증명)

`revoke` 뒤에는 **`HARDWARE` 를 돌려줄 가짜를 주어도** `REVOKED` 여야 한다.  "한 번 더 불러도
안 돌아온다" 로는 부족하다 — 뒤이은 **성공**이 되돌리지 못한다는 것이 단방향의 내용이다.

### A-switch (호스트, P4 를 실제로 증명 — 두 부분)

첫 판에서 "켜기 값을 줘도 `NOT_RUNNING` 이어야 한다" 고 썼다.  **그건 틀린 기대다** — 스위치는
빼기만 하므로 `"on"` 도 **끄고**, 답은 `DISABLED`(여전히 소프트웨어)가 되는 것이 맞다.  그리고 그
기대로는 "값을 읽어서 켤 수도 있게" 만든 구현을 **못 잡는다**.  그래서 둘로 나눈다:

- **A-switch-1**: 스위치는 **읽는 값이 아니라 있음/없음**이다.  나머지가 전부 정상(=`HARDWARE`)
  일 때 `""`·`"0"`·`"1"`·`"on"`·`"off"`·`"no"`·`"yes"` **전부** `DISABLED` 여야 한다.
  값을 읽는 스위치는 **예라고 말하게 만들 수 있는** 스위치다.
- **A-switch-2**: **하드웨어가 아닌 상태**(`cpRunning == 0`)에서 어떤 값을 줘도 결과가
  **`HARDWARE` 가 되지 않는다**.  하드웨어가 멀쩡한 기계에서 이걸 시험하면 `HARDWARE` 가
  **맞는** 답이라 아무것도 증명하지 못한다.

### B. 규칙과 변이 (호스트, `check_probe`)

**같은 실행에서** 기준 소스가 **PASS** 하고 규칙마다 변이가 **FAIL** 해야 한다(`PLAN.md` 188 행;
[[checker-discipline]] 도 같은 말이다).  변이만 잡히는 것을 보는 것으로는 구현이
규칙을 지킨다는 증거가 되지 않는다.

### 실기

- **C** 정상 부팅에서 `HARDWARE`, 같은 프로세스에서 두 번째 호출도 같은 값.
  *(이건 안정성이지 캐시의 증명이 아니다 — 캐시는 A-cache 가 증명한다.)*
- **D** 스위치를 끄면 `DISABLED`.  *(P4 의 "켜기 불가" 는 A-switch 가 증명한다.)*
- **E** `revoke` 뒤 `REVOKED`.
- **F** CP 를 올리기 **전**에 물으면 `NOT_RUNNING`, 올린 뒤엔 `HARDWARE` — **같은 기계에서 판정이
  실제로 갈린다**는 증거.

## 7. 이 칸이 하지 않는 것

- `osmesa.c` 에 훅 자리를 **추가하지 않는다** — `openstep-mesa342` 트리는 건드리지 않는다.
- 가속 `libGL` 을 **만들지 않는다**.
- **아무것도 그리지 않는다** — 하드웨어든 아니든.
- 드라이버를 **바꾸지 않는다** → 이 칸은 **재부팅을 쓰지 않는다**.

## 8. 다음 칸에 넘기는 것 (지금 정하지 않는다)

- `UpdateState` 가 **첫 실제 훅**이 되어야 한다.  Mesa 는 상태가 바뀔 때마다 드라이버의
  삼각형 포인터를 지우고 다시 설치하게 하므로, 그 훅이 설치점·거절점·게이트를 겸한다.
  그리고 `gl_render_vb` 는 디스패치 표를 **루프 앞에서 래치**하므로(우리 트리
  `openstep-mesa342/upstream/Mesa-3.4.2/src/vbrender.c` 678–706 행에서 직접 확인) 중간에
  바꿔 끼울 수 없다 — **위임만이 방법**이다.
- 거절은 **상태 단위**다.  삼각형 단위 거절은 선택기가 제공하지 않으며, 선례는 거절된 배치가
  **그 삼각형을 잃고 프로세스 가속을 통째로 회수**하는 것을 실제로 두 번 봤다
  (`openstep-matrox-remade/docs/M1_4A0_FALLBACK_PLAN.md` 1–20 행, 직접 확인).  그러므로
  M1b 는 **거절이 삼각형을 잃지 않는 것**을 처음부터 설계에 넣는다.
- 색·깊이·텍스처를 **한꺼번에 켜지 않는다**.

## 9. codex 교차검토 판정표 (회신 `k1vmj1s80`, 계획 단계·코딩 전)

물은 것: **§3 의 9 판정과 §4 의 7 정책이 §6 게이트로 실제로 시험되는가.**

| codex 주장 | 내 검증 방법 | 결과 |
|---|---|---|
| 게이트 A 가 "도달"만 요구해서, 판정을 순서대로 뱉는 구현도 통과한다 | 내 §6 원문을 다시 읽었다 — `"9 판정 전부 도달"` 이 전부였다.  그리고 `PLAN.md` 188 행이 정확히 이걸 금지한다 | ✅ **채택 — 내가 틀렸다.** A 를 입력→기대 판정 표로 다시 썼다 |
| `NO_DEVICE`·`NOT_OURS`·`MAGIC`·`VERSION`·`NOT_READY` 는 A 에만 걸려 있어 조건이 시험되지 않는다 | 같은 원문 대조.  다섯 판정 모두 다른 게이트가 없다 | ✅ 채택 — A1–A8 로 각각 고정 |
| **P5(정확 일치) 미시험**: `VERSION` 에 한 번 도달하는 것으로는 정확 일치를 못 증명한다 | §4 P5 와 §6 대조.  맞다 — 낮은 값·높은 값·정확값 세 줄이 있어야 "정확히" 가 시험된다 | ✅ 채택 — A5·A6·A7 |
| **P6(정체는 ioctl) 부분 시험**: 이름·major 로 판정해도 `NOT_OURS` 에 도달한다 | 같은 대조.  맞다 | ✅ 채택 — A3 을 "이름·major 는 그럴듯한데 `ENOTTY`" 로 |
| **P2(캐시)**: C 의 "안 바꾸고 두 번 같은 값" 은 캐시를 증명하지 않는다 | §6 C 원문.  맞다 — 매번 다시 묻는 구현도 같은 값을 준다 | ✅ 채택 — A-cache(첫 호출 뒤 가짜를 바꾼다) |
| **P4(스위치)**: D 의 "켜도 `HARDWARE` 아님" 은 같은 프로세스면 캐시로 설명되고, 애초에 하드웨어가 있으면 `HARDWARE` 가 맞는 답이다 | §6 D 원문.  맞다 — **내 시험이 틀린 시험이었다** | ✅ 채택 — A-switch(비하드웨어 상태에서 켜기) |
| **P1**: 실패 조건마다 "오류 없이 판정을 돌려주는지" 가 확인되지 않는다 | §4 P1 과 §6 대조.  맞다 | ✅ 채택 — A-noerr |
| **B**: "기준 PASS + 각 변이 FAIL" 을 함께 요구해야 한다 | §6 B 원문은 변이만 본다.  그리고 이건 **내가 이미 기억에 적어둔 규칙**이다([[checker-discipline]]) | ✅ 채택 — 내가 내 규칙을 안 적었다 |
| A~F 중 전체가 무의미한 게이트는 없다 | 같은 대조 — 동의 | ⏭️ 행동 변화 없음 |

**codex 가 놓쳤고 내가 찾은 것**: E("revoke 뒤 한 번 더 불러도 안 돌아온다")는 **뒤이은 성공**이
되돌리지 못한다는 것까지는 안 본다.  단방향의 내용은 그쪽이다 → A-revoke 를 그 모양으로 썼다.

**정정 하나**: codex 는 `DISABLED`·`NOT_RUNNING`·`REVOKED` 를 "시험됨" 으로 분류했는데, 그건
**판정 자체**에 대해서만 맞다.  그 판정들이 거는 **정책**(P4·P3)은 위에서 보듯 시험되지 않고
있었다.  판정과 정책을 갈라 세지 않으면 커버리지가 실제보다 좋아 보인다.

## 10. 구현 중 고친 것 (게이트가 잡았다)

| 무엇 | 어떻게 드러났나 |
|---|---|
| `stat` 이 중복이었다 | 노드 없음과 `open` 거절이 **같은 판정**이라 두 번 물을 이유가 없다.  호출·헤더·시임을 함께 지웠다 |
| libc 헤더 의존 | 호스트에 32 비트 libc 헤더가 없어 빌드 불가.  이 프로젝트의 다른 시뮬레이터처럼 **libc 헤더 없이** 쓰고 필요한 4 개만 선언, `O_RDWR`(=2)는 타깃 헤더에서 확인해 고정 |
| `Forget()` 이 회수를 안 지웠다 | 단방향이라 앞 시험이 뒤 시험에 남았다.  시험 시임은 **초기 상태 전체**로 되돌린다 |
| **A-switch 의 기대가 틀렸다** | 스위치가 빼기만 한다면 `"on"` 은 `DISABLED` 가 **맞다**.  틀린 기대는 "값을 읽어 켤 수도 있는" 구현을 **못 잡았다** |
| **회수 걸쇠가 중복이었다** | `Revoke()` 가 캐시에도 `REVOKED` 를 써서, 걸쇠 검사를 지워도 캐시가 가렸다.  걸쇠가 **유일한 근거**가 되게 고쳤다 — *발동시킬 수 없는 검사는 검사가 아니다* |

`tools/mesa/sim_probe.py`: 입력 11 행 + 캐시·회수·스위치, **변이 9 개 전부 자기 시험에** 잡힘, 기준 PASS.
