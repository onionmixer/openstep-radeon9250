# R6g — 깊이 판정: 비교 함수 여덟 개와 쓰기 마스크를 실측으로 정한다 (계획, 코딩 전, codex 교차검토 대상, 2026-09-20)

입력: `docs/R6F_PLAN.md` 11–12(깊이 값: `floor(z·2ⁿ)`, 16 비트 = 24 비트 상위 16 비트, 배치 `mba_z16`, 보간은 아핀+내림이며 16 비트에서는 정확 보간과 구별 불가),
`docs/R6D_PLAN.md` 13(덮임 규칙), `PLAN.md` R6 절(사다리: 평면색 → 구로 → **깊이** → 텍스처 …).

## 0. 한 줄 요약

깊이 칸의 나머지 절반이다.  **저장된 깊이를 CPU 가 먼저 써 넣고**(프리필), 값이 정확히 알려진 **상수 z 삼각형**을 각 비교 함수로 한 번씩 그린다 —
색 버퍼가 통과 집합을, 깊이 평면이 "통과하면 새 값, 아니면 옛 값" 을 보여준다.  값 규칙이 R6f 에서 확정됐으므로 **이번에는 예측이 정확해 게이트를 걸 수 있다**(측정 부팅이 아니다).

## 2. 설계

### 2-1. 프리필 (새 것)

ZCLEAR 이 그리기 전에 **CPU 가 깊이 버퍼의 32×32 에 `stored(x, y) = A + B·x + C·y`(깊이 단위, 클램프)를 쓴다** — 주소는 형식에 맞는 `mba_z16`/`mba_z32`,
32×32 밖은 패턴 그대로.  쓴 뒤 되읽어 틀린 칸 수를 `pfbad` 로 기록(로그), 0 이 아니면 그리지 않고 실패.  그리고 **그리기 앞에 Z 캐시 purge**(E4·E5: 낡은 캐시 줄이
프리필을 덮지 못하게) — 프리필 경우에만 스트림 앞에 두 워드가 붙는다.  경우 필드: `pf`(0 없음, 1 프리필), `pfa`·`pfb`·`pfc`(부호 있는 32 비트, 2 의 보수로 저장).

### 2-2. 경우 (번호 82–96; A·F 는 회귀)

기하는 모두 **T1z**(4,4)(28,4)(4,28), 색은 평면 상수 C1, 프리필은 위 값(16 비트 A=15360·B=1024·C=512, 24 비트는 256 배), 그리는 z 는 **상수 0.5**
(= 16 비트 32768 · 24 비트 8388608)뿐이다(보간 경우 하나 제외).  `RB3D_ZSTENCILCNTL` 은 형식 비트 + 비교 함수 + 쓰기 비트로 만든다.

### 2-3. 판정 (`check_r6a.py --procedure r6g`)

- 안전: R6f 와 같음(표지·전제 되읽기·블록 나머지 불변·걸쇠 없음) + `pfbad = 0`.
- **색 = 통과 집합**: 덮임 지도(코드 1)가 예측한 통과 픽셀과 정확히 같아야(게이트).  덮임 밖은 패턴.
- **깊이 = 통과하고 쓰기가 켜졌으면 새 값, 아니면 프리필**: 깊이 평면 전 픽셀 대조(게이트), 그리고 평면으로 재구성한 요약값 = 로그의 깊이 요약값(배치·32×32 밖·스텐실).
- GZE(92)는 기록만: 통과 집합과 깊이가 "판정 끔(전부 통과)" · "쓰기 끔" · "선례와 같음" 중 무엇인지 이름을 붙인다.
- GF·GFG 는 두 가설("내림한 정수로 비교" vs "내림 전 값으로 비교")의 예측을 둘 다 계산해 어느 쪽인지 **이름을 붙인다**(둘 다 아니면 FAIL).
- 회귀 A·F 는 R6f 와 같음.

### 2-4. 안전

- 쓰는 곳은 R6f 와 같다(깊이 32×32 · 색 32×32, 깊이 영역 4/8 KiB 안).  새 레지스터 없음 — `RB3D_ZSTENCILCNTL` 의 비교·쓰기 비트와 `RB3D_CNTL` 한 비트.
- CPU 프리필은 별칭으로 쓰고 `cpFence` 뒤 되읽어 확인한다(ZPREP 과 같은 방식).  GPU 가 읽기 전에 Z 캐시 purge.
- Z_ENABLE 을 끄는 경우(92)는 깊이 쓰기가 아예 없을 수도, 전부일 수도 있다 — 어느 쪽이든 쓰는 범위는 같은 32×32 안.
- 로그: 경우당 ZCLEAR 1 + PLANE 8(16 비트)·12(24 비트) → 15 경우 + 회귀 2, PLANE 128 회.

### 2-5. 호스트 검사

- `depth_oracle.py`: R6g 경우·프리필·통과 집합·기대 깊이·C 행 생성 + 자체검사(표 2-2 의 통과 수, 프리필 범위, 등치 12 픽셀, GF 두 가설이 다른 예측을 낸다는 것).
- `world5.c`: 가짜 3D 에 깊이 판정(여덟 함수)·쓰기 마스크·Z_ENABLE, 프리필을 읽는 경로; `sim_r6.py` 에 R6g 스트림·평면·변이(비교 필드 자리 틀림, 쓰기 비트 무시,
  프리필 주소 틀림, purge 없음, 통과했는데 깊이 안 씀 …).
- `check_r6a.py` r6g 자체검사: 합성 부팅(정상) + 부정 시험(통과 집합 한 픽셀, 쓰기 마스크 무시, 프리필 불일치, GF 어느 쪽도 아님).
- `check_r5_src.py`: 새 필드·행을 오라클과 대조.

## 3. 실기 절차(한 부팅)

준비(RECORD·REC3D·LOAD·MAP·RESET·START·REC3D) → A·F → 82–96 각각 ZPREP·ZCLEAR·PLANE → REC3D·STOP·RECORD·cycle.
판정 `check_r6a.py <log> --boot N --build B --procedure r6g`.  첫 프리필 경우(82)에서 `pfbad ≠ 0` 이거나 예상 밖이면 그리기를 멈추고 정리만.

## 4. 교차검토에 물을 것 (한 호출 한 주장)

1. CPU 로 깊이 버퍼를 채운 뒤 그리기 전에 Z 캐시를 purge 하면 충분한가 — 참고에 "3D 가 읽기 전 무효화" 를 요구하는 다른 절차가 있는가.
2. `RB3D_CNTL.Z_ENABLE` 이 0 일 때의 동작을 말하는 근거가 참고에 있는가(판정만 끄는가, 쓰기까지 끄는가).
3. 깊이 비교가 내림한 정수로 이뤄진다는 가정을 반박하는 근거가 있는가(E8 의 판별 경우 설계가 타당한가).
4. 프리필을 쓰는 이 설계가 놓치는 것 — 두 번 그리기(진짜 가림)로만 드러나는 성질이 있는가.

## 6. 두 번 그리기 (codex Q4 반영, 2-2 에 이어지는 경우 97–100)

한 ZCLEAR 이 **그리기 둘**을 같은 제출에 넣는다: 첫 그리기 뒤 `RB3D_ZSTENCILCNTL`(비교·쓰기)만 바꾸고 두 번째 머리·VF·정점을 잇는다 — **사이에 캐시 비움이 없다**(그것이 ① 의 시험).
경우 필드 `d2`(0 없음, 아니면 둘째 그리기 표의 행: zcntl, z, 색, 기하)와 `d2wait`(1 이면 두 그리기 사이에 `WAIT_UNTIL` 3D_IDLECLEAN 두 워드).

| 97 | H1 | 없음(패턴) | z **0.9**, ALWAYS, 쓰기 켬, 색 C1 | z **0.5**, LESS, 쓰기 켬, 색 C2 | ① GPU 가 쓴 깊이를 캐시 비움 없이 읽는다 — 정상이면 **276 전부 통과**(색 C2·깊이 32768), 낡은 패턴을 읽으면 **132** 만 통과 |
| 98 | H2 | 상수 0.75 | z 0.25, LESS, **쓰기 끔**, 색 C1 | z 0.5, LESS, 쓰기 켬, 색 C2 | ② 쓰기가 꺼졌을 때 내부 값도 안 남는가 — 둘째가 전부 통과하고 깊이 0.5 |
| 99 | H3 | 없음 | z 0.5+2⁻¹⁷, ALWAYS, 쓰기 켬 | 같은 z, **EQUAL**, 색 C2 | ③ 래스터가 만든 깊이와 다시 만든 깊이가 같은가 — 전부 통과 |

| 101 | H1w | 없음(패턴) | H1 과 같음 | H1 과 같되 **사이에 `WAIT_UNTIL` 3D_IDLECLEAN** | 대기가 필요한지: H1 이 어긋나고 이것이 맞으면 "두 그리기 사이에 대기가 필요" 가 규칙이 된다 |

- 색은 두 값(C1·C2)이라 덮임 지도의 코드 1·2 가 그대로 "어느 그리기가 이겼나" 가 된다(R6d 의 두 색 경우와 같은 방식).
- 97·99·100 은 프리필이 없다(ZPREP 의 패턴이 저장값) — 패턴의 하위 16 비트는 픽셀마다 달라 첫 그리기가 통과할지 예측하기 어렵다 → **첫 그리기는 ALWAYS** 로 두어 저장값을 확정한 뒤 둘째를 판정한다.
- **판별력 검산**(python `build/r6g/design3.py`·`design4.py`): H1 정상 276 vs 낡은 캐시 132(처음 고른 0.25/0.75 는 **양쪽 다 0 통과라 힘이 없었다** — python 이 잡았다),
  H2 정상 276 vs 첫 그리기가 몰래 썼다면 0, H3 정수 비교 276 vs 내림 전 0, H4 통과 66·경계 2 LSB 안쪽 0 픽셀.
