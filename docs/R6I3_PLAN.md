# R6i-3 — 이중선형 반올림이 축을 따르는가 채널을 따르는가, 그리고 `FILTER_ROUND_MODE` 의 상수 (계획, 코딩 전, codex 교차검토 대상, 2026-09-21)

입력: `docs/R6I2_PLAN.md` 8(이중선형 = 축마다 k/64 절삭 + 두 단계 1 차원 혼합 `(a(64−k)+b·k+r)>>6`, **가로 r = 48·세로 r = 32**;
`PP_CNTL.FILTER_ROUND_MODE` 를 켜면 가로 상수가 ≤ 32 로 바뀐다), `docs/R6I_PLAN.md` 8(표본 = 픽셀 + ½, 텍셀 오프셋 a = −½).

## 0. 한 줄 요약

R6i-2 가 남긴 두 가지를 잰다.  ① "가로 48 / 세로 32" 가 **축**을 따르는지 **채널**(R/G)을 따르는지 —
지금 쓰는 무늬 pat2 는 R 을 u 에, G 를 v 에 묶어 두 해석이 같은 그림을 주므로 **전치 무늬**(R 이 v, G 가 u)를 넣어 가른다.
② `FILTER_ROUND_MODE` 를 켰을 때의 **가로·세로 상수**(R6i-2 의 Q5 는 0·8·16·24·32 를 못 갈랐다 — 그 훑기에 **짝수 탭**이 모자랐기 때문이다).

## 1. 사실

| # | 사실 | 근거 |
|---|---|---|
| W1 | 혼합은 `(a·(64−k) + b·k + r) >> 6`.  a, b 가 0·255 뿐이면 **짝수 탭(a=0, b=255)** 쪽에서만 r 이 바이트를 움직인다 — 홀수 탭은 (255(64−k)+r)>>6 이라 대부분의 r 에서 같은 값이 된다 | python(`build/r6i3/design1.py`, `design2.py`) |
| W2 | R6i-2 의 Q5 는 훑기가 텍셀 경계를 넘어 **짝수 탭 픽셀이 29 개뿐**이었다 → r = 0·8·16·24·32 가 한 그림이 됐다.  한 텍셀 **안에서** 짝수 탭으로만 훑으면 그 다섯이 19–96 픽셀에서 갈린다 | python(`design2.py`, `design3.py`) |
| W3 | 전치 무늬(R ← v, G ← u)를 쓰면 "축을 따른다" 와 "채널을 따른다" 가 **21/120 픽셀**에서 갈린다(각 1 LSB) | python(`design3.py`) |
| W4 | 16×16 삼각형(R6i-2 의 T2p)에서는 설정 기울기 반올림이 없다 — 이 조각도 같은 기하를 쓴다 | `docs/R6I2_PLAN.md` 8 |
| W5 | **`R200_PP_TRI_PERF`(0x2cf8)의 `TRI_CUTOFF`(비트 0–4)** 는 "brilinear"(삼선형을 건너뛰는 지름길) 조절이다.  Mesa 는 `0x1f − 0x1f × texture_blend_quality`(기본 품질 1.0 → **0**)를 넣는다.  우리는 이 레지스터를 **안 쓴다** — 밉 단계가 없으면 삼선형 자체가 없으므로 이번 측정엔 못 들어오지만, **밉 조각에서는 반드시 세워야 한다** | `radeon_drv.h` 88–89 행(DRM 1.16 의 이유), `r200_reg.h` 1067–1068 행, `r200_state_init.c` 652–653 행 |
| W6 | Mesa 의 **T0 hang 우회**는 `CHIP_FAMILY_R200` 에서만, 그리고 **단위 0 만 켜고 MIN 필터가 LINEAR 보다 위(밉)** 일 때 작동한다 — 주석이 "r200 파생품에는 필요 없다" 고 적는다.  우리는 RV280(파생품)이고 MIN = LINEAR 라 해당 없음; **밉 조각에서 이 조건이 정확히 우리 설정**이므로 그때 다시 볼 것 | `r200_texstate.c` 1811–1818 행 |

## 2. 설계

### 2-1. 새 무늬

`pat3` = pat2 의 **전치**: A = 0xff, **R = 255·(v&1)**, **G = 255·(u&1)**, B = 0x55.
pat2 와 텍셀 값 집합이 같아 ZPREP 패턴과 겹치지 않는다(python 으로 확인).

### 2-2. 경우 (번호 131–135; 모두 T2p 기하, 8×8, 선형, 클램프, W = 1)

훑기는 전부 **한 텍셀 안에서 짝수 탭**: x 로 15/16 텍셀, y 로 1/16 텍셀, 시작을 1/512 텍셀 밀어 절반 지점을 지나가게 한다.

| 번호 | 이름 | 무늬 | 훑는 축 | 고정 축 | `PP_CNTL` | 무엇을 가리나 |
|---|---|---|---|---|---|---|
| 131 | N1 | **pat3** | u (텍셀 0) | v = 1 정확(fv = 0) | 기본 | **축인가 채널인가** — G 가 가로 가중치를 나른다 |
| 132 | N2 | **pat3** | v (텍셀 0) | u = 2 정확(fu = 0) | 기본 | 거울: R 이 세로 가중치를 나른다 |
| 133 | N3 | pat2 | u (텍셀 2) | v = 1 정확 | **+0x400** | 비트를 켠 **가로 상수** |
| 134 | N4 | pat2 | v (텍셀 2) | u = 2 정확 | **+0x400** | 비트를 켠 **세로 상수** |
| 135 | N5 | pat2 | u (텍셀 2) | v = 1 정확 | 기본 | **대조**: 같은 훑기를 비트 없이 — 가로 48 을 더 촘촘한 k 로 다시 |

같은 부팅에서 **Q1(126)·Q3(128)** 을 다시 돌린다(R6i-2 의 값이 이 빌드에서도 같은지).

### 2-3. 판정 (`check_r6a.py --procedure r6i3`)

- **H1 (축인가 채널인가)**: N1·N2 의 모든 덮인 픽셀이 **한 읽기**로만 설명돼야 한다 — "상수가 축을 따른다"(가로 48·세로 32) 또는 "채널을 따른다"(R 48·G 32).  둘 다 맞거나 둘 다 틀리면 FAIL(측정).
- **H2 (비트의 상수)**: N3·N4 는 두 단계 공간(`ARULES2`)에서 **한 이름**으로 설명돼야 한다.  N5 는 R6i-2 가 잰 (가로 48·세로 32)와 **워드까지** 같아야 한다.
- **H3 (대조)**: Q1·Q3 가 R6i-2 부팅의 픽셀과 같아야 한다(같은 경우·같은 빌드 계열).
- 안전: R6i-2 와 같다.

## 7. R6i-3 실기 결과 (부팅 05ffa3a5, 빌드 297bca66) — 축을 따른다, 비트는 둘 다 16 으로

절차 전체 rc 0(ZCLEAR 8 회, PLANE 112 회), cycle `verdict=0`, 판정 `--procedure r6i3` **PASS**(`build/r6i3/judge-05ffa3a5.txt`).

- **반올림 상수는 축을 따른다**: 전치 무늬(R←v, G←u)의 N1·N2 에서 **"축을 따른다" 읽기가 120 픽셀 전부**를 맞히고,
  "채널을 따른다" 읽기는 각각 **21 픽셀**을 틀린다.  즉 가로 혼합은 언제나 +48, 세로 혼합은 언제나 +32 이고, 어느 색 채널이든 같다.
- **`FILTER_ROUND_MODE`(PP_CNTL 비트 10)를 켜면 두 상수가 모두 16 이 된다**: N3(가로) r = 16, N4(세로) r = 16.
  비트 없는 같은 훑기 N5 는 48·32 로 120 픽셀 전부 일치 — 같은 부팅 안에서 비트의 효과만 갈라 보였다.
- **대조**: R6i-2 의 Q1·Q3 가 이 빌드에서도 픽셀까지 같다.
- **독립 재계산**(`build/r6i3/indep_r6i3.py`: 자체 파서·덮임·보간·무늬·필터): 다섯 경우 **600 픽셀 0 불일치**.

### 이로써 이중선형 규칙은 완성됐다

```
ST 는 픽셀 + ½ 에서 평가, u = s·폭 − ½
각 축:  k = floor(64 · 소수부)
1 차원 혼합 = (a·(64−k) + b·k + r) >> 6
   기본            r = 48 (가로), 32 (세로)
   FILTER_ROUND_MODE  r = 16 (둘 다)
상수는 축을 따르고 색 채널과 무관하다.  가중치 합은 정확히 1 이라 상수 채널은 보존된다.
```
