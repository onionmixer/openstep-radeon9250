# R7 — 제출 인터페이스와 검증기 (**R7a 실기 PASS 2026-09-21**, R7b 미착수)

R6 사다리(`PLAN.md` R6 5)는 닫혔다.  남은 R6 항목은 **3 항 — 커널 제출·검증기**이고, 그것이
M(Mesa 통합)의 전제다.  이 문서는 그 조각의 계획이다.

## 0. 한 줄 요약

지금 `RDNR5Cp` 는 **경우 번호**만 받는다 — 기하도 상태도 드라이버 안의 표에 있다.  R7 은
**유저 공간이 워드 스트림을 건네고 커널이 전량 검증한 뒤에만 링에 복사하는** 경로를 만든다.
첫 조각(R7a)은 이미 답을 아는 그림(R6d 의 삼각형 T1)을 **유저가 만들어** 제출해, 하드웨어가
아니라 **인터페이스**를 잰다.

## 2. 조각 나누기 — R7a 와 R7b

이 일은 한 조각에 넣기에 크다(문자 디바이스 `ioctl` + 두 번째 mmap 창 + 검증기 + 새 연산).
**둘로 나눈다**, 그리고 **위험한 쪽을 먼저** 잰다.

| 조각 | 무엇을 | 통로 | 왜 이 순서인가 |
|---|---|---|---|
| **R7a** | **검증기**와 "유저가 준 워드로 그린다" | **이미 있는** `RDNR5Cp` 매개변수 경로(낱말 512 씩 append, 그다음 submit) | 규칙이 제일 많고 틀리기 쉬운 부분을, **이미 실기에서 검증된 기구**로 잰다.  새 디바이스 배관이 없다 |
| **R7b** | 문자 디바이스 `ioctl` + 배치 mmap 창 | 3 절의 설계 | 가속 라이브러리가 쓸 통로.  **R7a 에서 이미 통과한 검증기**를 그대로 재사용하므로, 이 조각에서 새로 잴 것은 배관뿐이다 |

R7a 가 `setIntValues` 를 쓰는 것은 **가속 라이브러리가 그걸 쓴다는 뜻이 아니다**(못 쓴다, 3-1).
시험 도구는 Objective-C 라도 되고, R7a 의 목적은 **검증기**다.  그리고 커널은 append 마다
**자기 버퍼로 옮긴다** — 그래서 7 절의 미검증 사항("배열이 사본인가")에 기대지 않는다.

### 2-1. R7a 가 재는 것

**재는 것은 하드웨어가 아니라 인터페이스다.**  그림은 이미 R6d 에서 측정해 규칙까지 이름 붙인
삼각형 T1 이고, 답을 알고 있으므로 **틀리면 인터페이스가 틀린 것**이다.

- **A. 유저가 만든 스트림이 그대로 실행된다**: 도구가 T1 의 상태 블록·클립·`3D_DRAW_IMMD_2`
  를 **자기가 조립해** 보내고, 나온 그림이 R6d 의 규칙과 화소 단위로 같다.
- **B. 검증기가 거절한다**: 허용 밖 레지스터·허용 밖 패킷·길이 불일치·창 밖 표면 주소·
  헤더와 정점 수 불일치 — 각각 **한 번씩 실제로 거절**되고 링에는 한 워드도 안 들어간다.
- **C. 부분 그리기가 없다**: 거절된 제출 뒤 표면이 **독 패턴 그대로**다(검증 전에는 아무것도 안 쓴다).
- **D. 조각난 전달이 하나의 제출이 된다**: 512 낱말(F3)을 넘는 스트림이 여러 번의 append 로
  모여 한 번에 검증·실행된다.

**범위 밖**: Mesa 연결(M), 텍스처 업로드 경로, 여러 클라이언트, TCL, 그리고 **R7b 의 디바이스 배관**.

## 3. 설계 — 제출 경로 (**고쳐 적음**: 내 첫 안은 불가능했다).  3-2 는 **R7b** 의 설계다

### 3-1. 내가 틀린 것

처음 이 문서는 `setIntValues` 를 여러 번 불러 커널 스테이징 버퍼에 이어 붙이는 안(a)을 권고했다.
**그 안은 성립하지 않는다.**  `setIntValues` 는 `IODeviceMaster` 를 거쳐야 하고, 그것은
Objective-C 클래스다 — 그 클래스가 든 아카이브는 **C 프로그램에 링크되지 않는다**.  가속
라이브러리는 `libGL_radeon.a` 이고, 요구는 "응용이 `-lGL` 하나만으로 그대로 빌드된다" 이므로
**라이브러리는 순수 C 여야 한다**.  Matrox 가 같은 자리에서 같은 결론에 도달해 주석으로 남겼고,
나는 그 파일을 열어 확인했다(6-1 판정표 V1).

`setIntValues` 는 **시험 도구**(`rdnr5cp` 같은 Objective-C 도구)에는 계속 쓸 수 있다.  가속
라이브러리에는 못 쓴다.

### 3-2. 고친 설계 — 문자 디바이스 하나에 창 둘

우리는 이미 문자 디바이스를 등록한다(R4c): `open`·`close`·`mmap` 은 있고 `ioctl` 은
`rdnDevNotSupported` 다(`OSRDNDisplay.m` 683-694).  R7 은 **그 디바이스에 `ioctl` 을 붙이고
두 번째 mmap 창을 연다**.

| 창 | 오프셋 | 누가 쓰나 | 왜 |
|---|---|---|---|
| VRAM | `caps[VRAMOFF] + k`(기존 R4c 창) | 클라이언트가 색·깊이·텍스처 표면에 직접 | 이미 있다 |
| **배치** | `R7_BATCH_BASE + k` | 클라이언트가 **자기 워드 스트림**을 쓴다 | 512 낱말 한계(F3)를 안 겪는다 |

**핵심은 "배치만" 이다.**  커널은 검증을 통과한 워드를 **클라이언트가 매핑할 수 없는 자기
메모리**의 명령 목록으로 옮기고, 링에는 그 목록만 간다.  그래서 TOCTOU 가 구조적으로 없다 —
복사로 막는 것이 아니라 **클라이언트가 검증된 것을 만질 수 없게** 해서 막는다.  이 분리는
Matrox 가 주석으로 이유까지 적어 두었고(V2), 우리 F5("유저는 링·GART 를 못 본다")와 같은 말이다.

**타깃 사실 둘, 설계에 그대로 들어간다**:

- **ioctl 매개변수 블록은 128 바이트 미만**이어야 한다 — 이 시스템의 `IOCPARM_MASK` 는 `0x7f`
  다(V3).  그러므로 ioctl 이 나르는 것은 **낱말 스트림이 아니라 작은 서술자**(배치 안의 길이,
  표면 핸들, 결과 코드)뿐이고, 스트림은 매핑된 배치 창에 있다.
- **`mmap` 에 `MAP_FIXED` 도 "주소 골라 줘" 도 없다**: `vm_allocate` 로 먼저 범위를 소유한 뒤
  그 위에 `mmap` 해야 한다(V4).  라이브러리 쪽 헬퍼가 그렇게 해야 한다.

**창의 크기는 링이 정한다**(`build/r7/design3.py`, 전부 python 계산):

| 상수 | 값 | 왜 |
|---|---|---|
| `R7_BATCH_WINDOW_WORDS` | **2048**(8192 B = 한 페이지) | `d_mmap` 은 페이지 단위로만 준다(R4c 실측 `page=8192`) |
| `R7_BATCH_MAX_WORDS` | **2016** | 한 ZCLEAR 은 제출 **둘**(프리픽스 22 → 32, 그리고 클라이언트 워드)이고, `cpR6Submit` 은 안 들어가면 링 끝까지 패딩한다.  **모든 시작 위치**에 대해 둘의 합이 링 4096 안에 들어가는 최대값이 2016 이고, **16 워드만 더 해도 4127 로 넘친다**(경계가 딱 맞는다) |
| `CP_R7_WORDS` | **2048** | 커널의 명령 목록 = 최대 제출 + 프리픽스, 16 의 배수로 |

매핑은 한 페이지지만 **쓸 수 있는 길이는 2016 워드**다 — 그 값은 caps ioctl 이 알려 주므로
클라이언트가 추측하지 않는다.

이 숫자는 **두 번 틀렸다가** 2016 이 됐고, 두 번 다 `build/r7/design3.py` 안에 이유를 남겼다:

1. 처음엔 두 제출의 최악을 **각각** 더해 2016 을 얻었다 — 실제로 못 일어나는 조합이라 너무
   보수적이었다(프리픽스가 포인터를 옮긴 뒤에 둘째가 시작한다).  찾기와 검사를 **같은 모형**으로
   바꿔 2032 가 됐다.
2. 그런데 그 2032 는 **드라이버의 꼬리 10 워드를 빼먹은 값**이었다(codex Q3).  꼬리
   (`PURGE_DC`·`PURGE_ZC`·`WAIT_UNTIL`·`RB3D_CNTL`·`SCRATCH_REG0+8`)는 클라이언트 워드와
   **같은 제출**에 들어간다(`osrdn_cp.m` 2317-2321, 열어 확인).  2032 짜리 스트림은 꼬리까지
   2042 → 2048 이 되어 불리한 위치에서 4127 워드를 먹는다 — "항상 들어감" 이 깨진다.
   꼬리를 넣고 다시 풀어 **2016**, 그리고 16 워드만 더해도 4127 로 넘치는 것까지 확인했다.

**결과 전달**: ioctl 의 반환값이 아니라 **블록 안의 `status`** 로 준다 — 4.3BSD ioctl 은 반환이
0 일 때만 블록을 되돌려 주므로, 거절 사유를 반환값에 실으면 사유가 사라진다(V5).

### 3-3. 소유와 임대 (F12)

R7a 는 **협조적 단일 클라이언트**로 간다(V 단계의 operator 결정과 같은 선).  다만 Matrox 가
"이 인터페이스로는 못 고친다" 로 끝낸 자리(두 프로세스가 한 배치 버퍼와 한 표면을 중재 없이
공유)를 **처음부터 피할 수 있는 만큼은 피한다**: 배치 창은 `open` 한 서술자마다가 아니라
**드라이버에 하나**이므로, `open` 이 **이미 열려 있으면 거절**하는 단순한 걸쇠를 둔다.
Matrox 의 경험상 `close` 가 클라이언트마다 오지 않는 것이 걸쇠의 위험이므로(V6), R7a 의 걸쇠는
**계수여서는 안 된다**.

V6 을 원문에서 읽고 나니 함의가 내 첫 추측과 반대다.  무서운 쪽("죽은 클라이언트가 영영 안
놓는다")은 **측정으로 반증됐다** — `close` 는 SIGKILL 에도 온다.  깨지는 것은 **세는 것**이다:
`close` 가 *마지막 참조*에서만 오므로 `opens − closes` 는 점유 수가 아니다.

그러면 **불리언 걸쇠는 오히려 옳다**: `close` 가 "아무도 안 들고 있다" 는 바로 그 순간에 오므로,
첫 `open` 에 `busy = 1`, `close` 에 `busy = 0` 은 점유를 정확히 표현한다.  대가는 **같은 프로세스의
두 번째 `open` 도 거절**된다는 것인데, 우리 라이브러리는 한 번만 연다.

이 추론이 맞는지, 그리고 불리언으로도 못 막는 시나리오가 있는지를 codex 에 묻는다(Q1').

## 4. 검증기 규칙 (**Q3 뒤 전면 개정**)

제출 전체를 훑어 **전부 통과해야** 링에 복사한다.  하나라도 걸리면 아무것도 안 쓴다.
**초안에는 구멍이 여섯 개 있었다** — 둘은 내가, 넷은 codex Q3 가 찾았고 전부 원문에서 확인했다(7 절).

1. **소비가 정확하다**: 헤더부터 끝까지 걸어 정확히 끝에서 끝난다.
2. **패킷 종류**: 클라이언트는 **타입 0 과 타입 3 만** 보낼 수 있다.
   **타입 1 은 헤더에 레지스터를 둘 싣는다**(`REG0_MASK 0x7ff`, `REG1_MASK 0x3ff800`)
   — 파서가 기본 거절하지 않으면 **패킷 0 허용 목록을 통째로 우회한다**.  타입 2(패딩)도 거절한다.
3. **패킷 0**: **개수 칸 == 1**(칸은 *값 개수 − 1*) **이고 `ONE_REG_WR`(0x8000) 이 0**,
   그 다음 레지스터 하나가 **측정된 41 개 허용 목록** 안.
   개수 칸이 크면 한 헤더가 `reg`, `reg+4`, … 를 연달아 쓰므로, 허용된 `0x1c2c` 에서 시작해
   목록 밖 `0x1c30`·`0x1c34` 로 **걸어 나갈 수 있다**.
4. **값 마스크** — 주소 허용 목록만으로는 안전한 **상태 집합**이 되지 않는다:
   - `PP_CNTL`(0x1c38): `TEX_1..5_ENABLE`(0x20–0x200) 를 켜면 샘플러가
     **우리가 검사하지 않는** `PP_TXOFFSET_1..5` 의 **잔존값**을 쓴다.  유닛 0 만 허용한다.
   - `SE_VAP_CNTL`(0x2080): TCL 을 켜면 **측정한 적 없는 실행 경로**로 들어간다.  TCL 은 꺼야 한다.
   - `PP_TXFORMAT`·`PP_TXFILTER`: mip 단계·cube·volume 을 켜면 샘플러가 **검사한 면적 뒤를 계속 읽는다**.
5. **패킷 3**: `3D_DRAW_IMMD_2` 하나만.  그리고
   - **첫 데이터 워드 `VF_CNTL` 도 검사한다**: `PRIM_WALK_RING` 이어야 하고(INDEX/LIST 면 뒤 워드를
     정점이 아닌 것으로 해석한다), primitive 는 허용 목록, 정점 수는 범위 안.
   - **헤더 count == `정점워드수(FMT_0, FMT_1)` × 정점 수**.
6. **정점 형식은 추적하고, 첫 그리기 전에 정해져 있어야 한다**: `정점워드수` 는 스트림을 걸으며
   **최신** `SE_VTX_FMT_0/1` 로 계산한다.  **형식 자체도 허용 목록**이다 — 측정해 본 칸
   (`Z0`·`W0`·`COLOR_0 = PK_RGBA`·`TEX0_COMP_CNT ∈ {0,2}`)만 허용하고, 법선·가중치·`FP_RGB(A)` 처럼
   **워드 폭을 우리가 측정한 적 없는** 칸은 거절한다.
7. **표면은 발자국으로 검사한다, 폭×높이가 아니라**:
   `offset + 피치바이트 × 높이 ≤ 창 끝`.  `COLORPITCH`·`DEPTHPITCH` 는 클라이언트가 쓸 수 있으므로,
   창 안의 오프셋 + 작은 폭·높이 + **큰 피치**면 첫 행만 창 안이고 **다음 행부터 창 밖 VRAM 을 덮는다**.
   텍스처도 같다: 베이스 하나로는 모자라고 피치·cpp·mip 수를 함께 제한하거나 발자국을 계산해야 한다.
8. **크기**: 클라이언트 스트림 ≤ **2016 워드**(`R7_BATCH_MAX_WORDS`).
9. **append 한 번의 적재량**: `setIntValues` 의 **512 는 배열 전체**의 한도다 — `{magic, op, 토큰,
   길이}` 같은 머리말이 같은 배열에 들어가므로 **실제 CP 적재량은 512 보다 작다**(508).

## 6. 선례 조사 결과의 재검증 (Matrox)

Matrox 선례 조사는 **모델 출력**이므로 codex 와 같은 규칙을 적용했다 — **쓰기로 한 것은 전부
그 파일을 열어 확인**했고, 확인 못 한 것은 채택하지 않았다.

| # | 주장 | 내 검증 방법 | 결과 |
|---|---|---|---|
| V1 | 가속 라이브러리는 순수 C 여야 하고, 그래서 `IODeviceMaster`(따라서 `setIntValues`)를 못 쓴다 | `mesa/OpenStepMGAMesaProbe.h` 3-9 를 열었다 — "the parameter form of this query needs IODeviceMaster, and an archive containing that class cannot be linked into a C program" | ✅ **채택 — 내 3-1 안을 폐기** |

## 7. codex 교차검토 판정

### Q1 — `setIntValues` 의 `parameterArray` 는 커널 사본인가

| codex 주장 | 내 검증 방법 | 결과 |
|---|---|---|

| NeXT 공식 예제가 `parameterArray` 를 `copyin` 없이 바로 읽는다 | `AMD_SCSI.m` 430-440 을 열었다 — `parameterArray[0]` 을 그대로 읽는다 | ✅ 사실.  다만 이것은 "커널 주소로 보인다" 까지만 말하고 "사본이다" 를 증명하진 않는다 |
| (MIG 정의와 생성 스텁을 근거로) `parameterArray` 는 **사본**이다 | **채택하지 않고, 내용도 여기 옮기지 않는다.**  근거가 전부 **참고 금지 나무** 안에 있다(2026-09-16 사용자 지시: 어떤 목적으로도 참고 금지).  codex 스스로도 "`ref/openstep/` 에서는 못 찾음" 이라고 적었다.  금지된 출처는 **기각할 때도 인용하지 않는다** — 인용하는 순간 그 내용이 우리 문서에 들어온다 | ⚠️ **미검증으로 남긴다** |

**결론**: "사본이라 스냅샷이 공짜" 는 **그럴듯하지만 허용된 나무에서 증명되지 않았다**.  그리고
V1 때문에 가속 라이브러리는 어차피 이 통로를 못 쓰므로 **이 조각의 설계는 이 답에 기대지 않는다**.
시험 도구가 이 통로를 쓸 때도, 스냅샷을 가정하지 않고 **커널이 자기 버퍼로 옮긴 뒤 검증**한다.

### Q2 — 우리 허용 목록 안에 주소를 나르는데 검사 안 하는 레지스터가 있나

codex 의 답은 **"없음"** 한 마디였다.  **부재 주장은 모델의 말로 받지 않는다** — 직접 계산했다
(`build/r7/design2.py`, 결과를 여기 옮긴다):

| codex 주장 | 내 검증 방법 | 결과 |
|---|---|---|
| 없음 | DRM 에서 **전이적으로** 유도했다: `radeon_drm.h` 의 `*_EMIT_*` 번호 → `radeon_state.c` 의 `packet[]`(그 번호로 색인) → `radeon_check_and_fixup_packets` 가 **패킷의 몇 번째 낱말**을 주소로 고치는지(`&data[(ADDR - FIRST)/4]` 형태라 주소 레지스터가 정확히 복원된다).  DRM 이 주소로 다루는 레지스터는 **54 개**, 그중 우리 41 개 안에 드는 것은 **정확히 3 개**(`0x1c24`·`0x1c40`·`0x2d00`)이고 그 셋이 우리가 범위 검사하는 셋이다.  나머지 51 개는 허용 목록 밖이라 애초에 거절된다 | ✅ **사실.  다만 근거는 내 계산이지 codex 의 답이 아니다** |

첫 계산은 패킷의 **전체 구간**을 비교해 거짓 양성 둘(`PP_MISC`·`PP_CNTL`)을 냈다 — 그 패킷들은
우리 레지스터를 걸치지만 **주소로 다루는 낱말**은 우리가 이미 검사하는 것이었다.  `design2.py`
가 낱말 단위로 보는 이유이고, 그 실패를 주석으로 남겼다.

### Q1' — 겹친 `open` 을 막는 걸쇠 (R7b)

| codex 주장 | 내 검증 방법 | 결과 |
|---|---|---|
| 계수기가 아니라 **이진 `FREE/HELD`** 가 맞고, **거절할 때 상태를 바꾸지 않아야** 한다 | 내 3-3 추론과 같다.  "거절된 open 은 짝이 되는 close 가 없으므로 세지 않는다" 는 `REMAINING_WORK.md` 675-676 에 이미 적혀 있다(열어 확인) | ✅ 채택 |
| `d_ioctl` 에는 **어느 fd 에서 왔는지 알려 주는 것이 없고**, `d_close` 에도 토큰이 안 온다 → **토큰을 fd 에 묶을 수 없다** | 세 콜백의 실제 원형을 열었다: `osmgaDevOpen(int dev, int flag, int devtype)`·`osmgaDevClose(같음)`·`osmgaDevIoctl(int dev, int cmd, caddr_t data, int flag)`.  `cdevsw` 는 원형 없는 `int (*)()`(`conf.h` 60-68), `IOSwitchFunc` 도 같다(`devsw.h` 16) | ✅ 채택 — **내 "소유 토큰" 안을 폐기한다** |
| `u.u_procp` 는 있지만 인자로 안 온다; fork/dup 때문에 마지막 close 를 한 프로세스가 첫 opener 가 아닐 수 있다 | 원형에 없다는 것은 위에서 확인.  `u_procp` 자체는 안 열어 봤고, **쓰지 않을 것이므로** 판정에 영향이 없다 | ⏭️ 안 쓴다 |
| `REMAINING_WORK.md` 738 의 "8 허용 / 28 거절" 은 **모든 겹친 open 이 성공한 로그**에 대고 돌린 반사실 계산이므로, 실제로 둘째 open 을 거절하면 그 사슬이 안 생긴다 | 738 근처를 열었다.  **사실관계는 맞다** — 거절되는 쪽이 "겹친 클라이언트가 아니라 **앞사람이 죽었는데 close 가 아직 안 온 정당한 다음 클라이언트**" 라고 원문이 그렇게 적고 있다.  **다만 "거절하면 사슬이 안 생긴다" 는 측정이 아니라 추론이다** | ⚖️ 부분채택 — 아래처럼 **틀려도 치명적이지 않게** 설계한다 |

**codex 가 잡아 준 진짜 빈틈**: `close` 가 이미 만든 **매핑을 없애지 않는다** — Matrox 가
주석으로 "an exclusive fd is not an exclusive mapping ... closing does not remove a mapping
already made" 라고 적어 두었다(`OpenStepMGAReplacementDisplay.m` 3009-3012, 열어 확인).
그러므로 **fd 걸쇠는 매핑을 회수하지 못한다**.

**그래서 R7b 의 통제점은 매핑이 아니라 제출이다.**  배치 창을 계속 들고 있는 클라이언트가
자기 페이지에 무엇을 쓰든, 그것이 하드웨어에 닿는 유일한 길은 `submit` ioctl 이고, 거기서
걸쇠와 검증기를 다시 통과해야 한다.  커널은 검증 통과분을 **클라이언트가 매핑할 수 없는**
명령 목록으로 옮기므로(3-2), 낡은 매핑은 **자기 페이지만 더럽힌다**.  이렇게 두면 위의
"사슬이 안 생긴다" 추론이 **틀려도** 최악은 "정당한 후임이 한동안 거절당함"이지
"남의 그림이 섞임" 이 아니다.

### 9-2. U4 — 호스트 컴파일러와 타깃 컴파일러가 갈렸다

U4 의 첫 워드는 `0xc0012800`(타입 3, opcode 0x2800)이다.  `P0_REG` 는 **그 워드를 PACKET0 으로
읽었을 때** 나오는 답이다((`0xc0012800 & 0x3fff`) × 4 = `0xa000`, 허용 목록 밖).  같은 소스가
`gcc-12 -m32` 위에서는 `P3_OP` 를 낸다 — 시뮬레이터의 171 경우 baseline 이 그것을 통과했다.
**타입 1 과 2 는 맞게 걸렸으므로** 상수 비교 자체가 안 되는 것은 아니고, 타입 3 만 어긋났다.

**추측으로 닫지 않았다.**  어느 워드에서 거절했는지가 로그에 없어 "첫 워드를 잘못 읽었다" 와
"패킷을 건너뛰고 다음 워드에서 걸렸다" 를 가를 수 없다 — `게이트는 읽힌 값을 남겨야` 가
정확히 이 상황을 말한다.  그래서 2 차 빌드(`4398697d`)에서:

1. **거절도 로그에 남는다**: 거절은 `c->zcase` 가 설정되기 **전에** 일어나 줄이 안 나왔다.
   이제 R7 경우는 검증 전에 `zcase` 를 세운다.
2. **문제의 워드 자체를 기록한다**(`word=%08x`) — 엉뚱한 워드에서 발화한 규칙은 옳은 워드에서
   발화한 규칙과 로그상 구별되지 않는다.
3. **타입 분기를 두 비트 값으로** 바꿨다: `t = hdr >> 30; if (t == 1UL || t == 2UL)`.
   32 비트 상수 셋과 비교하던 것을 0..3 짜리 수 하나로 줄여 컴파일러가 접을 여지를 없앴다.
4. 재발 방지: **소스 규칙**(`t = hdr >> 30;` 이어야 하고 `hdr & 0xc0000000` 은 금지),
   오라클 자기검사에 **네 타입 각각** 항목, 시뮬레이터에 "엉뚱한 비트에서 읽기" 변이.

호스트 검사로는 이 차이를 볼 수 없다(컴파일러가 다르다).  그래서 검사는 *결과*가 아니라
**견고한 형태**를 고정한다.

### 10-1. 무엇이 이미 정해져 있나

3 절과 6·7 절에서 검증을 마친 것들이 그대로 전제다:

- 클라이언트는 **배치만** 매핑하고, 커널의 명령 목록은 매핑할 수 없다(V2).
- ioctl 매개변수 블록은 **128 바이트 미만**(V3) — 워드는 블록으로 안 나른다.
- `mmap` 에 `MAP_FIXED` 가 없다: `vm_allocate` 먼저(V4).
- 결과는 반환값이 아니라 블록 안 `status` 로(V5).
- 겹친 `open` 은 **이진 걸쇠**로 막는다.  계수는 안 된다 — `close` 가 마지막 참조에서 한 번만
  오므로 `opens − closes` 는 점유 수가 아니다(V6, Q1').
- `close` 는 이미 만든 **매핑을 없애지 못한다**.  그래서 통제점은 매핑이 아니라 **제출**이다(Q1').

### 10-2. 창 배치 (`build/r7/design5.py`, 전부 python 계산)

| | 값 | 왜 |
|---|---|---|
| VRAM 창 | `0x0029e000 .. 0x07c00000` | R4c 가 이미 연 것, 카드 오프셋이 곧 mmap 오프셋 |
| **배치 창** | `0x40000000 .. 0x40002000` | 한 페이지.  VRAM 천장보다 **900 MiB 위**라 어떤 카드 주소와도 겹칠 수 없다 |
| 한 페이지면 되나 | 2016 워드 = 8064 B ≤ 8192 B | 최대 제출이 한 페이지에 들어간다(128 B 여유) |
| ioctl 서술자 | 8 워드 = 32 B < 128 B | `{magic, version, op, nwords, status, why, at, word}` — **워드는 안 실린다** |

**핵심은 배치 페이지와 스냅샷이 서로 다른 할당이라는 것**이다.  커널은 제출 때 페이지를
`cpR7Buf` 로 **복사한 뒤** 판정한다.  클라이언트는 자기 페이지를 얼마든지 다시 쓸 수 있지만,
실행되는 것은 **손댈 수 없는 사본**이다 — R7a 의 검증기가 그대로 쓰인다.

### 10-4. 재는 것과 게이트

- **A**: `CAPS` 가 창·한도·빌드를 알려 주고, 그 값으로 `mmap` 한 페이지에 U1 을 써서 `SUBMIT`
  하면 **T1 이 그려진다** — R7a 와 같은 그림, 다른 통로.
- **B**: 거절 스트림이 `status` 로 **R7a 와 같은 사유**를 돌려준다(통로가 판정을 안 바꾼다).
- **C**: **겹친 `open` 이 거절**되고, 거절된 open 뒤에도 원래 클라이언트가 계속 제출할 수 있다.
- **D**: `SUBMIT` 뒤 클라이언트가 페이지를 덮어써도 **이미 그려진 것은 안 바뀐다**(스냅샷).
- **E**: ioctl 이 아닌 경로(`read`/`write`)는 여전히 거절된다.

### 10-6. 배치 페이지 할당 (`build/r7/design6.py`, PASS)

`d_mmap` 은 **페이지 하나에 pfn 하나**를 준다(R4c 실측 `page=8192 shift=13`).  pfn 은 범위가 아니라
시프트이므로 그 8192 바이트는 **8192 정렬된 물리 연속 구간 하나**여야 한다.  헤더는 힙 할당에 대해
그걸 약속하지 않으므로 **잰다** — `cpBlock` 이 CP 블록에 대해 이미 하는 그대로.

| 결정 | 값 | 왜 |
|---|---|---|
| CP 블록에서 떼어 쓰지 않는다 | 별도 할당 | CP 블록은 GART 로 **카드에 보인다**; 경계가 한 번 미끄러지면 클라이언트가 링을 쓴다 |
| 할당자 | `IOMallocLow` | DMA 가 필요해서가 아니라 **물리적으로 연속인 유일한 할당자**라서(`OpenStepMGAReplacementDisplay.m:235-242`) |
| 요청 크기 | **12288 B**(8192 + 4096) | 물리 base 가 4 KiB 정렬이기만 하면 8192 정렬 구간을 **반드시** 찾을 수 있는 최소값 — design6 이 가능한 물리 base 를 전수로 확인 |
| 아레나 점유 | 65536 + 12288 = 77824 B = 640 KiB 의 **11.9 %** | 여유 있음 |

init 에서 통과해야 하는 것(하나라도 실패하면 `IOFreeLow`·장치 없음·로그 한 줄, 디스플레이 무영향):

- **C1** `IOMallocLow(12288)` ≠ 0
- **C2** 4096 B 마다 `IOPhysicalFromVirtual` 성공
- **C3** 그 주소들이 연속(`phys[i] == phys[0] + i*4096`)
- **C4** `(phys[0]+o) % 8192 == 0` 이고 `o + 8192 <= 12288` 인 `o` 가 있다
- **C5** `phys[0] + 12288 <= 0xa0000`

`d_mmap` 은 저장된 `o` 물리값에 `rel` 을 더하기만 한다(사실 A).

**설계에서 바뀐 것 둘**(구현 중 검사기가 잡았다):

1. 배치 가지의 `rel` 페이지 시작 검사는 **중복이라 지웠다**.  `BALIGN` 이 `bphys` 를 페이지 정렬로
   증명하므로 `rel % page == 0` 은 `phys % page == 0` 과 같은 말이고, 그 검사는 이미 있다.
   억지 경우를 만들어 살려두는 대신 지우는 쪽이 정직하다.
2. "페이지 전체로 경계를 묻는다"는 규칙은 **크기가 페이지의 배수면 오프셋으로 묻는 것과 같다**.
   그래서 검사기에 **페이지 배수가 아닌** raw 창(3 페이지 + 4096 B)을 넣었다 — 선례가 실제로 밟은
   모양이 바로 그거다.  그 창에서만 변이가 잡힌다.

### 10-10. 1 차 실기 (부팅 `ffdb0fa0`, build `8bc226a7`, 2026-09-22)

**통로 자체는 처음부터 동작했다.**  통과한 것:

| | 실측 |
|---|---|
| 배치 페이지 | `RDN-R7B page … va=00050000 phys=00050000 len=00003000 skip=00000000 ok` — **CP 블록 바로 뒤**(0x40000–0x50000), 8 KiB 정렬, 통상 메모리의 **11.9 %** |
| `skip=0` | 이 부팅의 `IOMallocLow` 는 12288 요청에 **이미 정렬된** 주소를 줬다.  여유 4 KiB 는 안 쓰였지만, 그게 항상이라는 증거는 아니므로 탐색은 남긴다 |
| 배치 창 | `batch=0`(수용), `bphys=00050000` |
| `d_mmap` 자체검사 | `self=15900/0` — R4c/R7a 의 **15893 보다 정확히 +7**, 배치 블록이 더하는 수와 같다(python 대조) |
| **게이트 C** | 쥐고 있는 동안의 두 번째 `open` → `second-open=-1 errno=6`(ENXIO) |
| **게이트 E** | 모르는 명령 `cmd=40205209 rc=-1 errno=25`(ENOTTY), `nwords=0` → `status=22`, `nwords=2017` → `status=22` |
| CAPS·mmap·채우기 | `magic=52374230 ver=1 win=40000000 bytes=8192 max=2016 ready=1 winstart=0029e000`, `step=fill` 도달 — **순수 C 로 창을 매핑하고 쓰는 데까지 성공** |

**그리고 결함 둘이 나왔다 — 둘 다 내 것이다.**

1. **씨앗으로 0 을 넘겼다.**  `zclear n=13 len=171 rc=1 why=13` = `CP_WHY_SEED`("zero, or the last seed").
   씨앗은 마커 무늬의 출처이고, 반복되면 **낡은 되읽기가 새것 행세를 한다** — 그래서 커널이 0 과
   직전 값을 거절한다.  R7a 는 도구의 run id 를 씨앗으로 넘겼다.  **고침**: `seed` 를 제출 블록의
   입력 항목으로 넣고, 클라이언트가 자기 run id 를 넣는다(0 이면 검증기 앞에서 거절).
2. **내 로그 줄이 CP 연산 줄의 모양을 입었다.**  `RDN-R7B … boot=%08x n=%u` 는 러너가
   `grep "boot=$N n="` 로 **연산을 고르는** 바로 그 모양이라, 제출 줄이 연산으로 세어지고 그
   `rc=` 로 판정됐다.  **고침**: 세 줄 다 `words=` 로.  그리고 **규칙으로 박았다**(`r7b-line-shape`):
   연산 줄은 `osrdn_modelog.m` 의 것이고, 드라이버 본체에 그 모양이 있으면 실패한다 — 예외
   두 줄(`RDN-R2B enter`·`revert`, `check_select.py` 가 파싱하고 CP 시퀀스 안에 나타날 수 없다)은
   **이름으로** 적었고, 그 줄이 사라지면 규칙이 목록을 고치라고 말한다.

**같이 고친 것**: `caps.ready` 가 "CP 가 돈다"를 뜻한다고 주석이 말했지만 **확인하지 않았다** —
`cpRunning` 을 따로 두고 `ready` 의 뜻을 실제 동작에 맞췄다.  그리고 걸쇠 자체에 규칙이 없어
지워도 아무도 모르는 상태였다 → `r7b-latch`(변이 3 개로 발동 증명).

**러너도 고쳤다**: 전문(`record rec3d load map reset start rec3d`)과 후문(`rec3d stop record`)을
**스크립트가 직접** 돌린다.  `check_plan_ops.py` 는 그 둘을 포함해 대조하는데 러너만 빠져 있었다 —
R6m 에서 부팅을 태운 것과 같은 모양의 구멍이었고, 이번엔 `case 6` 이 `CP_WHY_STATE` 로 멈춰
바로 드러났다(아무것도 소비되지 않았다).
