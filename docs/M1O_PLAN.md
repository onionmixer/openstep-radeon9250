# M1o — 남은 1.1 ms 도 되읽기였다 (계획, 재부팅이 드는 칸)

기준일 2026-09-23.  선행: M1n 완료(`docs/M1N_PLAN.md` 11).

## 1. A1 의 답 — 읽기와 산술이 같은 곳을 가리킨다

M1n 이 남긴 것: 제출 1,474 us 중 **판정 뒤 1,314 us(89 %)**, 그중 표본 digest 212 us,
**설명 안 되는 1,102 us**.

`cpZclear` 의 판정 뒤 경로를 순서대로 읽었더니 되읽기 루프가 더 있었다:

| 루프 | 읽기 | 가드 | R7 에서 도나 |
|---|---|---|---|
| 커버리지 맵 | `CP_R6_COV_WORDS` = **64** | `if (drawn)` | **돈다** |
| 그리기 뒤 스캔 | **1024** | `if (drawn)` | **돈다** |
| 평면/깊이 | 4×1024 / 1024 | `cs->lanes` · `cs->dsrc` | 안 돈다 |
| 텍스처 | 256 | `cs->tidx` | 안 돈다 |

`drawn` 은 R7 에서 참이다(`osrdn_cp.m:3112`).  그래서 **1,088 회**가 더 돈다.

산술(python)로 맞춰 보면:

    digest 256 + 커버리지 64 + 스캔 1024 = 1,344 회 x 830 ns = 1,116 us
    실측 설명 안 되는 몫                                      = 1,102 us   (+1.2 %)

**읽은 가드와 산술이 같은 조합을 가리킨다.**  다른 조합도 같은 개수를 내지만, 그것들은
가드가 거짓이라 돌지 않는다 — 두 줄기가 독립적으로 같은 답을 준다.

그리고 그 자리 주석은 이렇게 적혀 있다: *"1024 회지 위의 128 K 워드 스캔이 아니다;
비용은 여기 있던 적이 없다."*  **M1m 이 큰 것을 치운 지금은 틀렸다** — 이것이
제출의 **58 %** 다.

## 2. digest 처럼 건너뛸 수는 없다

`sim_r6.py:540-546` 가 **UC(클라이언트) 케이스의 커버리지 맵을 T1 과 대조**한다.
그것이 "클라이언트가 보낸 워드가 T1 의 그림을 그린다" 는 R7a/R7b 의 증거다.
`check_r7b.py` 는 `cov` 를 안 쓰지만(grep 0 건), 시뮬레이터는 쓴다.

**그러므로 경우로 가르면 안 되고, 목적으로 갈라야 한다.**

## 3. 이 칸의 한 줄

**`quiet` 을 "이 실행은 측정이다" 로 넓힌다** — 제출 로그와 **그리기 뒤 분석**을 함께 끈다.

M1n 이 만든 것을 그대로 쓴다: 같은 op, 같은 임대, 같은 기본값(켜짐).  `quiet` 이
이미 뜻하는 것이 "이 실행에는 증거를 만들지 말라" 이고, 로그와 되읽기 분석은 **같은
목적의 두 가지**다.  플래그를 둘로 나누면 둘이 어긋날 수 있다.

| | 바꾸는 것 |
|---|---|
| 1 | `cpZclear` 의 `if (drawn)` 커버리지 블록을 `if (drawn && !c->quiet)` 로 |
| 2 | 그게 전부다.  `covValid` 가 0 이면 `osrdn_cp_lines` 가 cov 줄을 안 찍는다(이미 그렇다) |

**표본 digest 는 끄지 않는다.**  212 us 이고, codex 가 짚은 **펜스** 역할이 있다 —
uncached 읽기가 사실상 배리어일 수 있다는 것을 우리는 반증한 적이 없다.

## 4. 기대와 그 한계

기대: 1,088 회 × 830 ns ≈ **900 us** 가 빠져 제출 고정비가 1,474 → **약 580 us**.
**예측이지 결과가 아니다** — M1m 에서 배운 대로 잰 뒤에 말한다.

**그리고 이것으로도 소프트웨어를 못 이긴다.**  한계비가 카드 1.90 us/삼각형 대
소프트웨어 1.28 us(네 실행, 열두 팔)라 **손익분기가 아예 없다**.  이 칸은 고정비를
정리하는 칸이지 이기는 칸이 아니다.  그 사실을 여기 적어 둔다.

## 6. codex 교차검토 (코딩 전)

| codex 주장 | 내 검증 | 판정 |
|---|---|---|
| **플래그는 둘이어야 한다.  "커버리지 켜고 로그 끄기" 가 실제 조합이다** | **우리 드라이버에서는 불가능하다.**  `RDN-R6 cov*` 는 `osrdn_cp_lines` 안(`osrdn_modelog.m:384`)이고, 클라이언트 경로는 `quiet` 일 때 그 함수를 **통째로 건너뛴다**(`OSRDNDisplay.m:1358`).  커버리지 맵의 유일한 출구가 이미 막힌 로그다 | ❌ **기각** — codex 가 몰랐던 사실 |
| "둘이 어긋날 수 있다" 는 합리화다 | 위의 사실 때문에 이 경우엔 아니다.  다만 지적 자체는 옳은 종류의 의심이다 | ⚖️ |
| **digest 256 회를 "펜스일지 모르니" 남기는 것은 비정합이다** — 펜스라면 한 번이면 되고, 주소마다 중요하면 256 은 나머지 1,088 을 증명 못 한다 | **맞다.**  그리고 digest 줄(`zd`/`zc`)도 `osrdn_cp_lines` 안이라(`osrdn_modelog.m:416-417`) **quiet 에서 똑같이 버려진다** | ✅ **채택** — 설계를 바꾼다(아래) |
| 시간 잰 묶음의 **앞뒤를 검사된 실행으로 감싸라** | 러너가 이미 그렇게 한다: `t-accel`(로그·커버리지 켬)이 앞, `t-accel2` 가 뒤.  그리고 M1d 의 일곱 모드가 화소를 따로 대조한다 | ✅ 이미 있음 — 문서에 명시 |
| 절감이 `1088 x 830 ns` 보다 작을 수 있다(읽기가 파이프라인·버스트될 수 있고, 첫 읽기가 완료 대기를 품고 있을 수 있다) | 반증할 수단이 없다.  **예측하지 말고 잰다** | ✅ 채택 |

### 그래서 §3 을 고친다

`quiet` 일 때 **커버리지 스캔(1,088)과 표본 digest(256)를 둘 다 건너뛰고**, 대신
**읽기 두 번만 남긴다** — 색 버퍼에서 하나, 깊이 버퍼에서 하나.

    이유: "완료된 uncached 읽기가 앞선 GPU 쓰기를 밀어낸다" 는 성질이 있다면 한 번으로
    족하고, 없다면 256 번도 소용없다(codex).  버퍼마다 한 번씩이면 두 성질을 다 만족하는
    가장 작은 모양이고, 값은 ~2 us 다.  명시적 `DC_FLUSH_ALL` + `W_DC` 대기는 그대로 있다
    (`osrdn_cp.m:3512-3514`) — 그것이 문서화된 펜스이고, 이 두 읽기는 덤이다.

바뀌는 것은 `cpZclear` 안의 두 자리와 `covValid`/`digestWords` 의 보고뿐이다.
**R6 케이스는 한 글자도 안 바뀐다**(그 실행들은 `quiet` 을 켜지 않는다).

## 7. 코딩 중에 더 큰 것을 봤다 — **카드의 래스터는 이미 소프트웨어보다 빠르다**

A2(훅이 워드를 두 번 쓰는 것)를 보려다, **이미 가진 데이터로 한계비를 분해**할 수
있다는 걸 알았다.  `poison` 팔이 열쇠다: 워드를 창에 다 쓰고, 커널이 워드 0 에서
거절하고, 그래서 **훅이 소프트웨어로 그린다**.  그러면

    창에 쓰기          = poison − software = 2.31 − 1.28 = **1.03 us/삼각형**
                       = 15 워드에 69 ns/워드
    커널 검증+링+카드  = accel − 창에 쓰기 = 1.91 − 1.03 = **0.88 us/삼각형**
    소프트웨어 래스터                                    = **1.28 us/삼각형**

**카드가 그리는 일(0.88)은 소프트웨어(1.28)보다 이미 1.45 배 싸다.**  카드가 지는
이유는 그리기가 아니라 **명령 워드를 uncached 창에 써 넣는 비용**이다.

내부 정합성: 읽기 830 ns 대 쓰기 69 ns = **12 배**.  posted write 와 round-trip read
의 차이가 딱 그만큼이어야 하고, 그래서 이 분해는 두 상수가 서로를 받쳐 준다.

### 그래서 손익분기는 어디에 있나 (python)

창 쓰기를 없앴다고 가정하면(카드 한계비 0.88):

    고정비      손익분기 n
     1474 us        3681
      580 us        1446
      300 us         746
      100 us         246
       50 us         121   <- 배치 상한 131 안
       20 us          46   <- 여유 있게 안

**지금 상태(한계비 1.91)로는 어떤 n 에서도 못 이긴다.**  이기려면 **둘 다** 필요하다:
창 쓰기를 거의 없애고(쓰기 결합 매핑, 또는 r200 처럼 캐시 메모리에서 DMA), 고정비를
50 us 근처까지 내릴 것.  둘 다 큰 칸이다.

**A2 는 값이 작다**: 두 번 쓰는 것 중 하나는 캐시 메모리이고, 비싼 쪽은 **창에 쓰는
uncached 쪽**이라 어차피 남는다.  없애도 1.03 us 는 그대로다.

## 8. 이번엔 **전수로** 셌다 — M1o 가 마지막 되읽기 칸이다

M1m·M1n·M1o 가 전부 "되읽기 루프를 **하나 더** 찾아 끈다" 는 같은 모양이었다.
M1m 뒤에 한 번에 셌어야 했다.  그래서 지금 셌다: `osrdn_cp.m` 전체에서
**uncached alias 를 만지는 함수는 셋뿐**(`cpZclear` 19, `cpR6Digest` 1, `cpZprep` 1)이고,
`cpZclear` 의 alias 루프는 **아홉 개가 전부**다.

| 루프 | 가드 | 클라이언트에서 | 읽기 |
|---|---|---|---|
| 텍스처 프리필·검증 (×2) | `cs->tidx != 0` | R7 은 tidx 0 | 0 |
| digest 2 패스 × 2 버퍼 | **M1o: `!c->quiet`** | quiet → 건너뜀 | 0 |
| 커버리지 초기화 64 | **M1o: `drawn && !quiet`** | quiet → 건너뜀 | 0 |
| 커버리지 스캔 1024 | **M1o: `drawn && !quiet`** | quiet → 건너뜀 | 0 |
| 깊이 평면 1024 (×2, 배타) | `cs->lanes` · `cs->dsrc` | R7 은 lanes 0 | 0 |
| **M1o 의 qTouch** | `c->quiet` | **일부러 남김** | **2** |

    제출당 uncached 읽기:  83,008  →  1,344  →  2
                          (M1h 전)   (M1m 후)  (M1o 후)

`tidx`·`lanes` 가 R7 에서 0 이라는 것은 표를 파싱해서가 아니라 **측정이 증명한다**:
그 루프들까지 돌았다면 1,344 가 아니라 3,000 회가 넘었을 테고, 1,344 × 830 ns 가
실측과 +1.2 % 로 맞았다.

**그러므로 이 방향으로는 더 깎을 것이 없다.**  다음 값은 되읽기가 아니라 **쓰기**에
있다(§7).
