## 0. 한 줄 요약

사다리의 텍스처 칸 **첫 조각**이다.  8×8 ARGB8888 텍스처를 CPU 가 VRAM(별칭 안)에 써 넣고, 최근접 표본·원근 없음(W=1)으로 삼각형 하나를 그려
**어느 텍셀이 어느 픽셀에 오는지**를 색 버퍼 전수로 읽는다.  이번에 정하는 것은 (1) 텍스처 배치와 피치, (2) ST → 텍셀 규칙(배율·오프셋·반올림), (3) 클램프와 랩,
(4) 읽어온 텍셀 값이 그대로 픽셀이 되는지.  이중선형·밉맵·원근(W≠1)·여러 단위는 다음 조각이다.

## 2. 설계

### 2-1. 텍스처 (새 것)

- **어디에**: 별칭 0x20000 부터 1 KiB(경우 XE 는 줄 간격 64 바이트라 512 바이트를 쓴다), 8×8 ARGB8888, 기본 줄 간격 32 바이트(폭 그대로).  CPU 가 텍셀을 쓰고 **되읽어 확인**(프리필과 같은 방식, `pfbad` 재사용).
- **무엇을**: 텍셀(u, v) = `0xff000000 | (u·32) << 16 | (v·32) << 8 | 0x55` — 서로 다르고 알파가 0xff 라 패턴(0xa5…)과 절대 같아지지 않는다(python 으로 확인).
- **검사 제외**: `restChanged` 루프가 텍스처 영역(0x20000 부터 1 KiB)을 건너뛴다 — 경우가 텍스처를 쓸 때만.
- **상태**(선례 X2·X3 그대로): `PP_CNTL = TEX_BLEND_0_ENABLE|TEX_0_ENABLE`, `PP_TXFILTER_0`(최근접 + 경우별 클램프), `PP_TXFORMAT_0`(ARGB8888 + **ALPHA_IN_MAP** + 폭·높이 log2),
  `PP_TXFORMAT_X_0 = 0`, `PP_TXSIZE_0 = (w−1)|((h−1)<<16)`, `PP_TXPITCH_0 = 피치−32`, `PP_TXOFFSET_0 = 창 + 0x20000`, 혼합 단계 0 은 R0 통과,
  `SE_VTX_FMT_0 = Z0|W0|PK_RGBA`, `SE_VTX_FMT_1 = 2`(ST 두 성분).  정점은 x, y, z, w, 색, s, t.

### 2-2. 경우 (번호 102–108; F 는 회귀)

기하는 T1z(4,4)(28,4)(4,28), z 상수 0.5, 깊이 ALWAYS·쓰기 켬, 색은 텍셀이 결정한다.  ST 는 정점마다 준다(보간은 색·깊이와 같은 설정 경로).

| 번호 | 이름 | 텍스처 | 클램프 | ST(세 정점) | 무엇을 가리나 |
|---|---|---|---|---|---|
| 102 | XA | 8×8, 피치 32 | CLAMP_LAST | (0,0) (1,0) (0,1) 을 삼각형에 맞춰 | 기본 대응: 텍셀 하나가 픽셀 4×4 |
| 103 | XB | 8×8 | CLAMP_LAST | XA + 반 텍셀(1/16) | **오프셋 규칙**: floor(s·w) 인가 floor(s·w − ½) 인가 |
| 104 | XC | 8×8 | WRAP | XA 의 두 배(0..2) | 랩과 배율 |
| 105 | XD | 8×8 | CLAMP_LAST | −0.25..1.25 | 양 끝 클램프 |
| 106 | XE | 8×8 이되 **줄 간격 64 바이트**로 저장, `PP_TXPITCH` = 32 | CLAMP_LAST | XA 와 같음 | **기록**: POT 에서 피치 레지스터를 보는가(X9).  보면 XA 와 같은 그림, 안 보면 줄이 섞인 그림 — 둘 다 python 으로 예측해 이름을 붙인다 |
| 107 | XF | **4×4**, 피치 32 | CLAMP_LAST | XA 와 같음 | 크기 필드(log2)와 배율 |
| 108 | XG | 8×8 | WRAP | s 만 0..1, t 상수 **17/32**(t·8 = 4.25) | t 고정에서 한 줄만 읽히는지(축 분리).  0.5 로 두면 t·8 이 정확히 경계라 못 쓴다(python 이 잡았다) |

- python 검산(`build/r6h/design2.py`, 위험 = 텍셀 좌표가 경계에서 2⁻¹⁰ 텍셀 안): 모든 규칙에서 안전한 픽셀은 XA·XB·XC 120, XD·XF 276, XG 184;
  후보 규칙 여섯(오프셋 0·±½ × 클램프/랩) 중 **어느 두 규칙도 최소 212 개의 안전한 픽셀에서 다른 텍셀을 고른다** → 한 부팅으로 이름이 갈린다.
- 읽기: 색 평면 네 레인(16 PLANE) + 덮임 지도.  ZCLEAR 8 회(F 포함), PLANE 112 회.

### 2-3. 판정 (`check_r6a.py --procedure r6h`)

- 안전: R6g 와 같음(표지·전제·걸쇠·덮임 = R6d 규칙) + 텍스처 되읽기 `pfbad = 0` + 두 버퍼와 텍스처 밖 불변.
- **게이트**: 위험 픽셀을 뺀 모든 덮인 픽셀에서 색 = 이름 붙인 규칙이 고른 텍셀의 값.  규칙 공간은
  `u = C(floor(s·w + a))`, a ∈ {0, −½, +½}, C ∈ {clamp_last, wrap, mirror}, s 는 보간된 값(정확 보간; 위험 픽셀 제외) — 여덟 경우 전부를 설명하는 이름이 **하나**여야 한다.
- 없으면 FAIL(측정): 경우별 최근접 규칙과 어긋난 픽셀 수·위치를 적는다.
- 텍셀 값이 그대로 픽셀이 되는지(바이트 순서)도 함께 이름 붙인다(R6c 처럼 "선형/Mesa 순서" 대 그 밖).

### 2-4. 안전

- 쓰는 곳은 색 버퍼(32×32)와 깊이(32×32)뿐이고, 텍스처 영역은 **CPU 만** 쓴다(GPU 는 읽기만).  전부 별칭 256 KiB 안.
- 새 레지스터 여섯 개(텍스처 상태)는 전부 링으로, 선례 값 그대로.  `PP_TXOFFSET` 은 드라이버가 창 시작 + 0x20000 으로 계산하고 게이트가 창 안인지 검사한다.
- 첫 텍스처 경우(102)에서 `pfbad ≠ 0` 이거나 예상 밖이면 그리기를 멈추고 정리만.

### 2-5. 호스트 검사

- `tex_oracle.py`(새 파일): 텍셀 표·경우·기대 지도·규칙 공간·C 행 생성 + 자체검사(텍셀이 패턴과 겹치지 않음, 경우마다 위험 픽셀 수, 규칙 공간이 경우들을 가름).
- `world5.c`: 가짜 3D 에 텍스처 표본(최근접·클램프·랩·피치·크기)을 넣고, `sim_r6.py` 에 R6h 스트림·평면·변이(피치 −32 안 함, 오프셋 틀림, 클램프 비트 자리, ST 순서 뒤바뀜, 텍셀 주소 u/v 뒤바뀜 …).
- `check_r6a.py` r6h 자체검사: 합성 부팅(규칙 두 가지) + 부정 시험(한 픽셀, 축 뒤바뀜, 클램프 대신 랩).
- `check_r5_src.py`: 새 필드·행·텍스처 표를 오라클과 대조.

## 4. 교차검토에 물을 것 (한 호출 한 주장)

1. 텍스처를 우리 별칭(0x20000)에 두고 CPU 로 채우는 것이 R200 에서 합법인가 — 참고가 텍스처에 요구하는 정렬·타일·캐시(예: `PP_TXOFFSET` 의 타일 비트, 텍스처 캐시 무효화)가 더 있는가.
2. 정점 차례가 x, y, z, w, 색, s, t 가 맞는가(X4·X5) — 반례가 있는가.
3. POT 8×8 에서 `PP_TXSIZE`·`PP_TXPITCH` 를 함께 쓰는 것이 맞는가, 아니면 POT 에서는 무시되는가(헤더 주석은 "NPOT only").
4. 이 설계가 놓치는 것 — 최근접·W=1 로만 재서 뒤 조각(이중선형·원근)에서 다시 재야 할 것이 무엇인가.

**다음 조각으로 미룬 것(각각의 최소 경우)**: 원근 = 같은 화면 좌표에 W 1·2·4 를 주고 한 픽셀에서 아핀과 원근이 다른 텍셀을 고르게;
이중선형 = 2×2 텍스처의 네 값과 1/4 텍셀 안쪽 표본 + 클램프 가장자리를 걸치는 자국; 밉 = 0·1 단계를 다른 색으로 두고 경계 양쪽 픽셀;
여러 단위 = 2×2 둘을 묶어 단위 1 단독과 0×1 결합.
