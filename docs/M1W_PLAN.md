# M1w — 카드를 기다리지 않는다 (드라이버, 재부팅 필요)

**설치까지 하고 재부팅을 요청한다.**  드라이버 변경이므로 순서는 메모리의
`driver-change-review-order` 그대로: 검토·수정 → 호스트 검사 → 빌드 → **설치 전 `nm -u`** →
설치 → 재부팅 요청.

## 1. 재기 전에 읽은 것 — 한 제출이 실제로 하는 일

`cpZclear` 의 클라이언트 경로(`zc == CP_R7_CASE`)를 끝까지 읽었다.  한 번의 `SUBMIT` 은
**링 쓰기 한 번이 아니다**:

| 순서 | 무엇 | 대기·MMIO |
|---|---|---|
| 게이트 | `cpIdleGate`(FIFO 가득·RBBM 비활성), `RPTR == wptr`(**따라잡음**), poison 카나리아, `SURFACE_CNTL` | MMIO 읽기 4 |
| 전초 | `cpWait(W_FIFO,2)` → 스크래치 둘 쓰기 → `cpWait(W_IDLE)` → 둘 되읽기 | 대기 2, 읽기 2 |
| **1 단계** | 프리픽스(레지스터 11~13 개) → `cpR6Submit` | 링 + 도어벨 + **`cpWait(W_RPTR)` + `cpWait(W_IDLE)`** |
| 1 단계 검증 | `SCRATCH_REG0` + `CP_R6_PRE_COUNT` 개 레지스터 되읽기 | 읽기 여러 개 |
| **2 단계** | **클라이언트 워드 + 우리 꼬리** → `cpR6Submit` | 링 + 도어벨 + **대기 둘** |
| 2 단계 검증 | 픽스캐시 플러시(읽기+쓰기+`cpWait(W_DC)`), 스크래치 되읽기 | 대기 1, 읽기 2 |
| 3 단계 | 분석 — M1o 가 quiet 일 때 2 읽기로 줄여 둔 것 | 읽기 2 |

**링 제출이 제출당 둘이고, 동기 대기가 넷이며, 그 사이에 R6 시절의 되읽기 검증이 있다.**
이것이 M1q 가 잰 **고정 8.6 us + 워드당 46 ns** 의 정체다.

## 2. 무엇을 고칠 것인가 — 고정비가 아니라 **한계비**

두 갈래가 있고 값이 다르다:

| 고칠 것 | 줄어드는 것 | 크기 |
|---|---|---|
| 1·2 단계를 한 번으로 합치고 R6 되읽기를 클라이언트 경로에서 뺀다 | **고정** 8.6 us 의 일부 | 제출당, n 으로 나뉜다 |
| **마지막 대기를 미룬다** | **워드당 46 ns × 15 = 0.69 us/삼각형** | **한계비의 34 %** |

M1q~M1v 가 쫓아온 것은 한계비다.  그러니 이 칸은 **두 번째**를 한다.  첫 번째는 별도 칸.

### 2-1. 왜 미루면 없어지나

지금은 `cpR6Submit` 이 도어벨을 울린 뒤 **카드가 링을 다 읽고 엔진이 idle 이 될 때까지**
커널이 돈다.  그동안 CPU 는 아무것도 안 한다.  미루면 그 시간에 라이브러리가 다음 배치를
조립한다 — M1s 가 잰 유저랜드 1.29 us/삼각형이 그 자리를 채운다.  카드의 0.69 us 는
**사라지는 게 아니라 가려진다**, 그리고 1.29 > 0.69 이므로 완전히 가려진다.

## 3. 무엇이 그 대기에 걸려 있나 (전수)

미루면 깨지는 것을 **코드에서** 셌다:

| 걸려 있는 것 | 어디 | 미룬 뒤 어떻게 |
|---|---|---|
| 다음 제출의 `RPTR == wptr` | `osrdn_cp.m:3203` | **"링에 자리가 있나" 로 바꾼다.**  같은 뜻의 약한 조건이고, 자리가 없으면 그때 기다린다 |
| 다음 제출의 `cpIdleGate` 의 `RBBM_ACTIVE` | `cpIdleGate` | 카드가 그리는 중이면 당연히 ACTIVE 다.  **클라이언트 경로에서만** 이 검사를 자리 검사로 대체 |
| 2 단계 뒤의 되읽기(`zreg2`, 픽스캐시) | `osrdn_cp.m:3511-3515` | 되읽기는 **엔진이 멈춘 뒤**라야 뜻이 있다.  미룬 경로에서는 **하지 않는다**(quiet 일 때 아무도 안 읽는 값이다) |
| 3 단계의 두 읽기 | M1o | 같음 — 미룬 경로에서는 건너뛴다 |
| 걸쇠(hang) 탐지 | `cpWait` 의 타임아웃 → `cpLatch` | **다음 제출의 자리 대기가 그 자리를 맡는다.**  타임아웃하면 그때 걸쇠 |
| poison 카나리아·`SURFACE_CNTL` | 게이트 | 그대로 둔다.  MMIO 읽기 둘이고 엔진 상태와 무관 |

## 4. 설계 — 손잡이 하나, 기본 꺼짐

드라이버에 `CP_R7_FLAG_NOWAIT`(제출 블록의 여유 필드 한 비트).  **클라이언트가 켜야만**
동작하고, 켜지지 않으면 오늘과 **바이트 단위로 같은 경로**가 돈다.

    켜졌을 때만:
      - 2 단계 뒤의 cpWait(W_RPTR)·cpWait(W_IDLE) 를 건너뛴다
      - 그 뒤의 되읽기(zreg2, 픽스캐시 플러시, 3 단계 읽기)를 건너뛴다
      - 다음 제출의 게이트는 "RPTR == wptr" 대신 "자리 len+pad 워드"

기본이 꺼짐이므로 **설치해도 지금 동작은 안 바뀐다** — 재부팅 뒤 회귀 위험이 0 이고,
게이트 실행(M1d..M1k)은 손잡이를 안 켜므로 그대로 판정된다.

## 5. 위험 — 이것은 커널이고, 크래시는 디스크를 건다

| 위험 | 막는 법 |
|---|---|
| 링을 앞질러 써서 카드가 안 읽은 워드를 덮어씀 | **자리 검사가 그것을 막는다** — §5-1 의 계산이 그 검사가 실제로 일할 여지가 있음을 보인다 |
| 카드가 멈췄는데 기다리지 않아 영원히 모른다 | 다음 제출의 자리 대기가 `C_RPTR_US` 로 타임아웃하고 `cpLatch` 한다.  **걸쇠는 종결적**([[failure-latch-must-be-terminal]]) |
| 되읽기를 건너뛰어 잘못된 그림을 못 잡음 | 손잡이가 **꺼진** 게이트 실행이 그림을 판정한다.  켠 실행은 **시간만** 재고, 그림은 켠 채로도 한 번 대조한다(마지막 제출 뒤에 한 번 기다린 다음) |
| 마지막 제출이 영원히 안 기다려져 프로세스가 끝난 뒤 카드가 그림 | `d_close` 나 다음 ZPREP 에서 한 번 기다린다 — **어디서 기다리는지 코드에서 세어 문서에 남긴다** |
| 커널 크래시 | 이 칸은 **레지스터 프로그래밍을 하나도 바꾸지 않는다**.  바뀌는 것은 "언제 기다리나" 와 "무엇을 되읽나" 뿐 |

### 5-1. 링에 몇 개가 떠 있을 수 있나 — python 으로 계산

링은 `CP_RING_WORDS` = **4,096 워드**(`osrdn_cp.h:51`).  한 제출은 두 단계이고 각 단계가
16 워드 배수로 패딩되며 링 끝을 넘지 않으려고 최대 15 워드를 더 버린다.  2 단계의 워드
수는 실측대로 `15n + 2 + 46`(프리픽스 46 워드가 클라이언트 스트림 앞에 붙는다).

| n | 2 단계 워드 | 제출당 링 워드(최악) | 비우기 전에 들어가는 제출 |
|---:|---:|---:|---:|
| 1 | 63 | 110 | 37 |
| 18 | 318 | 366 | 11 |
| 36 | 588 | 638 | 6 |
| 60 | 948 | 1,006 | 4 |
| 66 | 1,038 | 1,086 | 3 |
| **72** | **1,128** | **1,182** | **3** |
| 131(배치 상한) | 2,058 | 2,110 | **1** |

**우리가 재는 n=72 에서 세 개가 들어가므로 둘이 떠 있을 수 있다** — 겹치기가 성립한다.
배치 상한(`CP_R7_BATCH_MAX` = 2,016 워드 = 삼각형 131 개)에서는 하나뿐이라 겹침이 없고,
그때는 자리 검사가 그냥 기다린다 — **오늘과 같은 동작으로 곱게 퇴화한다.**

## 6. 읽는 법

| 관측 | 판정 |
|---|---|
| 손잡이 꺼진 팔의 그림·워드가 오늘과 다름 | **실패** — 기본 경로가 바뀌었다 |
| 손잡이 켠 팔의 그림이 꺼진 팔과 다름 | **실패** |
| 한계비가 0.4 us 이상 내려감 | 카드 대기가 가려졌다.  다음은 고정비 쪽(1·2 단계 합치기) |
| 0.1 us 미만 | 대기가 이미 CPU 와 겹쳐 있었거나, 다른 것이 직렬화하고 있다.  커널의 `RDN-R5 wait` 줄이 그 자리에서 답한다 |

## 7. codex 교차검토 판정표 — **이 칸은 보류한다**

45 건 넘게 받았고, **하나가 계획을 무너뜨렸다.**

| codex 주장 | 내 검증 | 판정 |
|---|---|---|
| **다음 제출의 전초에 `cpWait(IDLE)` 이 있으면 거기서 이전 단계를 기다리므로 겹침이 사실상 0 이다** | 열었다.  `osrdn_cp.m:3217-3222` — **모든 제출의 전초**에 `cpWait(W_FIFO,2)` → 스크래치 둘 쓰기 → **`cpWait(W_IDLE)`** → 되읽기 둘이 있다.  §1 표에 내가 직접 적어 놓고 §3 에서 "대기에 걸려 있는 것" 을 셀 때 **꼬리만 세고 머리를 빼먹었다** | ✅ **채택 — 계획이 틀렸다.**  꼬리만 미루면 얻는 것이 0 이다 |
| `RPTR == WPTR` 이 빈 링과 꽉 찬 링에서 같다 | 사실이다.  자리 계산은 한 워드를 비워 두거나 채움 수를 따로 세야 한다.  §5-1 의 계산은 **용량**만 보았고 이 모호성을 다루지 않았다 | ✅ **채택 — 계산이 불완전했다** |
| 픽스캐시 플러시가 진단용인지 coherency 필수인지 갈라야 한다 | 코드 주석은 "radeon_do_pixcache_flush, as radeon_do_cp_idle's wait does" 다 — 참고에서는 **idle 로 가는 길의 일부**이지 그리기마다 하는 일이 아니다.  다만 우리 시험은 **매핑된 창으로 화소를 되읽는다** | ⚖️ **부분채택 — 미해결로 남긴다.**  가르지 않은 채로는 건너뛰지 않는다 |
| 성공을 반환한 ioctl 의 실패를 나중 걸쇠로 소급 전달할 수 없다 | 맞다.  비동기 제출의 본질이고, 측정용 손잡이라도 **성공의 의미가 바뀐다** | ✅ 채택 |
| 마지막 제출의 hang 은 다음 제출이 없으면 영원히 미검출 | 맞다.  `d_close`·ZPREP 에 기다림을 넣어야 하고, 그 자리를 코드에서 세지 않았다 | ✅ 채택 |
| 플래그가 클라이언트 블록의 비트면 구형 클라이언트의 쓰레기 패딩이 켤 수 있다 | 블록에 `magic`·`version` 검사가 있지만 **예약 비트 검사는 없다**.  넣어야 한다 | ✅ 채택 |
| 링 쓰기 → 캐시 동기 → 배리어 → 도어벨 순서 | 지금 코드에 `cpFence(base)` 가 도어벨 앞에 있다.  대기를 빼면 **그 순서가 더 중요해진다** | ⚖️ 기록 |
| CP 가 RPTR 만 전진시키고 엔진이 멈춘 경우 자리 대기가 계속 성공한다 | `RPTR` 와 `IDLE` 은 동치가 아니다 — 맞는 지적이고, 자리 검사만으로는 엔진 hang 을 못 본다 | ✅ 채택 |

### 7-1. 그래서 이 칸은 **보류**다

겹침을 얻으려면 꼬리의 대기만이 아니라 **전초의 idle 대기와 그에 딸린 센티넬 검증까지**
들어내야 한다.  그것은 한 손잡이가 아니라 클라이언트 경로 전체를 다른 계약 위에 올리는
일이고, codex 가 센 실패 모드(링 덮어쓰기·늦은 걸쇠·성공 후 실패·자원 수명)가 전부
실재한다.  **커널이고, 크래시는 루트 fsck 를 부른다.**

## 8. 그리고 산수가 다음 작업을 바꾼다 — 고정비가 78 %다

이미 측정된 팔들로 고정비를 갈랐다(run 790113565, python):

| 몫 | us/제출 | 어떻게 |
|---|---:|---|
| 라이브러리만, ioctl 없음 | 2.0 | `t-nullsend` 의 절편 |
| **+ ioctl 진입·커널 게이트·워드 0 거절** | **162.5** | `t-poison` − `t-nullsend` |
| **+ 나머지 커널 연산**(링 2 단계, 대기 4, 되읽기) | **365.8** | `t-quiet` − `t-poison` |
| = 제출당 | **530.3** | |

    n=72 에서: 고정 530 + 한계 149 = 679 us,  **고정비가 78.1 %**
    삼각형당: 고정 7.36 + 한계 2.07 = 9.43 us   (소프트웨어 1.29)

**M1q~M1v 다섯 칸이 쫓은 것은 21 % 쪽이었다.**  큰 덩어리는 고정비에 있다.
다음 칸(M1x)은 **커널 연산 366 us** 를 겨눈다 — 그리고 그것은 대기를 미루지 않고도,
불변식을 하나도 바꾸지 않고도 줄일 수 있다.
