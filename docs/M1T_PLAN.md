# M1t — 훅의 0.788 us 는 호출인가

재부팅 없음.  훅과 테스트·판정기만.

## 1. 남은 것

M1s 가 한계비 2.00 us 의 모형을 닫았고, 가장 큰 항이 **훅 자체 0.788 us(39 %)** 다.
그 안에서 이미 배제된 것:

| | us/삼각형 | 근거 |
|---|---:|---|
| 산술 전부(`fdiv` 3, 비트 캐스트 12, 색 워드 3) | 0.050 | M1r, `tools/mesa/fpcost.c` 실측 |
| 위임(`osrdnSlotOf` 4 슬롯 루프 + 간접 호출 하나) | ~0.03 | `OSRDNMesaHook.c:1101-1107` |
| **남는 것** | **~0.71** | |

## 2. 가설 — 호출과 인자

삼각형 하나가 훅을 지나며 부르는 것을 **소스에서 센** 결과:

| 호출 | 횟수/삼각형 | 오브젝트를 넘나드나 | 인자 |
|---|---:|---|---:|
| `osrdn_surf_bound_to` | 1 | 예 | 1 |
| `osrdn_surf_shifts` | 1 | 예 | 4 |
| **`osrdn_tri_vertex`** | **3** | **예** | **10** |
| `osrdnColourWord` | 3 | 아니오(`static`) | 5 |
| `osrdnWantWord` | 3 | 아니오 | 5 |
| `osrdnBits` | 12 | 아니오 | 1 |
| 합 | **23** | 그중 5 개가 오브젝트 밖 | 인자 밀기 약 40 회 |

`osrdn_tri_vertex` 하나가 **인자 열 개**를 스택에 밀고, 삼각형마다 세 번 불린다.
`static` 인 넷은 `cc 2.7.2.1 -O` 가 인라인할 수도 아닐 수도 있다 — **그것도 재는 대상**이다.

**하지만 이것은 가설이다.**  M1p 는 50 배, M1r 은 1.7 배 빗나갔고 둘 다 "소스에서 세고
마이크로벤치 속도를 곱한" 것이었다.  그러니 세어서 맞히지 않는다 — **없애고 잰다.**

## 3. 이 칸이 하는 일 — 호출 **하나만** 없앤다

손잡이 하나, `RDNMesaInline=1`.  훅이 정점마다 부르던 `osrdn_tri_vertex` 세 번을 없애고
**같은 배열 `vtx[]` 의 같은 자리에 같은 워드를 직접 쓴다.**

**예약/커밋 두 단계 API 는 쓰지 않는다.**  첫 초안은 `reserve` 로 배치 창 포인터를 먼저
받아 거기에 바로 쓰려 했다 — 그러면 **조립보다 먼저 거절이 일어나도록 순서가 바뀌고**,
예약만 하고 커밋 안 한 상태·wrap·부분 예약 같은 **새 실패 경로**가 생긴다(교차검토
#8·#9·#30, 채택).  이 칸의 가설은 "호출과 인자" 이고, 그것을 시험하는 데 순서를 바꿀
필요가 없다.  바뀌는 것은 **그 워드가 어떤 호출을 거쳐 `vtx[]` 에 도달하는가** 뿐이다.

### 3-1. 배치는 **한 곳에만** 적는다

`osrdn_tri_vertex` 의 헤더 주석이 이미 이 사고를 기록하고 있다 — 다섯 워드짜리 쓰기가
일곱 워드짜리 블록 안에 들어가 "카드가 색 자리에서 28.0 을 받았다".  그러니 자리 계산과
슬롯 순서를 **헤더의 매크로 하나**로 옮기고, unit 의 `osrdn_tri_vertex` 와 훅의 직접
경로가 **둘 다 그것을 쓴다.**  두 벌을 적으면 같은 사고가 다시 난다.

### 3-2. 손잡이는 삼각형당 **한 번** 읽는다

정점 루프 안에서 읽으면 없앤 호출 자리에 새 호출이 들어선다(교차검토 #15, 채택).
루프 위에서 지역 변수로 한 번 읽는다.  그리고 **런타임 손잡이 하나짜리 바이너리**다 —
`#ifdef` 로 두 바이너리를 만들면 코드 배치·정렬 차이가 측정에 섞인다(교차검토 #19).

## 4. 값이 안 바뀐다는 것을, 어떻게 **증명**하나

교차검토가 가장 크게 짚은 곳이다(#21·#24): 호스트 워드 대조는 **tri 단위까지만** 덮고,
화소가 같다고 스트림이 같은 것도 아니다.  그래서 실기에서 **훅의 출력 자체**를 본다.

1. **훅의 출력, 비트 단위 (실기)** — 테스트는 이미 보낸 삼각형의 **모든 워드**를 찍는다
   (`osrdn-mesa-tri.c:353-358` 의 `tri k w0 w1 ...`).  정답 장면을 손잡이 **끄고 한 번,
   켜고 한 번** 돌려 그 줄들을 대조한다.  **한 워드라도 다르면 실패.**
2. **그림, 바이트 단위 (실기)** — 같은 두 실행의 28,672 화소를 대조한다.
3. **계수기** — `submitted`·`batched`·`refused[]` 합이 같아야 한다.  (이것만으로는
   내용·순서를 증명하지 못한다 — 교차검토 #27 이 맞다.  그래서 1 번이 있다.)
4. **호스트** — `sim_batch` 의 워드 대조는 그대로 돌지만, 훅을 안 덮는다는 **한계를 적어
   둔다**(교차검토 #21).

### 4-1. 값이 안 바뀐다는 것의 **구조적** 근거

- `osrdn_tri_vertex` 의 원형은 **전부 `unsigned long`** 이다(`OSRDNMesaTri.h:195-198`).
  **부동소수가 호출 경계를 건너지 않는다** — `osrdnBits` 가 먼저 비트로 바꾸고, 그
  나눗셈은 두 경로 모두 **같은 자리**에 있다.  그래서 x87 반올림 지점도, 기본 인자 승격도
  옮겨갈 데가 없다(교차검토 #1·#2·#3, 기각).
- 인자 식은 전부 순수하다(`osrdnBits` 는 공용체 캐스트, `col` 은 루프 앞에서 이미 계산).
  평가 순서가 고정돼도 결과가 안 바뀐다(교차검토 #4, 기각).
- `osrdn_tri_vertex` 의 유일한 부수효과는 **인자 검사**(`vtx==0 || i<0 || i>=3` 이면
  아무것도 안 쓰고 돌아간다)다.  이 호출 자리에서 `vtx` 는 지역 배열이고 `i` 는
  `for (i = 0; i < 3; i++)` 의 귀납 변수라 **구조적으로 참**이다(교차검토 #6, 기각 —
  다만 매크로에 검사를 넣지 않는 이유로 여기 적어 둔다).

## 5. 읽는 법

| 관측 | 판정 |
|---|---|
| 화소가 한 바이트라도 다르다 | **실패** — 값이 바뀌었다.  시간을 읽지 않는다 |
| 기울기가 0.3 us 이상 내려간다 | 훅의 값은 **호출과 인자**였다.  다음은 나머지 호출(`surf_shifts`·`bound_to`·색 워드)을 같은 방식으로 |
| 0.1 us 미만 | 호출은 아니다.  그러면 남은 것은 `VB->Win.data`·`ColorPtr` **포인터 추적과 캐시**이고, 다음 칸은 정점 데이터를 한 번에 읽는 쪽 |
| 그 사이 | 부분.  **없앤 것은 23 개 중 3 개**이므로(교차검토 #11·#12) 나머지를 같은 방식으로 하나씩 없애 본다 — 비례로 환산하지 않는다 |

**두 팔에서 잰다.**  `t-quiet`(카드가 그린다)만 보면, CPU 가 빨라진 만큼 카드 대기가
늘어 기울기가 안 움직일 수 있다(교차검토 #13).  그래서 **`t-nullsend` 에서도** 잰다 —
그 팔은 카드가 아예 없으므로 **순수 CPU 절감**이 그대로 보인다.

## 6. 위험

| 위험 | 막는 법 |
|---|---|
| 배치가 두 곳에 적혀 어긋남 | 자리 계산과 슬롯 순서를 **헤더의 매크로 하나**에 두고 unit 과 훅이 둘 다 쓴다.  `check_hook` 의 `m1g-hook-does-not-pack` 이 "손으로 번호 슬롯을 쓰면" 실패하도록 정밀화했고, 그 변이가 잡히는 것을 확인했다 |
| 인자 식을 두 벌 적어 **변이가 한 벌만 고침** | 실제로 일어났다 — 첫 판에서 `check_hook` 의 "z 를 Mesa 단위로 보낸다" 변이가 한 copy 만 고쳐 규칙이 다른 copy 를 보고 통과했다.  워드를 **지역 변수에 한 번** 계산하고 두 팔은 호출 여부만 다르게 고쳤다 |
| 매크로가 `q` 를 일곱 번 펼쳐 주소 산술을 일곱 번 함 | 주소를 **지역 변수**에 먼저 담는다.  안 그러면 없앤 호출 자리에 숨은 일이 들어선다 |
| 손잡이를 정점마다 읽어 호출이 되돌아옴 | 삼각형당 한 번, 루프 위에서 |
| 훅은 호스트 C89 게이트가 안 덮는다 | 타깃 빌드가 유일한 컴파일 검사 — **빌드를 먼저** 하고 그 다음에 잰다 |
| 값이 같다는 것을 화소로만 확인 | §4 의 1 번(보낸 **워드** 대조)이 주 증인이다.  판정기가 한 워드라도 다르면 **값을 안 내놓고 실패**하며, 그 규칙이 발동하는 것을 자체검사로 보였다 |
| 카드가 병목이라 CPU 절감이 대기로 바뀜 | `t-nullsend`/`t-nullinl` 쌍에서도 잰다 — 그 팔엔 카드가 없다 |

## 8. 실기 결과 (run 790102773, 부팅 `0710c8bb`, 빌드 `1790102758`, **재부팅 0 회**)

### 8-1. 값은 안 바뀌었다 — 워드로 증명

    t-quiet vs t-inline: 기록된 여덟 삼각형이 **워드 하나까지 같다**
    (둘 다 n=91086, kept=8, words=15; `diff` 로도 0 줄)

### 8-2. **가설은 반증됐다 — 세 번째다**

카드가 없는 쌍(순수 CPU):

    t-nullsend  b = 2.188 us/삼각형      t-nullinl  b = 2.199
    → 정점 쓰기를 인라인해서 **+0.011 us/삼각형**.  저-군집 4~7 에서 +0.010~+0.015 로 안정.

**삼각형당 오브젝트 밖 호출 셋과 인자 서른 번 밀기를 없앴는데 아무 일도 안 일어났다.**

| 칸 | 추정 | 실측 | 비 |
|---|---:|---:|---:|
| M1p 캐시 금지 창에 쓰기 | +593 us/블록 | −7 us | 0.01 배 |
| M1r 링 21 워드 | 0.21 us | 0.123 us | 0.59 배 |
| **M1t 호출 3 개 + 인자 30 개** | **크다** | **0.011 us** | **≈ 0** |

**`cc 2.7.2.1 -O` 의 호출은 싸다.**  이 기계에서 비싼 것은 호출이 아니다.

### 8-3. 그러면 훅의 0.88 us 는 **메모리**다

배제된 것을 다 빼면:

    산술 0.050 · 위임 0.03 · 호출 0.011  →  합쳐 0.09 us, 훅 값의 **10 %**

남는 90 % 는 삼각형마다 하는 **읽기**다 — `VB->Win.data[idx[i]][0..2]`(정점마다 다른
캐시 줄), `VB->ColorPtr->data[...]`, 서로 다른 줄에 흩어진 `ctx` 필드 넷.  다음 칸은
그것을 **덜 읽는** 쪽이고, 또 세어서 맞히지 않는다.

### 8-4. 러너의 결함 하나 — 그리고 판정기가 그것을 잡게 했다

카드가 있는 쌍은 **읽을 수 없었다**: `t-inline` 의 고정비가 1,616 us(t-quiet 은 529)이고
기울기가 **음수**로 나왔다.  원인은 `quiet N` 이 **가진 것이 아니라 쓰는 것**이라는 데
있다 — 한 팔이 2,160 제출이고 `quiet 5000` 하나로 세 팔을 덮으려 했으니 **세 번째 팔
중간에 리스가 떨어져** 드라이버가 다시 25 줄씩 찍었다.

- 러너: 조용해야 하는 팔은 **저마다 리스를 다시 건다**.
- 판정기: **고정비가 다르면 값을 안 내놓고 실패한다.**  손잡이는 삼각형당 일만 건드리므로
  두 팔의 고정비는 같아야 하고, 다르면 손잡이 밖의 무언가가 움직인 것이다.  비율만 쓰면
  0 근처의 두 수(카드 없는 쌍의 1.1 과 −0.2)가 늘 "비교 불가" 가 되므로 **절대 하한
  20 us** 를 함께 둔다.  둘 다 자체검사로 발동을 보였다.

## 9. 리스를 고친 재실행 (run 790103041, 같은 부팅·같은 빌드) — `judge_m1l: PASS`
