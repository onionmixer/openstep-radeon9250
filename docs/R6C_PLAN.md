# R6c — 첫 색 쓰기: 정점 색 사각형 (계획, 코딩 전, 교차검토 대상, 2026-09-19)

입력: `docs/R6_PLAN.md`(R6a 설계·실측), `docs/R6B_PLAN.md` 7(가위 규칙 H 확정), 참고 조사(내부 agent — 아래 인용은 이 세션에서 연 것만).

## 0. 한 줄 요약

R6a/R6b 에서 검증된 `RECT_LIST` 깊이 사각형을 **그대로** 두고, 바꾸는 것은 색 쓰기에 필요한 것뿐이다: 정점에 **색 워드 하나**(`PK_RGBA`), 픽셀 파이프
**텍스처 블렌드 0 단계 = 정점 색 통과**(Mesa 초기값), **평면 마스크 전부**.  사각형은 기하 = 가위 + `SCISSOR_ENABLE`(규칙 H).  세 정점이 같은 색이라 평면/구로와
"어느 정점 색" 은 결과에 영향이 없다(변수 제거).  색 버퍼(선형 ARGB8888)와 깊이 버퍼를 모두 워드 단위로 판정한다.  삼각형(`TRI_LIST`)·구로는 다음 조각.

## 2. 설계

R6a 스트림에서 **바뀌는 워드만**:
- 선례 상태 블록: `PP_CNTL` 0 → **0x1000**, `RB3D_PLANEMASK` 0 → **0xffffffff**, `SE_VTX_FMT_0` 3 → **0x803**, `RE_CNTL` → **2**(규칙 H).  나머지(`RB3D_CNTL=0x1902`,
  Z 항상·쓰기, `SE_CNTL=0x480055de` 평면·마지막 정점, TCL 끔) 그대로.
- 전제 상태에 픽셀 파이프 네 레지스터(C4 값).  되읽기 게이트에 넣을지는 교차검토 질문(4 절) — 기본안: **기록만**(되읽기 미확인 레지스터로 부팅을 버리지 않는다).
- 그리기 패킷: `VF_CNTL = RECT_LIST|WALK_RING|COLOR_ORDER_RGBA|3` = 0x00030078, 정점 5 워드 × 3 = 15, 페이로드 = VF_CNTL + 15 = 16, 헤더 개수 필드 = 페이로드 − 1 = **15** → `0xc00f3500`(선례 페이로드 13 → 12 와 같은 규칙, python).
- 경우: **F**(색 12,34,56,78, 순서 비트 켬 — Mesa 대로), **G**(같은 색, 순서 비트 끔 — 바이트 순서 의미를 실측).  기하 = 가위 = (5,3)–(37,21).
- 되읽기: 색 버퍼 4096 워드도 요약값(깊이와 같은 함수), 기대는 선형 주소 `4*(x+64y)`.

판정: 색 버퍼 576 워드 = 기대 픽셀(F: 0x78123456, G: 가설 표에서 이름 붙여 기록), 나머지 색 워드·블록 나머지 불변, 깊이 버퍼는 R6a 경우 A 와 같음(깊이 경로 회귀 없음).

안전: 기하가 두 버퍼 안(R6a/R6b 와 같은 사각형), 가위 켬; GPU 쓰기는 VRAM 두 버퍼뿐(writeback 끔 그대로).  새로 켜는 것은 색 쓰기와 픽셀 파이프 한 단계.

## 3. 실기 절차(한 부팅)
RECORD → REC3D → LOAD → MAP → RESET → START → (ZPREP→ZCLEAR) A(회귀) → F → G → REC3D → STOP → RECORD → cycle.

## 4. 교차검토에 물을 것
1. 색이 나오는 데 필요한 레지스터가 빠졌는가(예: `PP_CNTL_X`, `RE_SOLID_COLOR`, `SE_CNTL` 셰이딩 비트, `RB3D_BLENDCNTL`, 디더·반올림, `RB3D_COLOROFFSET` 정렬).
2. 전제 상태의 픽셀 파이프 레지스터를 되읽기 게이트에 넣어야 하는가.
3. 경우 G(순서 비트 끔)가 안전한가, 가치가 있는가.
4. 판정기가 색 버퍼의 바이트 순서·디더·반올림 때문에 속거나 거짓 FAIL 을 낼 경로.

### 1-1. 계획 작성 중 잡은 내 오류
- 그리기 패킷 헤더의 개수를 "15−1=14" 로 적었다 — 개수 필드는 **페이로드(VF_CNTL 포함) − 1** 이라 15 가 맞다(python, 선례로 규칙 확인).

## 6. 수정된 설계 (코딩 대상)

**경우 표**(`cpR6Case` 에 필드 추가; A–E 는 fmt 3·pp 0·planemask 0·vsc 0·hdr 0xc00c3500·vf 0x00030038 → **R6a/R6b 스트림과 비트 동일**):

| 경우 | 번호 | 기하·가위 | RE_CNTL | fmt | PP_CNTL | PLANEMASK | vsc(prefix) | hdr | VF_CNTL | 색 워드 |
|---|---|---|---|---|---|---|---|---|---|---|
| F | 6 | A 와 같음 (5,3)–(37,21) | 2 | 0x803 | 0x1000 | 0xffffffff | 0x10000 | 0xc00f3500 | 0x00030078 | 0x78563412 |
| G | 7 | 〃 | 2 | 0x803 | 0x1000 | 0xffffffff | 0x10000 | 0xc00f3500 | 0x00030038 | 0x78563412 |
| H | 8 | 〃 | 2 | 0x803 | 0x1000 | 0xffffffff | **0** | 0xc00f3500 | 0x00030078 | 0x78563412 |

- 스트림: 상태 26(값 워드 w[3]·w[5]·w[13]·w[19] 를 경우 값으로) → **픽셀 블록**(색 경우만, 단일 레지스터 PACKET0 네 쌍: 0x2f00=0x1000, 0x2f04=0x11000, 0x2f08=0x1000,
  0x2f0c=0x11000 — 다중 레지스터 PACKET0 은 실기 미검증이라 쓰지 않는다) → 가위 4 → IMMD(정점당 4 또는 5 워드) → 꼬리 10.  F·G·H = 65 워드, A–E = 54.
- prefix 의 `SE_VTX_STATE_CNTL` 값 = 경우의 vsc, 되읽기 기대도 같음(게이트 밖, 기록).
- 호스트 규칙: 경우마다 `hdr` 개수 = 1 + 3×(4 + [fmt 에 색0]) − 1, fmt 의 색0 필드 ∈ {0, PK_RGBA}, 색 경우 ⇔ PP_CNTL≠0 ⇔ 픽셀 블록 있음.
- REC3D: +0x2f00·0x2f04·0x2f08·0x2f0c(읽기만) → 64 개.
- 실기 절차(한 부팅): RECORD → REC3D → LOAD → MAP → RESET → START → (ZPREP→ZCLEAR) **A(1) → F(6) → G(7) → H(8) → F′(6)** → REC3D → STOP → RECORD → cycle.
- 판정:
  - 모든 경우(안전): 표지·블록 나머지 불변·잠금 없음·깊이 버퍼 = A 의 깊이(576, 같은 요약).
  - A: R6a 판정 그대로, 색 버퍼 불변.
  - **F, F′ (게이트)**: 색 버퍼 변경 576, 값 하나, 선형 배치(`4*(x+64y)`, 요약 ixor/isum 일치), 값 = 0x78123456 → PASS.  채널별 ±1 은 이름 붙여 FAIL 이 아닌
    "근사" 로 보고(판정은 운영자 결정 사항으로 남김), 타일 배치·순서 뒤바뀜은 이름 붙인 FAIL.  F′ = F(같은 요약).
  - G, H: 측정 — 가설 표(7 절)에서 이름을 붙여 기록, 게이트 아님(단 안전 판정은 적용).
- 변이(sim_r6): F/G 순서 비트 뒤바꿈, 색 워드 틀림, 픽셀 블록 한 쌍 누락, A 가 F 상태 사용, 헤더 개수 ±1, 색 워드 빠진 정점(헤더는 15), vsc 틀림, 색 경우 PLANEMASK 0.
- 스택: `w[72]`(288 B) — 재측정해 R6a 최대 572 B 와 비교해 기록.

### 6-1. 수정 과정에서 잡은 내 오류
- 0x2180 부팅값이 "스스로 바뀐다" 고 읽을 뻔했다 — 우리 prefix 가 0 을 쓴다((검토 시점) `osrdn_cp.m` 1156 행).
