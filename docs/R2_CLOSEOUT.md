# R2 닫기 — 게이트 대조와 남은 틈 (개정 0, 2026-09-17)

R3(다중 모드·심도·Configure)로 넘어가기 전에, `PLAN.md` §5 R2 의 **Gate** 문장을 한 항목씩
지금까지의 실기 증거와 대조한다.  모드는 operator 결정으로 1024×768 이 아니라
**800×600@60** 이다(`docs/R2_FIRST_LIGHT_PLAN.md` §1c-1).

## 2. 틈 1 — 0 단계 의미 조건 넷을 진입에 넣는다

R2b-0 기록 경로가 이미 이 넷을 게이트로 평가했고 **실기에서 통과했다**(`osrdn_record.m`
`gateEvaluate`, R2b-0 판정 `refused=1` 은 `divsel` 뿐).  비트 정의는 xf86 `radeon_reg.h` 와 대조했다:

| 게이트 | 레지스터 | 조건 | 헤더 |
|---|---|---|---|
| `crtc2` | `CRTC2_GEN_CNTL` 0x03f8 | `CRTC2_EN`(bit 25) = 0 | `radeon_reg.h` 401·414 |
| `fpon` | `FP_GEN_CNTL` 0x0284 | `FP_FPON`(bit 0) = 0 | 839·840 |
| `cpmode` | `CP_CSQ_CNTL` 0x0740 | `>> 28` = 0 (`CSQ_PRIDIS_INDDIS`) | 3141·3143 |
| `rbbm` | `RBBM_STATUS` 0x0e40 | `RBBM_ACTIVE`(bit 31) = 0 | 1485·1487 |

**빼는 것**: `divsel` 은 부팅마다 달라서(R2b-0 H5) 의미 조건이 아니다.  R2a 정확값 14 개
(`TV_DAC_CNTL` 등)는 H5 의 "부팅 상태 상수를 코드에 굳히지 않는다" 에 따라 넣지 않는다.

**어디서 읽는가**: 모드 모듈은 하드웨어를 `osrdn_snap.m` 접근자로만 만진다.  이 넷은 스냅샷·복원
대상이 **아니므로**(우리는 절대 쓰지 않는다) 스냅샷 표에 넣지 않고, `osrdn_snap.m` 에 **읽기
전용 접근자** `osrdn_peek(base, which)` 와 그 전용 표 `osrdnPeek[4]` 를 둔다.  쓰기 접근자는
이 표를 받지 않으므로 "진입이 쓴 것 ⊆ 복귀가 되돌리는 것" 규칙은 그대로 선다.
역어셈블 게이트의 호출자 목록에 `_osrdn_peek` 가 `_rdnMmioRead32` 의 호출자로 추가된다.

**재진입**: `modeCheck` 는 `snapshotValid` 면 부팅상태 게이트를 건너뛴다(R2B 개정 2).
이 넷은 **우리가 바꾸지 않는 것**이므로 재진입 때도 본다 — 순서를 그렇게 둔다.

**거절 코드**: `MODE_WHY_BUSY_CLIENT` (새 값) 와 어느 게이트인지(`clientWhich`).

## 3. 틈 2 — 대기 상한 도달을 로그에 낸다

`wait` 줄에 `slim=<settleLimit> shlim=<showLimit>` 를 더한다.  순환 줄의 `pending` 과 합쳐
**다섯 대기 전부의 상한 도달 여부가 로그에 나온다**.

## 4. 틈 3 — 종료 때 콘솔이 돌아오는지 본다

코드 변경 없음.  operator 가 **다음 종료(재부팅) 때 화면을 본다**: WindowServer 가 내려간 뒤
커널 콘솔의 종료 메시지가 읽을 수 있게 나오면 통과, 검은 화면·깨진 화면이면 실패(그래도 다음 부팅은
VGA BIOS 가 되살리므로 기계는 안전하다 — 그래서 지금까지 이 틈이 안 보였다).

**주의**: 종료 메시지가 원래 화면에 나오는 구성인지 모른다.  그래서 이 확인 **전에** 드라이버를
끈 VGA 부팅에서도 한 번 봐야 기준이 선다 — 그런데 operator 결정(§설치만)에 따라 VGA 전환은 하지
않는다.  대안: 복원 묶음이 만든 VGA 부팅들(R2B·R2C·R2D 원복)에서 operator 가 종료 화면을 기억하면
그것이 기준이다.  **이것은 operator 에게 묻는다.**

## 5. 검사 (코드 전에)

- 시뮬레이터: 넷 각각을 켠 세계에서 **쓰기 0 회로 거절**, 끈 세계는 진입.  재진입 때도 거절.
- 변이: 게이트 하나를 지우면 그 세계가 잡는다.
- 소스 규칙: `osrdn_peek` 표의 오프셋이 스냅샷 표·쓰기 경로에 없을 것, 모드 모듈이 `rdnMmioRead32`
  를 직접 부르지 않을 것.
- 역어셈블 게이트: `CALL_WANT` 에 `_osrdn_peek` 추가.

기준 길이도 같은 방식(`mode->fbLength`)으로 넘긴다 — 모드 모듈은 PCI 를 읽지 않는다.

## 8. 개정 1 — 대기 계측

논리적 대기 지점마다 `{돈 횟수, 한도 도달}` 을 따로 둔다:

| 지점 | 진입 | 복귀 |
|---|---|---|
| 원자갱신 쓰기 대기 | `aw` | `raw` |
| 원자갱신 읽기 대기 | `ar` | `rar` |
| PLL 정착 | `ps` | `rps` |
| 슬롯 정착 | — | `rss` |
| 노출 | `sh` | — |
| 오프셋 트리거 | — | `trig`(있음) |

wait 줄은 **진입 뒤와 순환 뒤 둘 다** 찍는다.  "실행됨" 은 횟수 > 0 으로, "한도 0" 은 도달 플래그로.

## 9. 틈 3 — 종료 관찰의 판정

- **PASS**: 데스크톱이 사라지고, 다음 BIOS 화면 전에 화면이 콘솔 모드로 바뀌며, 종료 문장이 읽힌다.
  짧은 동영상이 기억보다 낫다.
- **검은 화면은 판정 불가**: 같은 설정의 VGA 대조 재부팅이 기준인데, operator 결정(설치만, VGA
  전환 없음)으로 그것을 새로 만들지 않는다.  operator 가 **VGA 로 돌던 시절의 종료 화면**을
  기억한다면 그것을 기준으로 삼는다.
- 이 관찰이 닫는 것은 "종료가 래퍼를 불렀고 쓸 수 있는 콘솔이 나왔다" 뿐이다.

### 14-1. 원인 (python)

순환은 `noSleep` 이라 `IODelay(500)` 로 돈다.  이 기계의 `IODelay` 는 **짧다**: R2b-0 실측
`IODelay(2000)` = 1872–1881 µs(비율 0.936–0.941, `docs/R2B0_RESULT.md` §2).  횟수 한도
`limit/tick + 8` 은 여유가 4 % 뿐이다.

| 대기 | 한도(µs) | 필요 턴(비율 0.936) | 한도 턴 | 결과 | 실측 |
|---|---|---|---|---|---|
| `rps` | 50 000 | 106.8 | 108 | 시계가 간신히 이김 | `108/0` |
| `rss` | 100 000 | 213.7 | 208 | **횟수가 먼저** | `208/1` |

즉 횟수 한도는 "시계가 멈췄을 때의 안전망" 으로 설계했는데 **정상 동작에서 발동**했다.
결과는 무해했다(약 97 ms 를 기다렸고 복귀는 항등).  하지만 게이트의 "한도 도달 0" 을 못 채우고,
설계 의도와도 다르다.

### 14-2. 제안

`maxTurns = (limit / tick) * 5 / 4 + 8`.  `IODelay`(또는 `IOSleep`)가 명목의 **0.75 배**까지
짧아도 시계가 먼저 끝낸다(python: rps 0.752, rss 0.775, show 0.799 까지).  반대 방향 — `IODelay`
가 길 때(R2a 실측 `IODelay(2000)` = 4.1 ms) — 은 시계가 더 일찍 끝내므로 영향이 없다.
시계가 멈춘 경우 정착 대기(순환의 진입 `ps` + 복귀 `rps` + `rss`)의 스핀은 python 으로
212 000 µs → 262 000 µs 로 늘어난다.  원자갱신 폴링은 틱이 아니라 `MODE_POLL_LOOPS` 로 끝나므로
이 변경과 무관하다.

검사: 시뮬레이터의 가짜 `IODelay` 에 **비율**을 넣어(0.936) 지금 코드가 `rss` 에서 한도에 걸리는 것을
재현하고, 고친 코드는 한도 0 인지 본다.  멈춘 시계 세계는 그대로 대기를 끝내야 한다.
