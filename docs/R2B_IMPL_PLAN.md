# R2b 구현 계획 — 첫 모드셋 (개정 2, 2026-09-16 — 구현으로 확정, §13)

상위 계획은 `docs/R2_FIRST_LIGHT_PLAN.md` 개정 6(진입 §4, 복귀 §5, 계약 §6, 게이트 §7).
이 문서는 **그것을 코드·검사·실기 절차로 옮긴 것**이고, 상위 계획과 어긋나면 상위 계획이 이긴다.
R2b-0 이 무엇을 이미 증명했는지는 `docs/R2B0_RESULT.md`.

> **출처 규칙**: `openstep-kernel-remade` 는 근거가 아니다(`tools/check_sources.py` 가 `check-all`
> 에서 강제).  근거는 실기 바이너리·미러 `ref/openstep`·`ref/upstream`·`doc/driverkit.md`·Matrox·실측.

## 1. R2b 가 R2b-0 과 다른 점, 같은 점

**같다(그대로 쓴다)**: 번들 구조·설치·활성화 절차(Configure → 주차 → `activate`·`same` 게이트 →
재부팅), 한-소유자 `+probe:` 걸쇠, `/me` 집합 복원, 옵트인 키, 기록 줄 문법·파서 틀, 타깃 스크립트.

**다르다(새로 만든다)**:

| # | R2b-0 | R2b |
|---|---|---|
| A1 | `enterLinearMode` 가 **항상 거절** | 진입 시퀀스 0–13 단계를 수행하고, 거절은 0–3 단계에서만 |
| A2 | 하드웨어 **쓰기 0 회** | CRTC·PLL·FIFO·DAC·팔레트·FB 에 쓴다.  **쓰기 목록은 §4 표가 전부**이고 그 밖의 쓰기는 소스 규칙이 막는다 |
| A3 | `revertToVGAMode` 는 슈퍼클래스 통지만 | 스냅샷 복원 10 단계 |
| A4 | 기록이 파라미터 트리거(부팅 뒤) | 진입·복귀가 **부팅 경로에서** 일어난다.  기록은 그 안에서 쌓고 부팅 뒤 도구가 꺼낸다 |
| A5 | 게이트 32 개가 "쓰지 않음" 을 검사 | 게이트는 **되읽기 판정**(13 단계)과 복귀 뒤 상태 |

## 2. 안전 불변식 (코드로 강제, 규칙으로 증명)

1. **스냅샷 먼저.** `snapshotValid` 가 서기 전에는 어떤 모드 레지스터도 쓰지 않는다.
2. **`modeWritten` 은 첫 하드웨어 쓰기 직전에** 선다(= 4 단계 블랭크).  복귀의 하드웨어 복원은
   `snapshotValid && modeWritten` 일 때만.
3. **거절은 쓰기 전에 끝난다.** 0–3 단계에서만 거절하고, 그 경로는 인덱스만 되돌린다.
4. **복귀는 끊지 않는다.** 복원 중 상한 도달은 기록만 하고 계속한다 — 끊으면 콘솔을 잃는다.
5. **한 소유자.** `+probe:` 걸쇠(R2b-0 에서 실기 확인).
6. **부팅 상태 상수 금지.** 복원은 그 부팅에서 읽은 값으로만 한다(H1·H5).  코드에 박는 상수는
   오라클이 계산한 **모드 값**과 참고 구현의 **비트 정의**뿐이다.
7. **쓰지 않는 것**: MC 맵·`HOST_PATH_CNTL`·`SURFACE_CNTL`·`BUS_CNTL`·버스 마스터·CP·2D·인터럽트·
   CRTC2·FP/TMDS·TV DAC·DAC 전원·동적 클럭 게이팅·오버레이·커서·`PPLL_DIV_0..2`·`PPLL_REF_DIV` 값 변경.
8. **`PPLL_REF_DIV` 는 네 슬롯 공유**다.  읽은 refdiv 를 그대로 되쓰고 값을 바꾸지 않는다 —
   바꾸면 쓰지도 않은 콘솔 슬롯의 주파수가 조용히 바뀐다.
9. **걸쇠**: 진입 중 실패는 RAM 기록 → 영구 걸쇠(다음 **진입**만 막음) → 복귀 수행.

## 3. 코드 구조

```
OSRDNDisplay/OSRDNDisplay_reloc.tproj/
  OSRDNDisplay.m/.h        클래스.  probe·init·enter·revert·get/setIntValues.  하드웨어 호출 없음
  osrdn_record.m/.h        (R2b-0 그대로) 기록·걸쇠·PCI·게이트·줄
  osrdn_mode.m/.h          **새로**: 진입 0-13 단계와 복귀 10 단계.  순수 C89
  osrdn_snap.m/.h          **새로**: 스냅샷 구조체와 읽기/되쓰기(MMIO·PLL·VGA 포트·팔레트)
  osrdn_expect.h           오라클 생성(모드 값·기대값 표) — 손으로 고치지 않는다
  osrdn_pll.m/.h           R2a PLL 스냅샷(그대로)
  osrdn_port.m/.h          포트 이음새(그대로)
  RDNR2aMMIO.m/.h          MMIO 헬퍼(그대로)
```

- **클래스는 하드웨어를 부르지 않는다**(`class-no-hw` 규칙).  `enterLinearMode` 는
  `osrdn_mode_enter(&rdnState)` 하나, `revertToVGAMode` 는 `osrdn_mode_revert(&rdnState)` 하나와
  `[super revertToVGAMode]`.
- 스냅샷은 `osrdn_state` 안의 구조체 하나(정적 크기, 동적 할당 없음).  팔레트 256×4 바이트 포함.

## 4. 진입 구현 (`osrdn_mode_enter`)

상위 §4 의 0–13 단계를 그대로, 한 단계 한 함수로.  각 함수는 `int` 를 돌려주고 0 이 아니면
그 자리에서 멈춘다(거절 또는 걸쇠).

| 단계 | 함수 | 쓰기 | 비고 |
|---|---|---|---|
| 0 | `modeCheck` | 없음 | 의미 조건만(개정 6 H5·H6).  실패 = 거절 |
| 1 | `modeSnapPll` | 인덱스만(복원) | R2a 코드 재사용.  refdiv 가 표에 없으면 거절 |
| 2 | `modeSnapVga` | 인덱스만(복원) | R2b-0 의 `vgaSnapshot` 재사용 → `snapshotValid` |
| 4 | `modeBlank` | `CRTC_GEN_CNTL`·`CRTC_EXT_CNTL` | **RMW**(상수 아님, H5).  여기서 `modeWritten` |
| 5 | `modeCrtc` | CRTC 9 개 | 오라클 값 |
| 6 | `modePll` | 6a–6m | 읽은 refdiv 로 고른 표 행 |
| 7 | `modeFifo` | `GRPH_BUFFER_CNTL` | 읽은 값에서 시작 |
| 8 | `modeDac` | `DAC_CNTL` | 읽은 값 RMW |
| 9 | `modePalette` | 팔레트 256 | 선형 램프 |
| 10 | `modePattern` | FB | 시험 패턴 |
| 11 | `modeUnblank` | `CRTC_GEN_CNTL`·`CRTC_EXT_CNTL` | RMW |
| 12 | (없음) | 없음 | 2 s 대기 |
| 13 | `modeVerify` | 없음 | 되읽기 판정 → 기록 |

- **대기는 전부 `IOGetTimestamp`**(R2b-0 에서 `IODelay` 가 부팅마다 1.87–4.1 ms 로 흔들리는 것을
  실측).  경과 계산은 R2b-0 의 `elapsedUs` 모양 그대로(64 비트 나눗셈 없음).
- 상한 도달 처리는 상위 §4 의 표 그대로(6g 는 건너뛰고 계속, 6i 는 기록하고 계속).

## 5. 복귀 구현 (`osrdn_mode_revert`)

상위 §5 의 4.1–4.10 을 순서대로.  **모든 값은 스냅샷에서 온다.**

- 4.5 의 PLL 은 진입 6a–6m 과 **같은 함수**를 값만 바꿔 부른다(코드 하나, 규칙으로 고정).
- 4.6 은 **읽은 32 비트 `CLOCK_CNTL_INDEX` 를 그대로** 쓴다(개정 6).  4.7·4.8 보다 앞이어야 한다.
- 4.9 는 `ATTR[0x10]` bit 0 이 0 이면 건너뛰고 로그(상위 §5 3).
- 멱등: 끝에서 `modeWritten` 을 내린다.

## 7. 호스트 검사 (코드 전에 만든다)

1. **오라클과 생성기**: 800×600@60 두 행 + 기대값 표를 `osrdn_expect.h` 로 생성하고 `--check` 로
   소스와 대조(R2b-0 `gen_expect_r2b0.py` 틀).  **생성물끼리 비교하면 항등식이 된다** — R2b-0 생성기가
   "원시 로그 값 = 사람이 문서에 적은 값" 을 강제했듯, R2b 생성기는 **오라클 계산값 = 이 계획서와 상위
   계획 §4 분주 표에 사람이 적은 값** 을 강제한다.  한쪽만 고치면 생성이 멈춘다.  대상:
   `PPLL_DIV_3` 두 행(`00030047`·`0003008e`), CRTC 4 워드(`00630083 00100340 02570273 00040258`),
   `CRTC_PITCH` `00640064`, `dotClockRate` 39937500, 리프레시 60.2223 Hz, 실현 VCO 319500 kHz.
2. **소스 규칙**(`check_r2b0_src.py` 확장): 클래스에 하드웨어 호출 없음; 진입의 쓰기 목록이
   §4 표와 정확히 일치(레지스터 오프셋 집합); `modeWritten` 이 4 단계 앞에서만 서고 복귀 끝에서만
   내려감; 복귀가 상수 `3` 을 쓰지 않음; `PPLL_REF_DIV` 값 변경 없음; 진입·복귀가 같은 PLL 함수를
   부름; 대기에 `IOGetTimestamp` 만 쓰고 `splhigh` 안에서 시각을 읽지 않음.  **각 규칙마다 변이**.
3. **시뮬레이터**(`sim_r2b0.py` 확장): refdiv 6·12 두 세계, 거절 세계(0 단계 조건 위반·표에 없는
   refdiv), 상한 도달 세계(6g·6i), 복귀 세계(스냅샷이 그대로 돌아오는지 바이트 비교), 걸쇠 세계.
4. **역어셈블 게이트**(`check_reloc_r2b0.py` 그대로): 포트 명령이 이음새 함수 안에만.
5. `check-all` 에 편입.

## 8. 실기 절차

R2b-0 과 **같다**(그 절차가 실기에서 끝까지 돌았다): 패킹 → 타깃 빌드 → reloc 게이트 → 설치 →
`cfgsnap pre` → `precheck` → 복원 묶음 스테이지 → **operator Configure 전환** → `postraw` → 주차 →
`post` → `activate` → `postb` → `same` → **operator 재부팅** → (telnet, `/ndrv` 수동 마운트) 기록 수집 →
판정 → `restore.sh` → **operator 재부팅**.

부팅 뒤 화면은 **시험 패턴**이어야 한다(2 s).  그 뒤 WindowServer 가 덮어 그린다.

## 9. R2b 가 PASS 라는 뜻

1. 진입이 0–14 단계를 끝내고 **12 단계 되읽기**가 전부 일치(순서는 13-1 에서 바뀌었다).
2. operator 가 시험 패턴을 봤다(모서리·띠·기울기가 어긋나지 않음).
3. 복귀 뒤 스냅샷 대상 레지스터가 **스냅샷과 같다**(드라이버가 되읽어 기록, 호스트가 판정).
4. 그 부팅에서 telnet 이 살아 있었고 복원·재부팅으로 VGA 로 돌아왔다.

## 10. 위험·미확인

- **첫 하드웨어 쓰기**다.  실패 모양은 (a) 그림이 이상함, (b) 화면 없음, (c) 행.  (a)·(b) 는 복귀·재부팅으로
  돌아온다.  (c) 는 telnet 도 잃을 수 있고 그때는 전원 재시작 → 루트 fsck 비용.
- `PPLL_RESET` 후 재잠금이 이 카드에서 처음이다.  같은 VCO(319500 kHz)로 되돌아가므로 콘솔이
  잠겼던 조건과 같다는 것이 유일한 근거다.
- VGA 코어 평면이 VRAM 어디인지 미확인 — 시험 패턴이 덮으면 복귀 그림이 깨질 수 있다(그림 문제).
- 종료 중 로그가 없다 — 복귀 판정은 되읽기 기록 + operator 육안.

## 11. 결정

1. **진입 PVG — 결정: 어느 쪽도 쓰지 않는다**(개정 1, 아래 12-1).
2. **블랭크만 하는 선행 실행으로 쪼갤 것인가 — 결정: 쪼개지 않는다**(개정 1, 12-7).
3. 시험 패턴 노출 시간 — 12-6 의 질문으로 바꾼다(길이가 아니라 커널 호출 안에서 기다리는 것 자체).
4. 복귀 팔레트의 클럭 처리 — 여전히 미결(상위 §5 4.3).  참고가 갈린다: radeonfb 는 항목마다 게이트,
   xf86 은 게이트 없음.  **진입 9 단계와 같은 처리로 고정**하되 근거를 12-3 의 짝 규칙으로 묶는다.

## 12. 개정 1 — 교차검토로 바뀐 것 (전 건 원문 확인)

### 12-1. 진입은 PVG 를 쓰지 않는다 (가장 중요)

- xf86 은 **쓸 값으로 이득을 다시 계산**하고(`legacy_crtc.c` 의 `RADEONComputePLLGain` 호출) 그
  RMW 의 클리어 마스크에 **`PPLL_PVG_MASK` 를 포함**한다.  그 함수는 **복귀에도 같은 것이 쓰인다**
  — 즉 xf86 을 그대로 따르면 **복귀에도 7 을 쓴다**.  상위 §5 4.5 의 "어느 참고도 PVG 를 저장·복원하지
  않는다" 는 맞지만 "그래서 xf86 은 콘솔 PVG 를 남긴다" 로 읽히면 틀리다 — xf86 은 7 을 덮어쓴다.
- NetBSD radeonfb(이 칩을 지원하는 출하 드라이버)는 **PVG 를 어디에도 쓰지 않는다**: `SETPLL` 은
  읽기-OR(`radeonfbvar.h` 334 행), `PPLL_CNTL` 쓰기에 PVG 비트가 없다(`radeonfb.c` 2223–2228 행).
  `.c` 어디에도 PPLL PVG 쓰기가 없다(전수 grep — 헤더의 정의뿐).  즉 NetBSD 는 새 VCO 를
  **펌웨어가 남긴 이득으로** 잠근다.
- 실측: 이 카드는 **VCO 319500 kHz 를 PVG 4 로 지속 잠갔다**(두 부팅 모두 `PPLL_CNTL 0000a700`).
  이번 첫 모드는 **같은 VCO** 다.  7 이 그 VCO 에서 잠기는지는 아무 근거도 없다("horribly crude" 라고
  참고 스스로 적은 3 구간 표).
- **그래서 진입의 `PPLL_CNTL` RMW 클리어 마스크에서 PVG 를 뺀다** — 7 도 리터럴 4 도 쓰지 않는다.
  이러면 (a) 진입과 복귀가 **같은 규칙**이 되고, (b) NetBSD 가 하는 것과 같아지고, (c) §2-6 이 금지한
  부팅 상태 상수가 생기지 않는다.
- 게이트 승격: 13 단계에서 `PPLL_CNTL` 의 PVG 필드가 **스냅샷과 같아야 한다**(기록만 아님).
- 규칙: `REG_PPLL_CNTL` 쓰기의 클리어 마스크에 `PPLL_PVG_MASK` 가 없을 것.  변이: 마스크에 추가.
- **적용 범위**: 목표 VCO 가 콘솔 VCO 와 같기 때문에 안전하다.  다른 모드·다른 VCO 로 가는 R3 는
  이 면제를 물려받지 말고 다시 판단한다.

### 12-2. PLL **쓰기** 프로토콜을 적는다 (이 카드가 한 번도 안 한 접근)

- 참고: `OUTREG8(CLOCK_CNTL_INDEX, (addr & 0x3f) | PLL_WR_EN)` → **32 비트** `CLOCK_CNTL_DATA` 저장
  (`radeon_driver.c` 의 `RADEONOUTPLL`).  R2a 가 증명한 것은 **읽기**뿐이다(바이트 인덱스·32 비트 읽기).
- 구현: 쓰기 헬퍼는 읽기 헬퍼와 같은 규율로, **데이터 저장 뒤 인덱스 바이트를 WR_EN 없이 되쓴다**.
  이유는 12-3.  이 되쓰기는 참고에 없는 추가 쓰기이므로 **여기에 적어 근거를 남긴다**(R2a 읽기 헬퍼가
  인덱스를 복원하는 것과 같은 모양).
- 역어셈블 게이트(`check_reloc_r2b0.py`)를 **확장**한다: 새 저장 모양 두 가지(인덱스 바이트 `|WR_EN`,
  32 비트 DATA)를 심볼 범위별로 확인.  §7-4 의 "그대로" 는 틀렸다.
- 시뮬레이터에 PLL 쓰기 세계를 넣는다(인덱스·데이터 순서, WR_EN 비트).

### 12-3. WR_EN 을 남기면 우리 자신의 읽기 경로가 "busy" 로 거절한다

`osrdn_pll.m` 은 `CLOCK_CNTL_INDEX` 에 `PLL_WR_EN` 이 서 있으면 `WHY_BUSY` 로 거절한다.  xf86 의
`OUTPLL` 은 WR_EN 을 내리지 않고 다음 `INPLL` 이 내린다.  그대로 두면 **13 단계 되읽기가 거짓 FAIL**
이 되고 두 번째 진입도 1 단계에서 거절된다.  → 12-2 의 "데이터 뒤 인덱스 되쓰기" 로 닫는다.
13 단계에 `CLOCK_CNTL_INDEX` 의 WR_EN 이 0 이라는 검사를 넣는다.

### 12-4. 진입은 실패하면 **스스로 복귀한다**

`- (void)enterLinearMode;` 는 **반환값이 없다**(`IOFrameBufferDisplay.h`).  실패를 커널에 알릴 수
없으므로 커널이 복귀를 불러 주지 않는다.  따라서 `osrdn_mode_enter` 는 `modeWritten` 이 선 뒤의
어떤 실패에서도 **자기가 `osrdn_mode_revert` 를 부른다**.  종료 때 오는 `revertToVGAMode` 는
`modeWritten` 으로 멱등이다.  (§2-9 와 §4 의 "그 자리에서 멈춘다" 가 어긋났던 것을 이렇게 맞춘다.)
그 뒤 WindowServer 는 여전히 리니어 모드라고 믿고 프레임버퍼에 그린다 — R2b-0 에서 본 그림이고
**operator 고지에 적는다**.

### 12-5. 새 불변식: **진입이 쓴 레지스터는 전부 복귀의 복원 목록에 있다**

§2 에 없던 것이고, 이 실행의 안전이 여기 걸려 있다.  검사 둘로 못박는다:
- 소스 규칙: 진입 쓰기 오프셋 집합 ⊆ 복귀 복원 오프셋 집합.
- 시뮬레이터: 가짜 레지스터 파일을 진입 전과 복귀 후에 **바이트 비교**(refdiv 6·12 두 세계).

### 12-6. 상위 계획에서 빠뜨린 규칙 두 개를 가져온다

1. **`PIXCLK_DAC_ALWAYS_ONb` 짝**: 9 단계의 내림은 **모든 출구 경로**에서 복원과 짝이어야 한다
   (상위 §7).  안 지키면 복귀가 성공해도 **DAC 픽셀 클럭이 게이트된 채 검은 화면**이 된다.
   변이: 사이에서 반환.  시뮬레이터에 9 단계 안에서 걸리는 세계.
2. **`nm -u` + 64 비트 나눗셈 없음**: 빌드는 되고 **적재가 실패**한다 = 디스플레이 드라이버 없는 부팅.
   §7 목록에 명시한다(물려받는 것으로 두지 않는다).

### 12-7. 쪼개지 않는 이유를 적어 둔다

상위 계획의 미결 1 번("블랭크 → 즉시 복귀" 선행 실행)은 **하지 않는다**.  `modeWritten` 이 블랭크
단계에서 서므로 블랭크만 해도 복귀는 **PLL 시퀀스를 포함해 전부** 실행된다 — 가장 위험한 부분은
그대로 두고 실패해도 그림만 나빠지는 부분만 빠진다.  재부팅 한 번을 더 쓰면서 새로 증명되는 것이 없다.

### 12-8. 아직 답이 없는 것 (실행 전에 정한다)

- **커널 호출 안에서 2 s 를 기다리는 것**이 WindowServer 쪽 RPC 상한을 건드리는지.  참고 트리에 답이
  없다 — 상한을 두고, 호출자가 포기해도 시퀀스가 견디게 한다.
- `CRTC_EXT_CNTL` 을 평평한 상수로 쓰면 이번 부팅에서 켜져 있던 bit 27·28(두 헤더 미정의)이 지워진다.
  xf86 도 지운다(초기화 구조체가 0 에서 OR 로 만들어진다)므로 참고와 같지만, **검은 화면을 이걸로
  오진하지 않도록** 적어 둔다.  복귀는 스냅샷으로 되돌린다.
- `PLL_DIV_SEL` 과 VGA 코어 클럭 소스의 관계는 미확인인데, 복귀의 임계 경로에 있다(4.6 이 슬롯을
  1 로 되돌린 뒤 VCO 가 RESET 없이 다시 잡혀야 한다 — xf86 도 같은 모양, 100 ms 가 유일한 보호).

### 12-10. FIFO(7 단계) — 정수만으로, xf86 의 "HIGH" 경로 (개정 1 결정)

원문을 열어 보니 상위 §8 이 요구한 "float32 흉내" 는 **필요도 없고 가능하지도 않다**:

- xf86 의 대역폭 계산은 `float` 로 하고(`legacy_crtc.c` 의 `disp_latency`·`disp_drain_rate` 선언),
  입력이 메모리 타이밍 레지스터(`mem_trcd`·`mem_tras`·`mem_trp`·mclk·sclk·DDR 여부)다.
  **커널 드라이버는 부동소수점을 쓸 수 없다.**
- 그런데 xf86 자신이 정수만 쓰는 길을 갖고 있다: 사용자 옵션 `DisplayPriority "HIGH"`
  (`DispPriority == 2`)이면 **임계점을 0 으로 둔다**.  그리고 소스 주석이
  "`GRPH_CRITICAL_CNTL = 0` will thus force high priority all the time" 이라고 적는다 —
  우리 계획이 이미 `CRITICAL_CNTL` 을 0 으로 두기로 한 것과 맞는다.
- **NetBSD radeonfb 는 `GRPH_BUFFER_CNTL` 을 아예 쓰지 않는다**(전수 grep 0 건).  같은 칩을 모는
  출하 드라이버가 안 건드린다는 것은, 이 레지스터를 잘못 써서 **행이 나는 부류가 아니라는** 뜻이다
  (실패 모양은 화면 아티팩트).
- xf86 의 기본값은 `DispPriority = 1` 이고 **옵션이 0("BIOS")일 때만 안 건드린다** — 즉 "안 쓰기" 도
  참고가 인정하는 구성이다.

**결정**: 7 단계는 유지하되 **정수 경로**로 한다 — `stop_req = start_req = 0x5c`(800×4/16 = 200 을
RV100 계열 상한으로 클램프), `BUFFER_SIZE` 1, `CRITICAL_CNTL`·`AT_SOF`·`STOP_CNTL` 0, **임계점 0**.
읽은 값에서 RMW 하며 보존 비트는 `0x0f808080`, 0 에서 만들면 `0x20005c5c`.  오라클이 계산하고
(`tools/oracle/radeon_modeset.py` 의 `fifo()`) 자체검사가 실측·문서 값과 대조한다.
복귀는 스냅샷으로 되돌리므로 되돌릴 수 있다.

### 12-11. 오라클 확장 완료 (개정 1)

`tools/oracle/radeon_modeset.py` 에 추가: `fifo()`·`crtc_pitch()`·`display_info()`·`pll_rows()`·
`mode_by_name()`.  자체검사 9 종 — 그중 **R2a 콘솔 실측 `PPLL_DIV_3 = 00030047` 재현**이 사슬 전체의
정본 대조이고, 음성 대조 4 건이 각 기준값이 정말 입력에 의존하는지 증명한다(같은 실행에서).
작업 중 함정 하나를 제거했다: 상수를 **기본 인자**로 받으면 정의 시점에 묶여 나중에 상수를 고쳐도
동작이 안 바뀐다(변이가 안 걸렸다) — 호출 시점에 읽도록 고쳤다.

### 12-12. 스냅샷 목록 (정본, 개정 1)

**진입이 쓰는 것 = 복귀가 되돌리는 것**(12-5 불변식).  python 으로 두 집합을 대조해 차집합이 비었음을
확인했다.  이 목록이 "콘솔이 돌아온다" 의 정본이고, 소스 규칙과 시뮬레이터가 이것을 강제한다.

**MMIO 13 개**(오프셋 순, 모두 `osrdn_record.m` 의 레지스터 표에 이미 있는 이름):

| 오프셋 | 이름 | 진입에서 쓰는 단계 |
|---|---|---|
| `0x0008` | `CLOCK_CNTL_INDEX` | 6c(bit 8–9), 복귀 4.6 이 32 비트 스냅샷을 되씀 |
| `0x0050` | `CRTC_GEN_CNTL` | 4·5·11 |
| `0x0054` | `CRTC_EXT_CNTL` | 4·5·11 |
| `0x0058` | `DAC_CNTL` | 8 |
| `0x0200` | `CRTC_H_TOTAL_DISP` | 5 |
| `0x0204` | `CRTC_H_SYNC_STRT_WID` | 5 |
| `0x0208` | `CRTC_V_TOTAL_DISP` | 5 |
| `0x020c` | `CRTC_V_SYNC_STRT_WID` | 5 |

진입이 쓰지 않기 때문이다(콘솔이 그중 하나를 쓰고 있을 수 있다).

**그 밖**: 팔레트 256 × 30 비트, 표준 VGA 포트 61 바이트(MISC 1 + SEQ 5 + CRTC 25 + GR 9 + ATTR 21).

주의: `PPLL_REF_DIV` 는 **스냅샷에 있지만 값을 바꾸지 않는다**(§2-8).  스냅샷에 두는 이유는 복귀의
6d 가 같은 RMW 모양을 쓰기 때문이고, 쓰는 값은 읽은 값 그대로다.

### 12-9. §7·§8·§9 에 더할 것

- **번들·발행 모드 상수**: `OSRDN_WIDTH/HEIGHT`·`rowBytes`·`memorySize`·`dotClockRate`·`OSRDN_FB_LENGTH`

  §7-1 의 "사람이 적은 값과 일치" 규율을 유지한다.

## 13. 개정 2 (2026-09-16) — 코드를 쓰면서 확정한 것

### 13-1. §12-8 첫 질문의 답: **되읽기를 기다림보다 먼저** 한다

커널 호출 안에서 2 초를 기다리는 것이 WindowServer 쪽 상한을 건드리는지는 **여전히 모른다**.
참고 트리에 답이 없고, 실기 없이는 잴 수 없다.  대신 그 불확실성이 **증거를 못 잃게** 만들었다.

- Matrox 대체 드라이버는 `enterLinearMode` 안에서 옵트인 엔진 시험(`runStormLivenessTest`,
  `runStormBlitTest`)을 돌린다 — FIFO 타임아웃 대기와 사각형 전수 루프가 들어 있다
  (`OpenStepMGAReplacementDisplay.m:7325-7346`, `:5022`).  같은 파일의 주석은 다른 청구자가
  "1 초씩 기다리다 포기한다" 고 적는다(`:7327-7329`).  **호출 안에서 시간을 쓰는 것 자체는
  그 프로젝트가 실기에서 넘긴 일**이다.  다만 2 초라는 수의 안전은 이것으로 증명되지 않는다.
- 그래서 순서를 바꿨다.  **12 단계 = 되읽기 검증, 13 단계 = operator 노출(2 s), 14 = 끝**.
  (1) 호출자가 기다리는 도중 포기해도 판정 근거는 이미 상태 구조체에 들어 있다.
  (2) 모드가 안 들어갔으면 그 그림을 2 초 동안 보여주지 않고 **즉시 복귀**한다.
- `MODE_SHOW_US` 는 2000000 그대로.  §9 1 항의 "13 단계 되읽기" 는 **12 단계 되읽기**로 읽는다.

### 13-2. 새로 찾은 결함: **두 번째 진입이 스냅샷을 덮어쓴다**

`-enterLinearMode` 는 한 부팅에 두 번 이상 불릴 수 있다(클래스가 `enterCount` 로 센다).
고치기 전 코드는 매번 `osrdn_snap_take` 를 다시 했다 — 두 번째 스냅샷은 **우리가 쓴 모드**를
읽으므로, 종료 때 복귀가 콘솔 상태가 아니라 우리 모드를 카드에 되돌린다.  스냅샷이 존재하는
이유 자체가 무너진다.

- `modeSnapshot`: `snapshotValid` 면 **첫 스냅샷을 지키고**, 살아 있는 `PPLL_CNTL`·
  `VCLK_ECP_CNTL` 게이트만 다시 본다.
- `modeCheck`: 부팅상태 게이트(`CRTC_EN` 켜짐·`CRTC_EXT_DISP_EN` 꺼짐)는 **커널 콘솔이 남긴
  상태**를 뜻하므로 아직 아무것도 안 썼을 때만 적용한다.  우리 모드는 확장 디스플레이가 켜져
  있어 이 게이트를 통과할 수 없다 — 안 고쳤으면 두 번째 진입이 `why=5` 로 거절됐다.
- 증명: `simworld2b.c` 에 "두 번 진입 → 복귀" 경우를 넣었고, 보호를 끄는 변이
  (`if (mode->snapshotValid)` → `if (0)`)가 `CLOCK_CNTL_INDEX 00000309, was 00000303` 으로
  잡힌다.  재진입은 **거절이 아니라 재프로그래밍**으로 처리한다(거절하면 revert→enter 짝에서
  화면이 콘솔 타이밍에 멈춘다).

### 13-3. 중단·복구 행렬

| 어디서 | 증상 | 드라이버가 하는 일 | operator 가 하는 일 |
|---|---|---|---|
| 0 단계 게이트 거절 | 화면 = 커널 콘솔이 남긴 그대로 | 아무것도 안 쓴다, `why` 기록 | 없음.  telnet 으로 기록 수집 → `restore.sh` → 재부팅 |
| 스냅샷 거절(`why=2`) | 같음 | 안 쓴다 | 같음 |
| PLL 원자갱신 대기 한도 | 그림이 이상하거나 검은 화면 | 대기는 **끝난다**, `atomicWriteLimit/atomicReadLimit` 기록, 시퀀스는 계속 | 같음 |
| 12 단계 되읽기 불일치 | 2 초 노출 없이 콘솔 그림으로 돌아옴 | `latched=1`, **스스로 복귀** | 같음 |
| 진입은 끝났는데 화면이 검다 | 검은 화면, telnet 살아 있음 | 없음(로그·기록만) | telnet 으로 기록 수집 → `restore.sh` → 재부팅.  **패닉이 아니다** |
| 행(telnet도 죽음) | 응답 없음 | — | 전원 재시작.  비용은 루트 UFS fsck |

복귀는 **중간에 멈추지 않는다**(`revert-runs-through` 규칙).  대기 한도에 걸려도 남은 복원을
끝까지 쓴다 — 반만 복원한 카드가 콘솔을 잃는 경우다.

### 13-4. operator 고지 (이번 부팅에 실제로 보일 것)

1. 재부팅 뒤 화면에 **시험 패턴**이 약 2 초 보인다: 위에서부터 빨강·초록·파랑·회색 띠가
   왼쪽에서 오른쪽으로 밝아지고, **네 모서리에 자홍색 사각형**이 있다.  그 뒤 Workspace 가 덮는다.
2. **검은 화면은 예상된 실패 중 하나이지 패닉이 아니다.**  telnet 은 살아 있어야 한다.
3. 깨진 그림·검은 화면 어느 쪽이든 **아무것도 만지지 말고** 알려 달라 — 기록은 telnet 으로 뺀다.
4. 회수는 R2b-0 과 같다: `restore.sh` → 재부팅 → `Active Drivers` 끝이 `VGA`.
5. 재부팅은 operator 몫이다.

### 13-5. 기록 반출 예산

R2b-0 과 같은 통로를 쓴다(줄 예산 120, 상태 9 워드).  이번에 더 나가는 줄은 `osrdn_modelog.m`
한 곳에서만 나오고, 진입 1 회·복귀 1 회 기준으로

- `mode` 1 줄 + `wait` 1 줄 + `reg` 13 줄 + `pll` 5 줄 + `vga` 1 줄 = **21 줄**, 호출 2 회 = 42 줄.
- 진입·복귀 자체의 클래스 줄 2 줄을 더해 **44 줄** — 120 줄 예산 안이다.

**모드 모듈과 스냅샷 모듈은 로그를 하지 않는다**(`no-log` 규칙).  커널 VGA 콘솔이 0x3d4/0x3d5 를
쓰기 때문에, 시퀀스 안에서 로그하면 VGA 스냅샷·복원의 전제가 깨진다.  로그는 `osrdn_modelog.m`
에서 **시퀀스가 끝난 뒤** 클래스가 부른다.  기록 모듈(`osrdn_record.m`)은 R2b-0 에서 실기로
검증된 그대로 두었다 — 그 파일의 sha256 을 `sim_r2b0.py` 가 추적한다.

### 13-6. 양쪽 부팅 검사 — 어디서 도는가

0 단계의 의미 조건과 진입·복귀 전체를 **R2a·R2b-0 두 실측 부팅 상태**에서 돌린다:
`tools/r2b/sim/simworld2b.c` 의 `boots[]` 가 두 상태를 심는다(R2a `CLOCK_CNTL_INDEX 00000303`,
refdiv 6, `PPLL_DIV_3 00030047` / R2b-0 `00000103`, refdiv 12, `0003008e`).  둘 다 진입이
성립하고 복귀가 항등이어야 통과한다.

### 13-7. 역어셈블 게이트에 더한 것: **호출자 규칙**

`check_reloc_r2b0.py` 가 감사된 하드웨어 도우미 7 개(`_rdnMmioRead32`, `_rdnMmioWrite8`,
`_rdnMmioWrite32`, `_osrdn_inb/inl/outb/outl`)를 **누가 부르는지** 역어셈블로 확인한다.
목록 밖에서 부르면 거절한다(한쪽 방향만: 목록에 있는데 안 부르는 것은 실패가 아니다 —
cc 가 접을 수 있고, 불러야 할 호출이 일어나는지는 소스 규칙·시뮬레이터가 증명한다).
R2b-0 실기 reloc 으로 돌려 봤고 호출자 표가 소스 감사와 정확히 같다.  `call 0x0` 은 링커가
채울 외부 호출이며 `__text` 시작 주소와 구분되지 않으므로, 감사 대상이 주소 0 에 놓이면
**믿지 않고 거절**한다.

### 13-8. 결정 4(복귀 팔레트 클럭) — 확정

**진입 9 단계와 같은 처리**로 고정했다: 팔레트를 쓰기 전에 `VCLK_ECP_CNTL` 의 픽셀 클럭 게이트를
끄고, 쓴 뒤 **읽어 둔 값으로 되돌린다**.  진입·복귀가 같은 `modePalette` 를 쓰므로 어긋날 수 없고,
되돌리지 않는 변이는 시뮬레이터가 `VCLK_ECP_CNTL 00000043, was 000000c3` 으로 잡는다.

## 14. 개정 3 (2026-09-16) — 분주 행을 두 개에서 표 전체로

### 14-1. 왜

R2b 가 실기에서 통과한 뒤 **드라이버를 켠 채로 두기로** operator 가 결정했다(2026-09-16).
그러면 다음 부팅을 내가 보고 있지 않을 수 있다.  그때 살아 있는 구멍이 하나 있었다:

- 드라이버는 `PPLL_REF_DIV` 를 **절대 쓰지 않는다**(네 분주 슬롯이 공유한다).  그래서 부팅이 들고
  올라온 값에 맞는 되먹임 분주를 써야 하는데, 표에 행이 **6 과 12 두 개뿐**이었다.
- 실측으로 R2a 는 6, R2b-0 과 R2b 는 12 였다 — **부팅마다 다르다**.
- 표에 없는 값으로 올라오면 진입이 `MODE_WHY_REFDIV` 로 거절되는데, `displayInfo` 는 그대로
  800×600 을 알리므로 **화면이 깨진 채 Workspace 가 뜬다**.  거절이 안전한 상태가 아니다.

### 14-2. 규칙 (사람이 승인하는 것은 이 규칙과 지문이다)

오라클 `radeon_modeset.pll_table` 이 refdiv 1..1023 을 전부 돌려 다음을 **모두** 만족하는 것만 받는다:

1. `rfb_calc_dividers` 가 VCO 를 200000–400000 kHz 안에 두는 후분주를 찾을 것,
2. 되먹임 분주가 필드에 들어갈 것,
3. 실현 도트 클럭이 요청값 40000 kHz 의 **±0.5 %** 안일 것(VESA 일반 타이밍 한도).

결과: **행 168 개, refdiv 5 부터 172 까지 연속**, 지문 `0bbf9ca83b478bc7`.
경계는 규칙에서 나온다 — refdiv 4 는 오차 0.86 % 로 3 번에 걸리고, 173 은 되먹임 분주가 넘친다.
실현 VCO 는 318600–321300 kHz 로 전부 범위 안이다.

표를 168 줄 손으로 적는 것은 검토가 아니므로, 문서는 **규칙·경계·개수·지문**을 승인하고
생성기가 그 넷을 이 문서에서 찾아 대조한다.  기계가 실제로 보여준 두 행은 여전히 값 그대로
`docs/R2_FIRST_LIGHT_PLAN.md` 에 적혀 있고 그대로 대조된다(`00030047`, `0003008e`).
어느 행이 하나라도 바뀌면 지문이 바뀌고, 그러면 이 문서를 고쳐야만 생성기가 통과한다.

### 14-3. 커널 쪽 변화는 없다

`modeSnapshot` 의 선형 탐색은 그대로다 — 표만 커진다(행 168 개, 한 행 8 바이트).
`PPLL_REF_DIV` 를 쓰지 않는다는 규칙, 진입이 쓴 것은 전부 복귀가 되돌린다는 규칙,
PVG 를 안 쓴다는 규칙은 그대로다.

### 14-4. 남는 한계 (적어 둔다)

- `displayInfo` 의 `dotClockRate` 는 **39937500** 으로 고정 발행한다 — 기계가 보여준 두 refdiv(6·12)가
  실현하는 값이다.  다른 refdiv 로 부팅하면 실제 도트 클럭이 최대 0.5 % 다르다.  이 필드는 안내용이고
  스캔아웃을 정하지 않으므로 화면에는 영향이 없다.
- refdiv 가 1–4 이거나 173 이상이면 여전히 거절이고, 그때는 화면이 깨진다.  그런 부팅은 관측된 적이
  없고(실측 3 회 모두 6 또는 12), 있다면 복구는 telnet `sh /me/rdn-r2b0/restore.sh` → 재부팅이다.
